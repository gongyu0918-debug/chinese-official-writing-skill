# 办理要素

本页用于起草前和复核时抽取办理要素，不代替文种骨架、不编造缺项。要素进入正文、保持状态、省略或作为实质缺口提示，统一按 `information-selection.md` 处理。

## 通用要素

主体（发文、报告、申请或项目）、主送/受文/执行对象、办理或说明事项、政策/会议/工作依据、当前情况和问题、请求/要求/答复/协调事项、期限和进度、责任与配合单位、附件和支撑材料、数据来源及实际/测算/估算性质、反馈方式、联系人、落款和成文日期。

先按用户模板和最新版底稿识别已给要素，再按主文种确认成立条件。已给要素在正文、附件和表格中的名称、顺序、数字和状态保持一致；缺少成立条件时保留缺项或按允许模式短列，不使用泛称、占位符、当前日期或接收方反推。

## 文种重点

| 文种/材料 | 优先核对要素 | 常见缺口 |
| --- | --- | --- |
| 通知/通告 | 对象、事项、要求、时限、材料、反馈方式 | 只有“高度重视”，没有办理动作 |
| 请示 | 主体、单一请批事项、依据、必要性、方案/金额、风险、请批语 | 多事并请，结尾写成报告 |
| 报告 | 报告对象、背景、事实/进展、结果、问题、下一步 | 夹带批准请求 |
| 方案/实施/建设 | 目标、范围、任务、路径、进度、责任、保障、验收 | 只有口号，没有责任和时限 |
| 申请 | 主体、事项、依据、用途、金额/资源、使用计划、承诺 | 事项不清或无使用计划 |
| 函/复函/征求意见函 | 对方、商洽或答复事项、反馈方式、期限、联系人 | 语气命令化或没有回应来文 |
| 公告/公示 | 发布主体、事项、期限、异议渠道、联系方式、处理方式 | 缺期限、渠道或联系人 |
| 采购公告/审查 | 项目、预算/上限、内容、资格、响应期限；审查对象、依据、发现、风险、整改、结论 | 缺预算、期限、证据或条件 |
| 批复/决定/意见 | 来文依据或权限、决定/措施、范围、生效、执行要求 | 没有明确决定或责任 |
| 纪要/工作要点/总结 | 会议和议题、议定事项、责任期限；阶段目标、任务、节点、已完成工作、问题和下一步 | 写成新闻或宣传稿 |
| 调研/可研/审查 | 对象、方法/数据、发现、问题原因、比较、成本、风险、建议/结论 | 结论没有依据或条件 |

技术、算力、采购和 Word 的专门字段不在本页展开。命中明确场景后，转读对应主文种页或条件附加页；本页只确认这些字段是否已经出现、是否保持来源和状态，不把场景规则带入普通稿件。

## 缺项和停止

- 不编造真实单位、金额、政策、日期、电话、邮箱、文号、签发人、印章和责任安排。
- 默认不外搜补缺项；用户明确搜索或任务含时效事实时才读外部研究页，冲突和无法核验保持待核状态。
- 正文不得残留 `〔签发日期〕`、`〔会议时间〕`、`〔待补充〕`、`[具体项目名称]`、`XXXX万元`、`YYYY年MM月DD日` 等未完成占位，除非用户明确要求模板稿。
- 当前日期只可用于用户允许的草稿落款，不替代会议、维护、实施期限、政策依据或业务日期；正式签发日期、文号、印章和签发人不得编造。
- 缺项影响文种成立时标为实质缺口；请示、报告、上报申请缺主送、发文/申请单位或日期时不编造“上级单位”“申请单位”等泛称。

要素核对完成后停止本页，回到主文种叶成稿或复核。
