# 文种功能反查

本页只做未覆盖文种的最小功能核对。已有专页的任务先读专页，不把本页和专页整套叠加。

## 通用核对

- 文种名称与正文功能一致，标题、附件和正文关系清楚。
- 行文关系与语气一致：上行重请批或汇报，下行重办理要求，平行文保持商洽，公开文本交代公开对象和期限。
- 主体、对象、事项、依据、时间、责任、反馈和落款等已给要素保持原样；缺项按 `information-selection.md` 处理。
- 事实、分析、建议、待核和已决定状态分开；建议不写成决定，预测不写成成效。

## 法定文种最小功能

| 文种 | 只核对这些核心功能 |
| --- | --- |
| 决定 | 权限、决定事项、范围、生效和执行要求 |
| 决议 | 会议主体、审议事项、通过结果和执行要求 |
| 命令（令） | 发布主体权限和法定使用场景 |
| 公报 | 公开主体、重要决定或统计信息的权威发布 |
| 公告 | 面向较广公众的事项、范围和办理信息 |
| 通告 | 一定范围内应知或应遵事项、期限和责任提醒 |
| 通报 | 已发生事实、评价、问题或经验、后续要求 |
| 报告 | 汇报、反映或答复，不夹带请批事项 |
| 请示 | 一文一事、依据、必要性、明确请批事项 |
| 批复 | 对来文作出同意、调整或不同意的明确答复 |
| 议案 | 法定提请主体、审议事项、依据和拟议内容 |

## 事务材料最小功能

- 说明：解释情况、原因、过程或当前状态，不自动变成请示或宣传稿。
- 申请：写申请主体、用途、金额或资源需求，结尾服从模板和审批对象。
- 公示：写事项、期限、监督或异议渠道和联系人。
- 方案：写目标、任务、路径、进度、保障和验收；完整骨架转方案专页。
- 讲话稿、致辞、述职：服从场合、身份、听众和职责视角；完整写作转讲话专页。
