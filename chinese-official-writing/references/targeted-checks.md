# 指定材料与局部修改核对

以下工具按需使用，读取 UTF-8 的 TXT/MD，结果留在内部核对，不写入正文。输入路径用带引号的绝对路径，脚本按已读 SKILL.md 所在目录定位。

## 关键原文定位

多份材料含补充、更正，或需逐项核对金额、期限、名称、状态时，可用 `scripts/material_diff.py` 定位明确选中的原文片段：

```text
python "<Skill目录>/scripts/material_diff.py" --source "<有效材料绝对路径>" --draft "<稿件绝对路径>" --literal "预算38万元" --literal "建议分期实施"
```

先确定本轮有效依据，勿将旧稿或模型补写内容混入有效材料。所选片段保留主体、单位或状态词，避免孤立数字和过短词。工具列出双方全文中所有精确匹配的位置和上下文，不自动抽取事实，不判定遗漏、冲突或事实正确。未出现可能是改写、计算、格式变化或合理删减；出现也须核对所指主体、否定和引用关系。未选内容仍由 Agent 复核。退出码0仅表示定位完成，2表示输入或读取失败。

## 精确替换核对

仅当用户明确要求指定文字替换、其余逐字保留时，使用 `scripts/edit_scope.py`；一般润色、自由改写、仅给替换片段和 Word 排版不适用。按以下顺序执行：

1. 定目标：按用户指定的角色、段落和完整上下文确定改哪一处；`old` 在原稿出现多次时，先核对所指是哪一处，再在该项加 `start`（修改前原稿中的零基 Python 字符偏移）。
2. 存原稿：原稿在聊天中给出时，按用户文字逐字存为 UTF-8 TXT/MD，末尾不补换行，不增删空行，不转换换行形式。
3. 写计划：依原稿和用户要求先写替换计划，保存为 UTF-8 JSON；不按已写好的改稿倒推计划。

```json
{"edits": [{"old": "预算38万元", "new": "预算36万元"}]}
```

4. 直接生成：用 `--output` 生成改后全文，排他创建新文件，原稿不变；歧义定位、重叠或原稿哈希不符时不生成。

```text
python "<Skill目录>/scripts/edit_scope.py" --original "<原稿绝对路径>" --output "<新稿绝对路径>" --plan "<计划绝对路径>"
```

5. 核对交付：读取新稿，核对每处替换符合用户要求、范围外逐字保留，再按本轮要求的形态交付。退出码0表示生成成功，不代表语义审查通过。

改后稿已作为文件存在、只需核对其是否等于计划时用 `--candidate "<改后稿绝对路径>"` 代替 `--output`：退出码0为完全一致，1为不一致（列出第一处差异及上下文），2为原稿绑定、定位、计划或读取有误。

`old` 必须非空。删除用空字符串 `new`，插入用相邻原文作 `old` 锚点；空 `edits` 表示逐字保留。所有替换同时基于原稿，范围不得重叠。可在顶层增加 `source_sha256`，绑定原稿文本按 UTF-8 编码后的 SHA-256。工具严格保留空格、换行形式、段尾及末尾换行，读取时仅去掉文件开头的 UTF-8 BOM；输出为 UTF-8 无 BOM。结果只说明改后稿是否等于计划指定的预期全文，不判断修改内容是否妥当。偏移不等于字节位置；变长替换后的差异偏移相对于预期全文和改后稿，不是原稿偏移。

定位或范围核对后，继续完成当前任务的材料语义、语言与交付检查；只审核就给意见，审后改稿就给改后稿，局部修改保留范围外原文。只给位置、问题、建议时，从第一处具体位置写起，最后一条建议后结束；工具结果、完成说明及“结果留在内部”等操作旁白不交付。
