# 文稿扫描

文字稿同时需要篇幅实测时，在现有计数命令加 `--scan`，同一次读取完成计数及语言、结构、格式扫描，返回 JSON：

```text
python "<Skill目录>/scripts/draft_length.py" --scan --min-chars 80 "<草稿绝对路径>"
```

上下限按实际要求传入。合并命令默认按仅正文扫描；输入文件已含允许的文后提示时，加 `--delivery-mode gap-note-allowed`，字数仍只计提示前的稿件。`review_candidates` 是待核对线索，不能直接当作错误或抄入文后提示，退出码0也不证明事实正确。已合并检查且未改动的同一稿件不再单独计数、扫描；只需扫描或处理 DOCX 时使用下面的原有接口。

入口明确判为试写时，临时文件包含正文和固定文后标识，同一命令加 `--trial`。该选项按含提示的成稿模式扫描，并要求末尾空一行后独立写“文后提示：本稿为拟生成稿件。”；缺失或格式不符返回1。它只核对标识，不能判断是否应当试写，也不代表事实通过；真实稿不要加此选项。缺失提示先核对模式：真实稿移除误传的 `--trial`，确属试写才补齐标识，不能因脚本要求而改变真实稿属性。

扫描被审原稿或拟交付稿件，支持 `.txt`、`.md`、`.docx`。以已读 SKILL.md 所在目录定位脚本，草稿使用带引号的绝对路径：

```text
python "<Skill目录>/scripts/prose_lint.py" --delivery-mode draft-body --structure --format "<草稿绝对路径>"
```

按扫描对象选择模式：稿件正文用 `draft-body`，正文连同独立文后提示用 `gap-note-allowed`，审稿意见本身用 `review-only`。审核收到的原稿仍用 `draft-body`，原文件保留，修改另存新稿。

需要标准输入时用 `-` 代替路径，并将实际文本通过管道传入。用户明确要求 Markdown 时加 `--allow-markdown`，保留相应格式，继续检查旁白、占位及其他风险。

逐项核对命中位置及上下文，由 Agent 按材料、常识和本轮修改范围判断。保留成立的归因、原因推断、影响分析和后续结论；确认的问题修正，真实对比、步骤、测算、术语和引用保留，同义问题合并处理。扫描未命中时仍完成抗 AI 页的句群检查。正文实质修改后复扫，最终采用最后一次扫描的文本。

读取或运行失败时核对路径与格式；仍无法执行时如实记录未完成的检查。
