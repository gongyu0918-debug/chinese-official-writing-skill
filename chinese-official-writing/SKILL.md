# 中文公文写作

处理中文公文、事务性材料、工作材料和新闻稿件的起草、修改、审核及Word整理。寒暄、概念问答及其他文本按所问处理；能力查询读 `README.md`。

## 先按任务分流

- **指定替换，其余逐字保留**：按 `references/targeted-checks.md` 定位、替换并核对全文，其余逐字保留。目标有歧义才澄清，用户不要工具时人工核对。用户要求不落盘或写入受限时，不创建任何文件，改用内存内或人工替换；材料含个人敏感信息或密级标识时，不创建原稿、计划、临时新稿等中间文件，用户明确要求最终文件时仅通过获准的宿主文档工具生成指定交付件。同轮另要审核时，按用户限定范围独立审核改后稿。
- **仅排版或整理空白模板**：保留业务文字，按用户要求处理版式或模板字段；字段整理读 `references/field-editing.md`。另有改写或审核要求时分别处理。
- **仅审核**：按 `references/review-checklist.md` 核对本轮材料、最新版原稿和用户限定范围；该页确定补读及交付。审后改稿先确认有据问题，再按下面的写稿路径在授权范围内修改。

起草所需的关键事实互相冲突时，先确认应采用的信息；用户要先交草稿时，已确定内容先成稿，冲突项按共性页在稿外提示。

### 快速写稿

仅写一份短通知或报送提醒，真实材料充分，文种、行文关系和办理要求明确，且无字数下限、复杂篇幅分配、正式版式或来源核查要求时，仅用已加载的本段和“正文形态”成稿并对照材料核对，规则读取至此。用户明确限定全文字数上限时，用 `python -B -X utf8 "<Skill目录>/scripts/draft_length.py" --delivery-mode review-only -` 一次计算全文非空白字符数，脚本按已读 SKILL.md 所在目录定位，解释器按宿主可用的 Python 3 选择。定稿经宿主标准输入接口按字面传入；POSIX shell 可用带引号的 heredoc，并选定稿中不存在的独立行作分隔符。核对篇幅后，最终回复即为定稿全文；超限先压缩背景与重复，必保内容与上限冲突时走完整路径。

围绕本次事项，按本轮材料写清对象、办理动作、条件、时间、地点、渠道和期限，保留数字、事实状态及用户点名内容；压缩背景与重复，结尾承接已有办理要求。定稿对照材料核全要求与安排。

需推导或设计职责程序、作评定结论，或涉及试写、用途冲突、多稿、制作附件时走完整路径；材料明确的多接收方、备选渠道和分步要求可按快速条件直接转述。

## 完整写稿路径

结合本轮请求确定交付件、用途、接收对象、最新版底稿、修改范围、必保内容和篇幅格式；有用户模板时优先。信息足以判断就继续，用途不明才集中询问影响选路的信息。独立稿件和有独立用途的附件分别选路，背景和引用沿主文本。

按顺序确定材料边界，命中即停：明确模拟、虚构或生成测试时按试写，读 `references/trial-draft-routing.md`；否则，有旧稿、现实材料、具体事项或状态，或要求实际使用、据实、只用已给内容时按真实稿；其余仅给文种或宽泛主题的成稿请求按试写。样稿、学习写法不覆盖现实材料；明确模拟仍保留用户点名内容和限制。模式确定后不重选。

按用途从 `references/reference-index.md` 选一个主叶；标题、模板、正文用途或行文关系冲突时读 `references/genre-routing.md`。真实稿的主送、落款以材料或模板明确的收文、发文身份为据；回执接收方、联系人和承办部门按各自职责入稿，其他未给字段按共性页处理。

按任务加读：

- 结构增删、重排读 `references/structure-editing.md`；字段处理读 `references/field-editing.md`，沿最新版底稿和指定范围修改。
- 压缩或限字按文种保留必要内容，复杂分配读 `references/compression-details.md`。
- Word、docx、红头或正式国标版式读 `references/format-gbt9704.md`，仅排版时保留业务文字。
- AI算力、模型推理或训练、智算中心和模型服务资源，在主叶上加 `references/ai-compute-docs.md`；普通服务器、接口、安全、SLA或验收不单凭术语加读。

不熟悉文种、事务写法、必备要素或格式，明确要求搜索，或涉及需更新核验的事实时，读 `references/external-research.md` 定向核查。网络材料补充通用写法和来源背景，用户事实仍以本轮材料为准；常规已知文种沿现有规则成稿。

完整起草、改写和审后改稿按 `references/writing-rules.md` 核对材料、成稿和交付。先写清读者本次要知道、同意或办理的核心事项，再安排必要支撑；不平均铺陈背景。涉及语言时读 `references/anti-ai-patterns.md`；工具按共性页的适用条件检查，接口见 `references/prose-lint-usage.md`，同稿合并检查不重复运行。其他专用路径按各自要求完成。

## 正文形态

整条回复按原始请求交付完整稿件、具体意见或文件链接；“只给”“仅”等限定贯穿整条回复。正文直接从标题或正文起笔，实质缺项按交付规则处理，制作记录留作内部过程。

普通文字稿按纯文本呈现标题和段落；明确要求Markdown、代码或固定模板时按要求处理。

纯文本主标题独立成行、末尾无句号，后空一行；层级标题与其统领正文分段，末尾无句号。编号内容为完整句时保留正常句末标点。模板优先，Word小标题按实际统领关系处理。

网页复制稿剥离栏目路径、责任编辑、字号和打印等元信息；“关于印发”的通知壳、被印发正文和附件关系分开处理。

列正文附件说明时，将来源文件名转为题名，如 `复核结果表.xlsx` 写为 `附件：复核结果表`，原名中的年份、版次照留。保存、下载链接及办理要求中的文件名用完整名称；逐字保留任务沿原文。
