# 中文公文写作

用于中文公文、事务性材料、正式工作材料、新闻消息和新闻评论的起草、改写、压缩、润色、审核及 Word 正文整理。

随着模型能力增强，原 Skill 多轮迭代形成的规则重复、职责混杂和路由负担需要重新梳理，Hook 的执行表现也受到宿主支持和稳定性的影响。2.0 对照原有功能重构入口、references 和普通脚本，使静态规则更加完善、精炼简洁，更适应新模型按需选读和调用工具的方式。

## 怎么实现

```mermaid
flowchart LR
    A[理解需求与材料] --> B[选择文种或事务页]
    B --> C[起草或落实修改]
    B --> S[按需补充场景参考]
    S --> C
    C --> D[篇幅、文种与抗 AI 味复核<br/>脚本扫描与修正]
    D --> E[交付稿件<br/>文后提示单独呈现]
```

文种页负责自身的要素、结构和行文习惯；共性规则处理材料分析、成稿、复核和交付；算力、领导讲话等附加参考按场景读取。审核给出位置、问题和建议，需要改后稿时落实修改。

## 主要能力

- 公文：申请、请示、报告、通知、函、批复、意见、决定、公告、通告、纪要等。
- 事务与工作材料：采购、整改、反馈、说明、公示、方案、制度、总结、调研、讲话和述职等。
- 新闻与技术材料：新闻消息、编者按、新闻评论、可研、审查、技术需求及算力专项材料。
- 修改与复核：压缩、扩写、润色、去口语化、降 AI 味、文种与格式检查、审核后改稿。
- Word 整理：配合宿主文档工具处理正文与版式。

## 使用方式

直接提供现有材料、稿件用途和写作要求。已有旧稿时，以最新版底稿及本轮修改范围为准。材料与常识支持的原因、目的、影响和下一步可以合理展开；具体数字、日期、主体及明确未决状态保持原意。

`scripts/draft_length.py` 在成稿阶段核对正文篇幅；`scripts/prose_lint.py` 在复核阶段提供格式、重复、占位和旁白等风险位置。运行需要 Python 3。Agent 对照材料处理结果，再交付完整稿件或审稿意见。

缺项、修改建议和仍未解决的问题统一放在正文之后的“文后提示”，与稿件分开；用户明确只要稿件时按其偏好交付。
