- 420字以内通知：候选胜，任务约束承载更完整。
- 800—900字报告：基线胜，候选增加未给流程和后续安排。

人工复核同时发现：第二篇在不同章节重复出现“应继续保持”“不改变后续安排”“结果以……为依据”等同机制收束，单稿达到三处以上。它说明保护性解释仍有残留，也说明当前结构检测的窄域规则没有覆盖更广的语义变体。该现象先登记为待做同模型 No-Skill 对照的共性机制线索；在缺少对照前，不把它直接归因于 Skill，也不通过扩充“尚未、不能、仍需”等词表处理。

## True No-Skill 状态

真正 No-Skill 计划采用项目外临时工作目录、仅含本地认证文件的临时 `CODEX_HOME`、`--ignore-user-config`、`--ignore-rules` 和逐字原始输入。子任务和主线程的两次启动均在向外部模型发送任务前被安全审批拒绝；两题均未启动、未重跑、未产生 No-Skill 成稿，临时认证文件无遗留。

因此，本轮能够判断1.5.33两篇长文的事实与后半篇稳定性，不能计算相对 true No-Skill 的胜负或领先率。继续该项需要用户明确授权把上述两个已哈希的具体任务发送给 OpenAI Codex `gpt-5.6-terra`，临时 `auth.json` 仍只用于本地认证。

## 剩余风险

1. 当前 lint 对明确模式的精度较高，但不能替代语义复核；保护性解释的多样化句尾仍可能零命中。
2. “只输出正文”压缩只覆盖两种明确输出范围，尚未覆盖所有复合交付组合。
3. 本轮没有新的 true No-Skill 稿，整体写作领先率仍为 unavailable。
4. Promptfoo 本机版本0.121.11低于提示的0.121.20，本轮20/20结果未受影响；未在本轮升级依赖。
