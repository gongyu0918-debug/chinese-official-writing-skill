# Hook 篇幅不恶化原子预注册（v1.6.2 候选）

## 固定边界

- 固定集成基线：`6a3745421b77c651a1d0a9ffc51654beec7bd368`。
- 唯一产品改动：收窄 `review_gate.py` 对已低于用户最小篇幅的 D1 缩短放行。
- 保持不变：字数识别、容差、扩写上限、正文保留比例、事实门禁、状态机、Hook 适配器、Skill、references、`prose_lint.py` 和发布配置。
- 本原子只防止 D1 明显扩大相对篇幅偏差；不新增补字、自动扩写或独立篇幅兜底。

## 基线复现

请求为“请写一份至少100字的情况说明。”；D0 与 D1 标题相同，按非空白字符计数：

| 场景 | D0 | D1 | 基线结果 |
| --- | ---: | ---: | --- |
| 明显继续缩短 | 90 | 65 | 放行（`None`） |
| 轻微删改 | 90 | 80 | 放行（`None`） |

90→65 的正文保留比例约为 70.9%，刚好越过现有 70% 正文坍塌门槛；`decisions` 模式的 `bounded_p0_shortening` 随后跳过篇幅偏差检查，因此 D1 被放行。

## 预期与停止条件

1. 90→65 必须返回 `prompt_length_compliance_worsened`。
2. 90→80 仍应放行，证明既有 20 字最小容差继续有效。
3. 只删除或收窄上述特例，不新增门禁类别、阈值或 reference 文字。
4. canonical 与合法全功能镜像的 `review_gate.py` 字节一致；排除该脚本的纯 Skill 镜像继续排除。
5. 定向测试、Hook 测试、全量单测、stub smoke、固定基线确定性消融、quick validate、同步幂等和 `git diff --check` 均通过后才可交付。
