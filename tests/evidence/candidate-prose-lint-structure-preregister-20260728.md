# prose_lint 结构重构预注册（2026-07-28）

## 固定基线

- 产品基线：`v1.5.27^{}` / `cfd7bd039e5655ba3e9fe7680206b520d7582072`
- 隔离分支：`codex/1.5.28-candidate-prose-lint-structure-v1527`
- 本候选只改善脚本可维护性，不改变 Skill 写作 Prompt、reference 路由或发布版本。

## 已复现问题

1. `duplicate_findings()` 内直接使用 `60` 作为最短重复段落阈值，名称和用途不可见，属于行为阈值魔法数字。
2. `scan()` 同时承担扫描配置准备、正文/文后区分、逐行匹配、交付模式专项检查、全文聚合检查和结果去重，函数约 194 行，职责过多。
3. 少量维护注释仍为英文；若不了解历史背景，较难判断默认扫描与交付模式扫描的边界。
4. 脚本中还有若干参与程序控制的裸阈值，需要区分为“应命名的程序阈值”和“正则表达式局部长度上限”。本轮只命名前者，不机械拆散正则。

## 单变量修改边界

本轮保持检测行为完全等价，只做以下结构调整：

1. 为重复段落最短长度、共享 token 数、相似度、上下文截取宽度、跨行引号查找范围、编号回看范围、标题长度和西式列表数量等程序阈值建立按用途分组的命名常量。
2. 将 `scan()` 按真实职责拆分为：
   - 扫描配置准备；
   - 逐行通用扫描；
   - 交付模式专项扫描；
   - 全文聚合检查；
   - finding 稳定去重。
3. 各辅助函数只接收本职责所需数据；不建立跨阶段的万能配置字典，不隐藏可变状态，不改变原有执行顺序。
4. 难以从代码本身看懂的分支补自然中文注释；现有英文内部注释改为中文。

本轮不修改：

- 任何正则文本、finding 的 `severity`、`label`、`advice`、行号、顺序或去重键；
- `60` 的取值以及其他阈值的取值；
- CLI 参数、退出码、JSON 字段、标准输出格式；
- canonical 以外镜像的独立语义；完成后仍由同步工具生成镜像；
- Skill 写作、复核、路由、Hook、FSM 或发布链。

## 验证计划

1. 修改前生成行为基准：对 `tests/test_review_regressions.py` 已覆盖的主要模式及 clean corpus 运行 `scan()`，保存 finding 的完整序列。
2. 修改后使用相同输入重放，逐项比较 `severity`、`label`、`path`、`line`、`match`、`excerpt`、`advice`；必须字节级等价。
3. 运行：
   - `python -m unittest tests.test_review_regressions`
   - `python -m unittest discover -s tests`
   - `python -m py_compile chinese-official-writing/scripts/prose_lint.py`
   - `python tools/sync_adapters.py`
   - `git diff --check`
4. 增加结构回归：确认程序阈值没有重新以内联裸数字出现，`scan()` 只负责编排，核心辅助函数职责和参数边界清楚。

## 验收

- 所有既有测试通过；
- 修改前后行为基准完全一致；
- `scan()` 不再承载逐行匹配和全文聚合实现；
- 没有新增万能字典、隐式全局状态或兼容性变化。

任一 finding 发生变化即停止，不以重构名义接受行为漂移。`60→40` 等召回率实验必须另建候选，补误报与召回校准，不与本候选混合。
