# 终稿 lint 指针纯前移预登记（2026-08-09）

## 唯一变量

只把以下现有原句从 `SKILL.md` 末尾“脚本”段移动到核心流程第 6 步末尾，逐字不改：

`检查终稿正文时按 references/final-review-layers.md 使用 draft-body 模式。`

实现时保留原有反引号。除位置外不改变字符、语气和加载条件；不增加“运行一次”“必须”、命令示例、检测词、正则、Hook、FSM、复核轮次或自动改稿。

## 假设

核心流程中的终稿使用时点更靠近实际成稿动作，可能提高 `final-review-layers.md` 与 `draft-body` 语义复核的自然执行率，并减少保护性外扩或正文外审稿说明。纯位置变化也可能没有可见效果；无差异记 `NO EVIDENCE`，不包装成收益。

## 真实题

1. 局部改稿：给定含真实事实与无材料锚定的“这不代表问题彻底解决，也不意味着业务完全恢复”尾句，要求改成可直接使用的情况说明正文。必要的“异常原因正在核查”必须保留。
2. 自然起草：给定接口恢复、抽查成功和原因核查中的单一材料，观察是否自行追加“尚不能、不能据此、不代表、不意味着”等外围保护尾句。
3. 反向控制：材料明确要求保留样本不得外推至全体的办理边界，不得因终稿复核将其删除或弱化。

写手至少覆盖 Alibaba DeepSeek V4 Flash 0731 与 Luna；同一题两臂使用相同模型和思考档位，首个最终正文冻结。后续只询问实际读取文件、脚本执行与语义处理，不允许补写正文。

## 判据

- 事实、数字、日期、对象、状态、文种和“只输出正文”为先决硬边界。
- Candidate 独有硬回退且能由位置变化或实际读取轨迹关联时，立即 `NO MERGE`。
- 只有 Candidate 可归因地删除或避免无锚保护尾句，且另一题和反向控制不负，才记改善；脚本读取或运行次数增加本身不算质量收益。
- 两臂共同错误或同提示下的孤立波动只记噪声；无法建立因果时扩大同题复放，不强行裁决。
- 工程验证与真实写稿分开：focused/full unittest、smoke、固定 main 消融、quick validate、镜像同步和 diff check 通过，不等于真实质量通过。
