# 1.5.39 Word 正文对齐方式最小修复预注册（2026-08-08）

## 复现与归因

- 固定 1.5.38 同题首稿明确给出正文“两端对齐”。
- 1.5.39 Candidate 同一自然 Word 任务连续三名独立 writer 均读取 `format-gbt9704.md`，均正确给出标题、字号、页边距、版心、行距、页码和成文日期处理，但 3/3 未写正文“两端对齐”。
- 匿名 verifier 将 Candidate 首稿判为 WARN、固定基线判为 PASS。
- 当前 `format-gbt9704.md` 的正文段落规则只写“首行缩进 2 个汉字，行距、段前段后以模板为准”，没有承载正文对齐方式。入口下沉后，格式 reference 成为该细节的单一来源，因此该缺项与本轮 Word 指针原子存在直接机制关联。

## 单变量修复

仅在 `references/format-gbt9704.md` 的“正文段落”条目补入“一般两端对齐”。保留现有首行缩进、模板优先和行距规则，不增加字体、页码、版头、版记或事实规则，不修改入口、路由、输出模式、复核顺序、脚本、Hook 和发布链。

canonical 修改后只通过 `tools/sync_adapters.py` 同步现有镜像；增加一条确定性断言，确保格式 reference 继续承载“两端对齐”且入口不重新展开字体字号细则。

## 验证

1. 定向边界测试、全量 unittest、Promptfoo stub smoke、固定 1.5.38 消融、quick validate、脚本编译、镜像幂等和 `git diff --check`。
2. 两名新的独立 writer 逐字复放原 Word 任务，各取首个完整技术有效输出，不二次修改。
3. 通过要求：两稿均读取 `format-gbt9704.md`，明确正文“两端对齐”，保留全部事实和合法否定句，不补年份或成文日期；版心、页边距、标题、正文、行距和页码要素无回退。
4. 任一复放仍漏“两端对齐”则本修复不进入发布，回到 1.5.38 格式入口或另立候选；不得补抽续命。
