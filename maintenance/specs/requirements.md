# 产品需求

## 写作核心

### WR-001 事实与状态边界

正文必须保留材料给出的主体、对象、数字、日期、范围、状态和结论强度。常识与合理推断可以帮助成文，但不得新增具体人、单位全称、程序、责任、期限、决定、结果或完成状态。

验收场景：

- “下一年度拟完善、拟优化”可写成“将在下一年度改进”，不得写成已经完成或已经确定具体方案。
- 核查范围内“未发现”是有功能的事实，不因含否定词删除。
- 新闻中的嫌疑人尚未抓获、故障尚未修复、恢复时间尚未确定可以保留；避免连续否定，并在材料和职责支持时由警方、电力部门、有关部门等主体承载进行态。

### WR-002 删除保护性外扩

删除不承担文种功能的免责、自证、外围未来治理和连续否定尾句。不得以单个“不、未、尚未、不能、不得”为删除条件；正式禁令、法律审计结论、必要未决状态和用户引语必须保留。

保护性外扩能力只删除冻结 span，不补进行态、不扩写、不承担通用事实审查。删除后确需补充，由普通写作或其他独立能力处理。

### WR-003 责任承载与合理推断

新增进展、承诺、后续动作或预期必须有材料明示、写作主体承担或语篇可继承的责任主体。主体可以省略，但语义上不能成为无头结论或无头承诺。

责任主体可以由近邻句、标题、发文身份或文种角色自然继承，不要求每句机械重复主语。新闻、会议、请示、申请、总结和汇报分别按实际主体与行文关系表达，不得凭常识补具体单位全称、职责分工或行动结果。

### WR-004 文种功能与常用语

开端、承启、综合和结尾语按文种及行文关系使用，不机械套用。请示、报告、通知、函、批复、纪要、新闻消息、新闻评论和事务文书不得互换功能。`综上所述` 在有真实归纳作用时可以使用。

常用语只提供文种功能和按需表达选择，不得让不同任务共享同一套开头、分层、总结和尾句。用户给定结构、材料自身逻辑和自然开合优先；不得以另一组固定的“反套话”表述替换原有套话。

计划、汇报、调查报告、讲话稿、演讲词、答复、责任书、公开信、倡议书、建议信、新闻发布稿、总结、情况反映、情况综合、编者按、新闻、短评、讲解稿、宣传手册和宣传材料，应路由到现有文种叶或确有必要的新叶。不得把申论答题框架直接当成机关实务模板；先核受众、行文目的、法定文种和材料边界。

### WR-005 短稿自然度

短稿及用户给定较短范围内避免同义复述、连续自证、过程旁白和 Markdown 包装。只输出正文时不得出现“已按 Skill 核验”“正文如下”等交付过程。

该要求在普通 Skill 和关闭 Hook 时也必须成立。可选的交付洁净度、重复清理 Hook 只提供写稿后的兜底，不替代普通语义层；优先用真实短稿验证，再决定是否增加路由、lint 或工程胶水。

### WR-006 审稿模式

“只读审核、帮我审核、审稿模式、审一下稿、看看哪里有问题、只审不改”等自然表达进入审稿模式；“先审后改、审核并优化、审完改写、不是只审不改”等仍需成稿。材料中的引语不得被误判为用户当前模式。

### WR-007 语义减载与自然表达

在不削弱事实、状态、权限、文种和交付边界的前提下，减少重复禁令、长串反控和同义保护说明。优先使用简洁、正向、按功能组织的写作提示，替换会把模型注意力拉向免责声明、自证、连续否定和句尾声明的高密度负向指令。

减载不以字数减少为成功标准。必须先用真实稿件确认：过度保护、过度声明、句尾免责和同义自证下降，正常未决状态、制度禁令、法律审计结论、用户引语和必要风险说明仍保留，且没有新增事实、篇幅、文种或自然度回退。通过真实写稿后才整理路由、reference 和必要反控。

### WR-008 标题与正文边界

纯文本正式稿的主标题单独成行，标题末尾不加句号，标题与主送机关或正文之间保留清晰段落边界；普通纯文本交付默认用一个空行表示该边界。Word 或正式排版交付使用段前段后等版式控制，不机械插入空白段落。

“一、申请事项”“二、有关情况”等确为层级标题时，标题行末不留句号，正文另起一行；编号内容本身是完整句子而非标题时仍按正文标点处理。用户固定模板、逐字标题或特殊版式优先，不以脚本无条件改写。

### WR-009 文后提示与正文分区

只有输出模式允许时才在正文后短列实质缺口。先完整结束正文、结尾语、落款和成文日期，再空一行另起无正文层级序号的 `待确认事项（正文外）：`；提示不得成为正文最后一段或连续章节，不使用 Markdown 横线包装。lint 只校验分区、标题和包装边界，不替模型决定缺什么或生成缺项清单。

### WR-010 会议结论与承诺证据

根据口语记录整理会议纪要时，保留已决定、暂定、提议、表达意向、会议交办和明确承接之间的强度，不把沉默当作接受，不把“看看、研究、尽量”等写成明确承诺。正式正文以可直接使用为先，不强制写入“未确认承接”等内部审计措辞。

若后续增加内部 claim—evidence sidecar，每条结论、责任和期限必须绑定语义相关的原话或记录位置，主体、动作、条件、状态和期限不得跨句拼接；精确 span 或 hash 只证明来源完整，不能单独证明来源蕴含。sidecar 不污染正文，证据相关性不能确认时沿用正文 D0。

`WR-010-M2` 只研究正文外的规则状态：区分已经正式形成并适用于后续事项的规则、仍在讨论或待批准的候选规则，以及仅对本次事项成立的一次性安排。候选规则不得写成正式标准，一次性安排不得推广为长期制度；若做 sidecar，状态、原话和记录位置必须绑定，正文仍按用户要求直接交付。先用会议纪要真实写稿确认这一分类确有增益，不先复制竞品表格、自动补负责人/期限或建设多格式渲染工程。

### WR-011 新闻声明级核验

同一新闻主张出现多来源冲突时，先按“主张—来源—来源身份与层级—冲突—结论状态”逐条核验，再形成安全正文。来源身份、数据原始出处和数据可信状态分别记录；不得把已知媒体或机构误写成身份待核，也不得凭名称推断机构性质。

不同截止日、统计范围、接入/覆盖口径不能直接相加、相减或折算；“超过”“至少”等开放数量不得写成确定差额。来源冲突时不按数量投票，不擅自选边；正文只归属陈述可确认内容，并把未核实或冲突主张保持为待核状态。核验矩阵属于内部工作区，用户只要正文时不得输出旁白、Markdown 包装或矩阵残片。

### WR-012 正式发文意图路由

先判断用户是否要求形成具有明确行文关系的正式发文，再判断“报告”“函”等名称。内部情况说明、工作材料或口头所称“报告”不因名称自动增加主送机关、正式结尾、文号、签发人、落款等发文外壳；普通业务联系函也不自动升级为正式公函。

用户明确要求正式上行报告、正式函件或给出相应行文关系时，保留必要文种结构，但不编造字段，也不在正文后追加“请自行补充”等保护性说明。路由候选必须分别通过内部材料、明确正式发文和相邻普通业务文书，不得用单题改善覆盖其他题的事实或直接可用性回退。

### WR-013 事实支撑的一般原因与即时作用

材料已经给出主体、事项和直接关系时，允许写入不改变事实状态的一般目的、原因、即时作用和低强度预期。事务性申请可把材料与常识直接支持的原因前置为“为……，拟申请/拟采购……”；活动新闻可概括由已给活动环节直接产生的一层即时作用，但不得把个别参与者原话、部分人员完成情况或一次活动扩大为全体成效、长期影响或既成推广结果。

发布单位、主办单位、举办地点和参与者范围分别保持；发布者身份不能反推举办地或参与者属地。合理推断必须有已给事实和可继承主体承载，不新增数字、对象、责任、程序、期限、决定或已取得成效。过严判定不得把上述允许关系重新挡回只列事实的过短稿。

### WR-014 证据可见性与事项进度

“未提供、未附、尚无材料”只表示当前证据不可见，不能自动改写为事项“未开展、未完成、不具备”或否定其真实性；材料明确“已完成但未附”和“明确未开展”时，应分别保持。“可安排、可开展、具备安排条件”是能力或选项，“拟安排、计划开展”是计划意向，两者分别保持原强度，均不得升级为“已安排、已落实”。复核或改稿时，现稿把“本次材料未提供某项数值”写成计划或草案未提出、未设置、尚未确定、待明确或待会议决定的，只删除这一材料外状态；缺失值不影响文种功能时保留已明确动作，不把材料视角换一种说法留在正文。

候选先用同一审查稿内的三态对抗题验证，只修正证据可见性与事项进度的关系，不同时增加审批字段、审查模板或宽泛保护性声明。

### WR-018 丰富材料下的事务稿密度

材料已经给出原因、过程、数量、影响、状态和办理关系，且用户没有要求简短或限定上限时，正文应按文种功能使用这些关系，不把完整材料压成只列结论的摘要。一般原因、即时作用和低强度预期继续按 WR-013 边界接受；篇幅本身不设统一门，只有遗漏必要关系、请批/报告/新闻功能或事项落点时才判“过薄”。

先以采购申请、异常处置报告和活动新闻三题诊断当前产品；没有跨模型共同缺口前，不新增固定段数、小标题、字数下限或统一扩写流程。

### WR-019 术语、行业表达与翻译腔

本项只做语义软审，不建立禁词表，不因裸词次数或单个句式判失败。候选分成四个可独立归因的原子，逐项完成真实写稿 A/B 后才决定是否进入产品：

- `WR-019a` “口径”只在指向统计、核算、测算、验收、审计等具体对象及其范围、时间、单位、分母、方法、纳入/排除项或依据时保留；不同对象的必要使用不按词频合并。只有空泛的“统一口径”缺少对象和边界时，才按材料改成具体规则或动作，材料没有时不补造。
- `WR-019b` `赋能、生态、底座、场景、抓手、矩阵、闭环、体系化` 等行业词只有脱离主体、对象、动作、机制、节点、产物或指标并成簇堆叠时才提示压实。官方文稿中有明确机制的真实使用须保留，不能把行业术语本身当作 AI 味。
- `WR-019c` 中文正式材料中的必要英文术语、产品名、型号和缩写保持官方拼写与大小写。首次出现是否补中文全称、英文全称或简称，服从现行规范、用户材料和受众；不确定时不得自造译名或扩写。后文简称保持一致，不能因降 AI 味删除 `AI、GPU、API、SLA、PUE、Token` 等必要术语。AI 算力与云服务叶只收录已经核准的少量常见映射，不扩建通用词典；用户材料或任务适用标准有正式译名时以其为准。
- `WR-019d` 翻译腔按句群判断：多个介词框架、名词化动作或无主体长链反复遮蔽动作和对象时，优先改用直接动词。只有材料明确或上下文能够无歧义继承主体时才显化主体；主体不明时保留无主表达或只调整动词，不得新增责任主体、实施主体或归属关系。单个 `基于、面向、围绕、通过` 及政策标题、法律定义、专业术语不判错。

测算说明已经给出单价、数量、公式或范围时，保留可追溯关系，不因出现“测算口径、单价×数量、计算如下”判为 AI 味；是否表格化由文种和用户要求决定。严格 lint 在进入工程改动前，必须先用合法对比、测算追溯、复合核查、短而具体的并列要求和技术缩写真实稿验证误伤。

### WR-020 长报告与讲话稳定性

长稿先区分用途和文种弧线，不把所有报告固定写成“成绩—问题—措施”，也不把所有讲话固定写成“开场—成绩—任务—号召”。综合工作报告、机构履职报告、内部决策分析、法定审议型计划/预算报告分别允许不同的结论位置；讲话按致意、部署、总结、调研、承诺、主旨演讲等任务选择结构，并核对讲话人、场合、听众、时长、中心主题、受众需要理解或办理的事项、必提内容和敏感边界。

一个控制论点可以由多项相关数据、案例、机制或动作共同支撑，不等于“一段只能放一条事实”。短统领段、称呼重置、转场句、功能性平行句群和较密集论证段可以并存；不得把单句成段、排比或段长差异一律当作头重脚轻或 AI 味。限字比例只作可调整预算，不是所有长稿固定配方。长稿验收至少检查事实/状态覆盖、标题与段落映射、前后篇幅和论证密度、跨章节一致性、文种间结构差异及实际朗读节奏；先做真实写稿，再决定是否需要产品规则或 Hook。

### 编号沿革

`WR-015` 的活动新闻覆盖范围样本已经并入 `WR-013` 的即时作用边界和 `WR-018` 的丰富材料诊断，不再作为独立机制；`WR-017` 曾作为真实写稿题的临时标签，其“可安排”状态反例已由 `WR-014` 取代，结构差异观察并入 `WR-018`。仓库没有找到可还原的 `WR-016` 需求正文或独立结果，记为孤儿编号，不补造完成状态，也不复用该编号。

## Hook 产品边界

### HK-001 普通路径独立闭环

普通 Skill、未安装 Hook、宿主不支持 Hook或用户当前任务关闭 Hook 时，必须继续依靠 SKILL、references 和可选 lint 完成写稿。Hook 默认关闭，不自动识别宿主、不自动生成或安装文件、不修改配置、不主动联网。

### HK-002 写稿后插入

交付型 Hook 的唯一业务检查点是完整 D0 形成后的 `Stop`。`UserPromptSubmit` 只绑定原请求，`PostToolUse(Read/Skill)` 只记录本 Skill 已参与或材料可见性；修订、验收、选稿与回显均发生在 Stop 之后。

### HK-003 单一协调器

同一 companion 每次只启用一个静态 capability，包括默认交付复核、保护性外扩删除、篇幅不足补足、交付洁净度或重复清理。多个能力不得作为并行 Stop Hook 竞跑；由一个 coordinator 串行选择并限制继续次数。

### HK-004 宿主薄适配

能力核心和事务状态只维护一份。Codex、Claude Code、CodeBuddy adapter 只负责映射官方事件字段、插件根和数据根、阻断返回与信任/加载差异。宿主 adapter 不承载写作规则。

### HK-005 故障回退

Hook 模块缺失、超时、非法 JSON、hash 不符、span 漂移、回显不一致或验收不明时，只能交付逐字 D0 或明确失败；不得把错误的最后消息标成成功终稿，不得无限循环。

### HK-006 用户知情与关闭

启用前说明功能、速度成本、本地数据、目标目录和宿主差异。用户说“本次关闭 Hook、本次不要用 Hook、跳过交付门禁”时不创建能力事务、不阻断、不替换终稿。完全关闭按宿主原生插件方式处理。永久移除本地 Skill 包内 Hook 时只在 `hooks/README.md` 说明精确范围，必须二次确认，并由 Agent 使用宿主原生文件编辑能力执行。

### HK-008 终态数据最小留存

Hook 只在完成当前有界生命周期所需的时间内暂存原请求、D0、候选稿、删除 span、观察包和 capability 事务文件。正常到达终态 Stop，或 Stop 判定本轮不启动门禁后，必须删除本轮原始文本和事务文件，只保留 hash、字数、阶段、选择、交付状态、Stop 计数和清理失败数等不含正文的回执；重复 Stop 不得重建已脱敏事务。

删除目标必须解析到本 companion 的插件数据子目录之下，不删除数据根、其他插件、其他任务或宿主日志。终态前异常退出可能保留未完成快照，必须在启用说明中公开精确留存和清理边界；没有真实宿主需求前，不以后台 TTL、全局扫描或宽目录递归删除扩大工程面。

普通 Stop 自动启动门禁时，必须在写入 request/D0 前登记当前 turn 的 provisional txn。detect 同步失败、缺少 state 或后续同 turn Stop 发现未绑定 pending 时，只清理该 turn 并安全放行 D0；并发 Stop 只能有一个 bootstrap owner。只有真实非阻塞加锁竞争可以继续等待，锁文件永久 I/O 错误必须脱敏后安全放行。宿主硬退出且不再产生同 turn Stop 的情形仍按人工清理边界处理，不据此增加后台全局扫描。

## 篇幅不足能力

### UL-001 触发边界

只处理用户明确给出字数下限或区间，且完整 D0 低于下限 10% 以上的任务。不处理超长压缩；带宽内、只审、允许短于下限和用户关闭 Hook 时旁路。

### UL-002 安全扩写

只请求一次 D1。可以展开已给事实、透明分类、解释关系和加入不升级强度的自然衔接；不得用新增流程、具体职责、数字、结果、连续否定、空泛承诺或重复句式凑字。

材料已经明确同数“几方面”时，候选可以用“几项”概括同一组事项并进入语义核验；“前一项、后一项”等回指不视为新增业务数量。该规则只解除机械误拦，不替代事项、范围、归属和状态核验，也不允许把两个小区改成三个小区等独立数量变化。

### UL-003 准入门

准入首先看同一 D0 是否产生至少一份可直接使用的 D1，并确实解决篇幅不足且不引入事实、状态、文种和自然度硬失败。生命周期能触发并安全回退只是工程成立，不等于功能可上线。合格 D1 再交独立 SOL max 做同源增量终审。

### UL-004 宿主证据迁移

当 CodeBuddy 等宿主的 `hooks.json`、adapter 与中央 coordinator 和旧在线成功样本逐字相同，仅宿主无关的篇幅 runtime 变化时，可以迁移旧在线生命周期证据；仍须保留当前 runtime 的同稿复放和至少一个共享宿主在线执行。宿主胶水发生变化时必须重跑该宿主。

### UL-005 语义验收来源绑定

写稿模型对自己生成的 D1 做自由类别自审，不能作为唯一事实安全门。同一增量在不同轮次被改标为 `reasonable_inference`、`transparent_derivation` 或 `restatement` 时，类别名称本身不得决定放行。

下一候选必须让新增事实绑定可机械核验的请求或材料 span/hash，或交给真正独立且已证明判别能力的 verifier。`N方面→N项`等透明数量关系也必须携带权威上下文与候选归属，不能因数量相同直接放行。没有可验证来源、verifier 不可用、分类漂移或结果不明时逐字回退 D0。普通起草可以使用有主体和状态锚的合理推断；篇幅兜底不得仅靠推断增加字数。

单稿事实台账还须证明同一语义关系，而不只是证明若干真实 span 分别存在。主体、动作、对象、状态和强度不能从不同句或不同 span 拼接成材料未表达的新谓语；透明改写也必须绑定方向、角色和近邻关系。安全同义改写不得因逐字谓语不相等被一律拒绝。verifier 未返回合规台账或未形成最终选择时，记为无效生命周期，不得冒充已安全回退 D0。

## 快速收益型 Hook 能力

### CL-001 交付洁净度

在完整 D0 形成后的 Stop 检查用户可见终稿，处理用户未要求的过程旁白、协议或 JSON 泄漏、代码围栏、模型自评和正文外包装。只删除可分离的非正文 span；用户明确要求 Markdown、说明、审稿意见或结构化 JSON 时必须保留对应形式。失败或边界不明时逐字交付 D0。

### RP-001 重复句与高相似句

短稿、用户给定较短篇幅和超长稿件都可以检查完全重复句及高相似句。完全重复只生成删除候选；高相似只能作为语义观察候选，必须判断两句是否承担不同事实、层次、承接或结尾功能，不得仅凭相似度阈值自动删除。第一阶段只删除冗余 span，不自由改写。

### AH-001 引用与硬锚保护

引用与硬锚是所有会修改终稿的能力共享的不变量，不单独作为第二个改稿 Hook 竞跑。冻结用户或可见材料明确给出的标题、主体、名称、数字、日期、金额、文号、引语、字段、否定与未决状态；检查值、归属关系和唯一必要出现是否保留，不要求机械维持词频或重复次数。

本能力先用实验 worktree 对同一 D0/D1 做真实修订验证：允许安全去重和改写，禁止数值换对象、日期换事项、引语换来源、否定或未决状态升级以及唯一必要锚丢失。真实结果成立后才抽共享 contract，并由 under-length、over-length、保护性外扩、交付洁净度和重复清理逐项迁移；不得先把现有分散规则机械合并。

### OV-001 超长收束

只在用户明确给出字数上限或区间，且完整 D0 超过上限10%以上时触发。先做一次重复语义观察，再清理不承载信息的衔接、客套和同义收束；仍超长时最多两次压缩句式。每个段落或相邻句组只承担一个主要事项，同一原因、理由或目的只写一次。不得为达标删除硬锚、改变状态、合并不同责任、遗漏用户必需结构或把未决改成已决；任一步不确定、未达标或回显不一致均交付逐字 D0。

## 维护与发行

### MT-001 真实结果优先

先用最简 reference、prompt 或强制路由验证写稿；真实输出通过后再精修 Hook 胶水、镜像和必要测试。工程门不得代替真实写稿。

### MT-002 可达性

每个新增脚本和 Markdown 都必须由 SKILL、说明、组装器、测试或维护索引中的真实入口接引；禁止孤儿脚本、孤儿叶子和失效相对链接。

### MT-003 公开面克制

公开 README 只展示能力、用法、结构、MIT 许可和最近五次主要证据；维护命令、未来功能、HOLD 条件和内部思考只留在维护区。

### MT-004 信息熵与重复规则

SKILL 主入口只保留会改变路由或写作决策的高信号规则；文种细则、示例和停止条件下沉到按任务读取的 reference。近重复指令只有在真实稿件出现稳定回退时才合并或删除，不为缩短文件破坏叶子自包含。

### MT-005 Description 入口减载

Skill description 会随宿主发现或加载 Skill 进入用户任务上下文，应说明能力、任务簇和触发边界，不逐项罗列全部文种、机构和“不能做什么”。减载收益按每次加载持续节省的上下文计算；负向排除只有在真实宿主出现稳定误触发时保留。可由正向能力边界自然区分的英文、文学、营销、社媒、论文、求职等任务，不默认堆入入口描述。

减载必须一次只改一个可归因原子：`MT-005a` 只删除负向排除清单；`MT-005b` 再按新闻、制度规范、函件、讲话致辞等枚举簇拆成独立子原子，每次只删除或合并一个簇；`MT-005c` 只合并受众表述。前一原子通过后才开始后一原子，不用一个组合候选同时验证多种变化。

`MT-005b6` 只把 `制度、规定、办法、管理办法、实施细则、操作规程` 六项替换为上位触发词 `制度规范`，其余 description 逐字不动。分别用短篇规定、管理办法、实施细则、操作规程四个低频正向题和私人生活规则边界题验证真实触发、误触发与成稿；任何候选独有的未给职责、流程、日期、适用范围或用途扩张都先拆样本定位，不能用字数收益覆盖。

`MT-005b6` 的19字伞词候选与后续仅删除 `管理办法、` 的5字候选均已完成真实调用并拒绝接入：触发和边界没有共同回退，但候选分别新增职责、依据或责任归属。后续 `MT-005b6b` 只把 `实施细则` 缩为 `细则`；两轮正向4/4臂均自主触发并形成安全正文，私人生活边界2/2臂均不触发，已把本地候选 description 由204字降为202字。正文路由仍明确保留 `实施细则`，不与 `操作规程` 或其他枚举合并。

验收先看真实宿主的自主路由和成稿：每个原子固定低频正向正式文种和与该改动直接相关的边界任务；正向稿须进入 Skill 且无候选独有硬回退，边界任务不得出现候选新增误触发。真实 A/B 可以充分消耗测试 token；宿主、模型、权限和产品正文必须一致，避免把权限差异当成 description 结果。静态词表命中和 description 字数下降不能单独作为通过依据。
