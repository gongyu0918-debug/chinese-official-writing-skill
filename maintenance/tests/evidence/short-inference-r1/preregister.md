# 短稿、合理推断与原因缺口 R1 预登记

## 固定边界

- 基线：`main@6e4e8914431c5674a3fda87ab42d35ed8a531e8c`（v1.6.20发布回执后的当前主线）。
- 普通写稿使用五条登记低成本路线，reasoning effort 固定为 `max`；技术失败不计质量票，不用昂贵模型补写。
- 正文短于包含大量约束的完整提示词不判失败。正文短于事实材料只作诊断；真正的“过薄”是遗漏文种成立所需的理由、事项、状态、作用、结论或办理落点。
- 材料事实、常识和二者直接支持的一层合理原因、目的、即时作用、真实归纳、条件结论与低强度预期均可写，不要求逐字出现在材料中。不能把预测写成既成成效，也不能补具体人、单位、金额、程序、责任、期限、决定或量化效果。
- 本轮先真实写稿，后动 reference 或 Hook；每次只改一个原子。不修改description、adapter、包体、版本和付费分支。

## `WR-013d/WR-018-R2` 无字数限制事务稿

三道全新当前基线题：扫描仪采购申请、投影设备维修申请、培训活动新闻。分别检查：

1. 能否从已给痛点、既有尝试、拟办事项或通常功能逆推一层合理原因；
2. 能否形成范围受控的即时作用、真实总结或低强度预期；
3. 是否保留全部明确数字、日期、尝试、未决状态和发布者范围；
4. 是否不靠新增具体事实、程序、承诺、既成效果或同义重复撑长。

只有同一道事务题至少2个有效provider共同遗漏文种必要的理由/作用/事项落点，且不是题面本身不足，才允许做一个最小产品措辞候选。若当前基线已经稳定成文，只记录 `WAIT_NEW_COUNTEREXAMPLE`，不为了“看起来更长”改规则。

## `UL-005-R10` 篇幅不足扩写指令校准

现有 `under_length` 的写后核验已经允许“材料事实与通常功能直接支持的一层原因、目的、即时作用或低强度预期”，但扩写指令前段仍写“公文常识不能据此补写原因、目的、作用、影响”，可能使生成端先过度退缩。候选只统一这段指令：明确允许事实与常识闭合的一层关系，同时继续禁止具体新事实、程序、责任、量化效果和既成成效；机械硬锚、来源台账、同span核验和失败回退均不放松。

先用采购申请、维修申请两份材料充足而D0过短的固定稿，以及一份材料确实不足的控制稿做真实扩写A/B。目标题候选至少3/5达到用户下限且无候选独有硬回退；不足控制题必须仍返回D0或不补具体事实。只有真实D1成立后才更新单元测试和运行时提示。

## `WR-009b` 事务稿原因缺口正文外提示

后续独立测试四种情形：原因可由事实直接推断、原因不可推断且允许提示、用户只要正文、用户明确不提供/不需要原因。候选只在“事务性文种成立需要理由、材料和常识仍不能闭合、输出模式允许”时于完整正文后提示“建议补充申请/办理原因”；可推断时直接成文，不重复提示；只交正文或用户明确拒绝时不提示。

本原子不得把文后提示写入正文层级，不得为了触发提示删除可合理推断的原因，也不得改成普遍追问或强制阻断。
