关于版慎通智能审校系统增加公文AI写作功能的立项申请

现申请立项建设版慎通智能审校系统公文AI写作功能，并批准项目实施所需的模型开发订阅费用。有关情况报告如下。

一、立项必要性

（一）版慎通当前只能审、不能写，存在功能缺口

版慎通智能审校系统目前具备图书审校功能，且比较完善，但不具备写稿功能，用户对增加写作功能的呼声较高。补齐写作能力，是完善系统功能、回应用户需求的直接需要。

（二）公文写稿需求众多，市场空间大

该Skill在SkillHub累计下载10.5万次，足以证明用户对专业的AI公文写作能力有着丰富的需求。为版慎通增加公文AI写作功能，涵盖AI智能写作、红头文件生成、格式修复、AI味审校等能力，能极大帮助提升用户群体，使广大机关、企业、事业单位等获得广泛的垂直市场。

（三）拟采用的Skill已经市场验证

该Skill位列SkillHub下载榜前50，为公文写作领域第一；在ClawHub下载7000次，趋势榜长期保持前100，同样为公文写作领域第一。其变体作品公文写作智能体项目获江西出版集团首届AI大赛专业组第三名。同时，经指纹检测，深知、WPS等公司均有复用该Skill代码构建公文写作系统的迹象，尤其是去AI味模块、短稿路由模块和检测脚本模块。上述情况表明，该Skill的技术路线和能力已经市场验证，具备立项基础。

二、建设方案与开发方式

（一）技术路线选择

本项目有两种实现形式：一是完整的Workflow Agent，二是受社区广泛下载的Skill。结合市场行情和系统实际判断，Skill方案更为适配。线上Skill为开源方案，落地前需进行闭源改造并完成对版慎通的适配。

（二）Skill现状概述

该Skill经测试已对各家harness进行适配，由references、scripts、hooks三大模块构成：references按从大到小、从粗到细的方式组织写作，平均每次写稿热加载规则压在14K token，远低于其他Skill约100K token的平均水平；hooks在成稿后做微调检测，经三轮react迭代，最终成稿错误率在1%左右；scripts负责清洗和格式校验。具体技术情况见附件。

（三）开发方式与项目改造

项目当前采用CODEX开发。因从个人项目转为公司项目，需按公司研发要求对项目进行改造。当前开发流程（LOOP）为：idea—登记为openspec需求—独立worktree预先修改—真实写稿A/B测试—通过后补工程和胶水—并入main；测试不通过则总结经验，开新的worktree重新迭代。该开发模式日均消耗token10亿，其中主力开发模型7亿、测试模型3亿，对开发工具和模型订阅档位要求较高。

三、费用申请

根据开发进度和上述token消耗规模，模型开发费用安排如下：项目前几个月订阅Codex Pro 20X（1600元/月）作为主力开发工具，并辅以适量Alibaba token plan进行Qwen模型适配；后续视需要转为Codex Pro 5X（900元/月）。

以上申请，恳请批准。

附件

公文写作Skill技术情况说明

该Skill经测试已对各家harness进行适配，主要由references、scripts、hooks三大模块构成。线上地址：https://skillhub.cn/skills/user_f3d82da7/chinese-official-writing

一、references模块：公文写作规则路由系统

references模块对公文和事务性稿件做了专门的路由，写作规则来自真实写稿实践和互联网成熟公文的总结，按从大到小、从粗到细的方式组织写作，是一个成熟、复杂的公文写作规则路由系统。平均每次写稿热加载规则压在14K token，远低于其他Skill约100K token的平均水平，有效节约使用成本。

二、hooks模块：成稿微调检测

references成稿后，由hooks模块做微调检测，涵盖字数一致性、提纲与正文一致性、篇幅一致性、AI味词汇、prompt遵循等方面，主要关注“提纲—正文”“成稿—交付”两个生命周期。对agent能发现的错误，hooks将稿件返回模型进行重改；经三轮react迭代，最终成稿错误率在1%左右。

三、scripts模块：清洗与格式校验

scripts模块主要针对显式AI味、错误、Markdown残留等进行清洗，并对成稿格式进行校验。
