# WR-026-R4 短意见正文能力预登记

日期：2026-09-02。

## 起点与目的

固定公开产品起点为 `main@821364abfd7df2fa0af04f5e3ab7277897110ff0`。本轮在独立 worktree `codex/wr026-short-advice-r4` 重开短意见，但不沿用 R1—R3 的“壳层数量净胜”作为唯一目标。

R1—R3 已证明：把载体说明写成显式禁令或“可直接粘贴正文”等元话语，可能诱发模型复述交付方式；这不等于短意见功能本身应放弃。本轮把它视为新增正文能力：短意见仍应成为一份有事实或依据、有明确主张、有权对象和必要说理的意见，只是根据载体压缩形式要素，不缩成提示词改写或机械的“问题—方案”标签。

## 单一产品原子

只允许修改 canonical `references/genre-playbook-advisory-feedback.md` 的“结构与版式”一处，并在真实写稿通过后再同步五套公开镜像。不得同时修改 `SKILL.md`、通用短稿页、description、Hook、版本或其他文种叶。

候选应表达以下结果，不使用固定字数、固定条数或包装禁令：

- 短意见在一至两个自然段内承载建议方的实际情形或依据、直接影响或判断、面向有权对象的具体建议；材料与常识直接支持时，可以写一层原因、作用或条件性结论。
- 外部字段已经承载题名、身份、联系方式时，正文不重复这些形式要素；独立成文且任务给出题名、建议方和日期时仍保留。
- 不把正式长意见压成短意见，不改变通知等其他文种。

## 真稿任务

使用 `cases.json` 的五道全新自然任务：政务平台建议栏、业务反馈邮件、独立成文短意见、正式长意见控制、已决定短通知控制。Baseline 与 Candidate 使用相同请求，普通写稿只使用项目登记的五条低成本 provider，reasoning effort 为 `max`；技术失败、错误模型、未加载当前 Skill 或全局 Skill 污染不计质量结果。

## 唯一通过门

真实写稿是产品准入的唯一通过门；确定性测试只能在真稿通过后确认路由、镜像和包体，不能把失败稿“测成通过”。

1. 正向稿应能直接用于其指定载体，写清已给事实或第一方依据、由事实直接支持的影响或判断、具体建议及有权对象；状态未定时仍保持建议或待研究状态。
2. 候选不要求逐句或逐项胜过 Baseline，也不因合理的一层归因、作用、总结、预测、条件性结论、常见礼貌语或普通文采差异判失败。没有逐字复现某个状态词，只要语义强度未升级，也不判失败。
3. 硬回退只包括与本原子可归因的错误事实、数字、日期、主体、权限、决定状态、文种功能，或违反用户明确交付形态；材料外具体程序、承诺、责任、金额、期限和既成成效仍是硬风险。
4. 单一 provider 的偶发包装或风格摆动先做同题复核和最小拆句，不直接终止。只有跨 provider 复现，或同一候选措辞可重复诱发硬回退，才阻断该句。
5. 候选准入至少需要两个实际读取目标叶的独立 provider 呈现新增的短意见正文组合，并且五家有效正向稿总体可用；控制题不得出现共同的候选相关回退。若首个候选未通过，按失败所对应的单一子句继续最小调整，不以一次失败宣布整个功能终止。

## 外部校准

既有官方样本继续有效；本轮另复核北京市政府典型建议、上海市人民建议指南和中央社会工作部关于建议质量的公开材料。共性是：载体字段可以承载标题和身份，但建议内容仍需有问题事实、理由或判断及可行对策；短不等于空泛，也不要求复制完整长稿壳层。公开材料只校准方法，不进入真稿事实。来源和窄结论见 [`official-corpus-r4.md`](official-corpus-r4.md)。
