# WR-014-R6b 证据未附与事项状态预登记

日期：2026-08-26。

## 启动原因

`WR-014-R6` 的原定目标是区分持续动作、一般职责和明确未开展。OpenCode 与 Ollama 两份 Baseline 都没有把明确未开展项写成“继续处理”，原目标未复现，不能启动原候选。

两稿同时出现了另一个共同反例：材料只说服务商已经修复、核验记录未附，两稿却分别改成“尚未获得核验确认/暂不能认定处理完毕”和“核验结论未定/结果待确认”。这与原预登记中“已核验、正在核验或安排核验”的失败枚举不同，不能事后并入原目标，须用全新材料独立确认。

## 新题与固定基线

- 固定 Baseline 仍为 `main@6d7fc0ec8f1227638652527670f251eba9d76f86`。
- provider 仍只用 OpenCode Go、Ollama DeepSeek V4 Flash，均 `max`，每家一次有效终稿；技术失败最多补一次，不质量重抽。
- 新题改为实验平台运行问题情况说明，同一稿内分别包含：已经完成但服务报告未附、已经完成且材料明示运行效果待观察确认、正在处理、明确未开展、持续汇总和协调会未形成新安排。

## 唯一目标

“报告、记录、证明未附”只表示当前材料中的证据不可见。材料同时明确动作已经完成时，正文分别保留“已完成”和“未附”，不得仅由未附改成尚未核验、结果待确认、尚未完成或需要安排核验。材料另行明示“运行效果待观察确认”时必须保留该真实未决状态，不能因保护前一项而把所有待确认表述删除。

两路 Baseline 都出现下列任一目标失败，才启动 Candidate：

- 把服务报告未附推成修复尚未确认、结果待核、尚未完成或需再核验；
- 把材料明示的运行效果待观察确认删掉或改成已经确认；
- 混淆正在处理、明确未开展或协调会边界。

Candidate 只能在 `references/information-selection.md` 的状态规则近场增加一句通用范围说明，不增加文种枚举、责任、流程、期限、Hook、lint 或 description。Candidate 同题两路必须修复目标，完整保留数字、日期、主体和全部状态，不得新增正文外说明；任何候选独有硬回退即拒绝。
