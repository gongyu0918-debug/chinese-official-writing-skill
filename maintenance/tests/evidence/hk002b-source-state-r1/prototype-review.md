# 固定原稿原型的独立复核

五条 Codex CLI 路线均以 max 完成同一组五题，共 5 次调用、25 个题目观察；不是 25 次独立调用。Ollama 实际请求为 `ollama-cloud/glm-5.3-flash`。更早准备目录中的旧 Ollama 配置没有执行调用。

两个明确错误分别是历史真实原稿的“上述时间明确后，目录核对和验收工作可相应推进”和诊断对照的“业务科尚未开展18份附件核对，其中10份已经完成”。后者材料明确正在核对，不是历史自然出错样本。五路均检出两处明确错误，10 条材料/原稿引句经连续包含核对均真实存在。

| 路线 | 进行态修订建议 | 无据日期条件修订建议 |
| --- | --- | --- |
| OpenCode DeepSeek V4 Flash | 修对 | 仍将业务科室反馈和抽检完成捆绑给目录核对、验收两项，未修稳 |
| Ollama GLM 5.3 Flash | 修对 | 重复紧邻句中两个日期未定事实；局部新增材料支持的数字8 |
| Alibaba 1 Qwen 3.8 Flash | 修对 | 新增“抽检已按确定的安排先行开展”，把安排已定升级为实际开展 |
| Alibaba 2 Qwen 3.8 Flash | 修对，但补入材料日期 | 分开附件反馈与抽检完成两个条件，语义修对；局部新增材料支持的数字8 |
| MiniMax M3 | 修对 | 分别对应附件归属反馈后处理目录、抽检完成后统计验收数量，修对 |

新增局部数字有材料依据，不等于编造；它们仍不满足本次固定局部修订的原硬锚要求。Alibaba 2、MiniMax 返回整个 JSON 的代码围栏；Alibaba 1 一个对象缺少 `uncertainties`。技术形态和可读内容分开记，不补齐原响应。

历史原稿的“未完成抽检→尚未抽检”改判为有争议，不能计为确认漏检。完整材料另写“下一步准备先……抽检；这项安排已定”，没有明确已开始。此前仅凭单句对照的错误确认撤回。明确进行态对照保留为测试对象。

两份正常对照五路都没有误报，保留最新更正、可能原因及建议；没有要求补回被最新累计覆盖的150，也没有误报“超过八成”、3盒包含在30盒内、设备维护的影响分析。“抽检后据实统计验收数量”按同项自然后续保留，不重新判为新增制度。

本轮只有检测和建议，未执行选稿或最终交付。独立复核由现有子代理只读完成，无新模型调用或稿件改写。原始证据见 [完整输入](raw/prototype/cases.json) 和 `raw/prototype/runs/{route}/attempt-01/final.txt`。
