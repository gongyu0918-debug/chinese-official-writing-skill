# 会议纪要 Playbook

本文件用于命中具体文种或专项时快速进入正确骨架。每个文种小节都是可从 `SKILL.md` 直接进入的叶子路由，只给适用边界、输入要素、结构骨架、常见误区和条件式补充读取。

## 使用方式

- 从 `SKILL.md` 直接进入本页；本页只给文种骨架和专项风险，不补材料外事实。字段式材料按入口硬边界保持字段单元，信息进入正文、保持状态、省略或短列缺口按 `information-selection.md` 处理。只有任务另有复杂改稿、多材料合稿或文种/行文关系不明等条件时才补读长 reference，节末“补充读取”不是固定清单。

## 会议纪要

- 适用：会议记录、录音整理、议题讨论稿需要转成纪要；重点是议定事项、责任、期限和后续动作。
- 不适用：会议新闻、宣传报道、个人笔记、逐字稿全文整理。
- 骨架：会议主题和范围 -> 议题或讨论要点 -> 议定事项 -> 责任单位/责任人 -> 完成期限 -> 未决事项。
- 路径：决策会重“审议、原则同意、决定、要求”；办公会重“听取、研究、明确、要求”；专题会重“听取、研究、明确”；座谈会重“听取、认为、指出”。材料未给会议结论时，只整理已给事实和当前状态。同一句中的主体、动作、期限应保持绑定，不把有期限的事项拆成多个待明确字段，也不把一个期限扩展到原文未绑定的其他任务。
- 风险：不写成会议新闻；不把发言顺序当成结论顺序；不编造“会议决定”；原材料只给议题、责任和期限时，不补写“会议认为”“会议强调”等未给会议判断，也不补写问题类型、产生环节、处理建议、保障效果等未给交付物；责任或期限未给时不使用“按审核执行”“后续推进”等泛口径补齐。
- 补充读取：`genre-checklist.md` 的纪要小节、`review-checklist.md` 的只审不改规则。
