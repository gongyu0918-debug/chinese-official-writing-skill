# 文种与专项 Playbook

本文件用于命中具体文种或专项时快速进入正确骨架。每个文种小节都是可从 `SKILL.md` 直接进入的叶子路由，只给适用边界、输入要素、结构骨架、常见误区和条件式补充读取。

## 目录

- 使用方式
- 函/复函/征求意见函
- 通知/通告/公告/公示/通报
- 意见/决定/决议/议案/公报/命令
- 讲话稿/致辞/述职
- 调研报告/研究报告/可研报告
- 采购公告/审查材料

## 使用方式

- 从 `SKILL.md` 直接进入本页；本页只给文种骨架和专项风险，不补材料外事实。字段式材料按入口硬边界保持字段单元，信息进入正文、保持状态、省略或短列缺口按 `information-selection.md` 处理。只有任务另有复杂改稿、多材料合稿或文种/行文关系不明等条件时才补读长 reference，节末“补充读取”不是固定清单。

## 函/复函/征求意见函

- 适用：平行商洽、答复来文、征求意见或协调事项。
- 骨架：来文依据或事项背景 -> 商请/答复/征求事项 -> 办理意见 -> 反馈期限和渠道 -> 联系人和附件。
- 风险：复函重回应来文；函不写成命令；征求意见函必须给反馈路径。
- 补充读取：`formal-addressing.md`、`genre-checklist.md` 的函和征求意见函小节。

## 通知/通告/公告/公示/通报

- 适用：布置办理、公开周知、公示名单或事项、通报已知情况和明确要求。
- 骨架：事项 -> 对象范围或已知事实 -> 已给问题或要求 -> 已给时限/渠道/联系人；材料未给执行要求、整改要求和后续处理时，不为了像通报而补写。
- 风险：通知重执行，公告/通告重公开范围，公示重异议渠道，通报重事实和已给要求；不要互相套用。通报只给“已完成梳理、发现问题、组织协调会”等事实时，可用短骨架“已完成事项 -> 发现问题 -> 已组织协调（只陈述次数或事实）”；协调会只写“已组织2次协调会”，不展开会议内容、处理边界、问题清单、对接要求、闭环机制或督办安排，也不写“对关键问题讨论、沟通、归集、说明、形成意见”；材料未给整改、处置、下一步安排时，不新增“已开展处置”“下一步安排”“整改方向”“治理闭环”“督导流程”等章节或小标题。用户第二轮指出补造事实或要求删未给内容时，按 `workflow.md` 的事实映射式二次修改删掉未支持推断。
- 补充读取：`genre-routing.md` 和 `handling-elements.md` 的对应行。

## 意见/决定/决议/议案/公报/命令

- 适用：规范性部署、会议审议结果、提请审议、权威发布或命令事项。
- 骨架：权限和依据 -> 事项或决定 -> 适用范围 -> 执行要求 -> 生效或后续程序。
- 风险：命令（令）不用于普通内部部署；公报只写适合公开的权威事项；议案不能写成一般建议。
- 补充读取：`genre-checklist.md` 的对应法定文种小节。

## 讲话稿/致辞/述职

- 适用：正式场合发言、活动致辞、述职报告等事务材料。
- 骨架：场合身份 -> 主题态度 -> 事实或工作基础 -> 重点任务/体会 -> 结尾落在责任或目标上。
- 风险：可比公文更有感染力，但不能空泛排比、编造成效或写成宣传口号堆叠；称呼和受众按材料给定，未给同学、领导、嘉宾等对象时，不自行补受众称呼。
- 补充读取：`official-style.md` 和 `anti-ai-patterns.md`。

## 调研报告/研究报告/可研报告

- 适用：专题调研、研究分析、可行性论证。
- 骨架：对象和范围 -> 事实、数据、样本 -> 发现和问题 -> 原因或方案比较 -> 建议/可行性/建设内容 -> 条件和风险。
- 路径：调研报告先锁定对象、样本、事实和问题；可研报告先核对项目类型、建设性质、建设内容、投资估算、资金来源、实施条件、风险和效益。
- 风险：不把公文报告写成投研报告；建议必须回到调研事实；可研结论要说明条件和测算边界。项目类型、资金来源、投资估算或测算口径缺失时不使用地方模板或空表补实，按 `information-selection.md` 判断是否属于实质缺口。
- 补充读取：`argument-chains.md` 的可研、调研和审查，专项技术材料再读 `ai-compute-docs.md`。

## 采购公告/审查材料

- 适用：公开采购事项、审查意见、初步设计或项目材料审查。
- 骨架：采购公告写采购主体、项目名称、预算、内容、资格、响应期限、提交方式、联系人；审查材料重点是依据、发现、风险、整改要求和结论。
- 路径：采购申请、采购公告和采购审查优先核对品名、规格、数量、预算或单价、供应商/报价依据、提交方式、验收和归档要求；已给的信息按文种功能组织，未给事项按 `information-selection.md` 处理，不写成正文里的流程承诺。采购需求不等于现有能力不足、效率提升、业务范围不变或影响结论；用户只给预算时写“预算为”，不包装成“经测算”。
- 风险：普通采购公告不默认进入 AI 算力语境；字段式审查材料只改用户指定字段，其他字段按原行、原字段名和原值保留，拆行时不保留原分号为行尾噪声；不得补造品牌、型号、供应商或评审结论。
- 补充读取：`handling-elements.md` 和 `genre-checklist.md` 的采购公告、审查材料小节。
