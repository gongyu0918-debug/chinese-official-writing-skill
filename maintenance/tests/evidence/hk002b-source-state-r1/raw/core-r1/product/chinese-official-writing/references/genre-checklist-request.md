# 请示/申请细查

本文件只在请示、申请需要细查文种功能、办理要素，或用户要求审稿、复核时读取。起草请示、申请仍按 `genre-playbook-request.md` 进入文种骨架。

## 请示

- 采购请示审稿时，供应商未定可以作为当前核心状态保留；由此顺带列出的合同未签、到货未发生、验收未实施、付款未发生等下游否定链直接建议删除。材料另有独立办理需要时除外。
- 资金已列入预算或已落实时，正文不再叠加“无需追加、不影响其他工作、完全满足需要”等外围充分性证明；审稿建议保留预算事实并删去保护性尾部。
- “持续推进、确保按期完成”没有材料给出的责任主体和期限时，不建议反向要求用户补齐套话依据；优先删除，或回到材料已有的当前进展。

- 一文一事，开头或前部明确请批事项。
- 依次说明依据、现状、必要性、经费或资源需求、拟实施安排。
- 结尾使用 `妥否，请批示`、`请予审定`、`请予批复` 等请批语。
- 不要写成包含多个无关问题的报告。

## 申请

- 写清申请主体、申请事项、依据、金额或资源需求、项目状态、使用计划和承诺。
- 经费申请可分项目单位、背景、建设内容、投资估算、资金来源、申请额度、绩效目标和真实性承诺。
- 企业或内部审批申请可能采用“单位名称 + 申请标题”两行标题、`尊敬的领导：` 等信件式称呼、字段式费用明细和右下落款日期。用户提供这类真实模板时，应保留其模板骨架，不强行改成法定公文主送机关格式。
- 向上级或领导班子请求批准时，可使用 `妥否，请批示`、`以上申请，恳请批准`、`恳请予以支持` 等结尾；结尾应放在落款和成文日期之前。
- 不要只因出现 `妥否，请批示` 就判定为请示；先看标题、申请事项、接收对象和用户模板。但若用户明确要求特定结尾，应按用户要求执行。
- 可参考顺序：申请主体、申请事项、依据、金额或资源需求、使用计划、承诺和结尾。
