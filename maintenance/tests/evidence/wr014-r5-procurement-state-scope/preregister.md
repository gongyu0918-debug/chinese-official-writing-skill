# WR-014-R5 采购状态层级真实写稿预注册

固定基线：`main@4a55c283da60c3ad5ed3d6a43708d803744a7120`。

## 单一目标

验证模型会不会把“局部采购节点未定”上推成“整体采购决定未形成”，并确认修复不会误删材料明确的整体未决状态，也不会压制事实支撑的原因、影响、结论和论证。

## 模型与角色

普通写稿只使用五个便宜 provider：OpenCode Go DeepSeek V4 Flash、Ollama Cloud DeepSeek V4 Flash 0731、Alibaba Token Plan DeepSeek V4 Flash 0731、Alibaba Token Plan 2 DeepSeek V4 Flash 0731、MiniMax M3。Kimi K3、Grok 4.6、Qwen 3.8 Max 不用于本轮普通写稿；若候选达到集成条件，只用于独立冷审。

同一 provider 的 Baseline/Candidate 使用同一三题、同一提示和相同 `max` 思考档位。每臂首个完成结果冻结；技术失败不计质量，不用另一模型结果顶替。

## 三题与判定

### A 已决总体、局部未定

材料明确馆务会已经原则同意采购2台设备、预算已安排，只剩型号、供应商和采购方式未定。

- 必须保留总体已决与三个局部未定节点。
- 写成“尚未形成采购决定”“未作出采购决定”“采购尚未获批”等相反总体状态，判 `HARD_FAIL_STATE_UPWARD`。
- 可以结合现有借还量、排队和故障事实说明采购原因、即时作用或低强度预期；只要不写成既成成效，不因推断本身判失败。

### B 整体未决明示

材料明确会议仅听取试用情况，决定继续试用和补测，之后再研究是否新增采购，没有作出新增采购决定。

- 必须保留整体未决办理含义；“未作出新增采购决定”或由“仅听取、继续试用、补测后再研究”完整承载均可。
- 不要求逐字保留“形成采购决定”，不因自然正向改写判失败。
- 升级成已决定、已批准、已安排采购，判 `HARD_FAIL_STATE_UPGRADE`。

### C 具体采购阶段

材料明确政府采购活动已经启动、资格审查正在进行、活动尚未完成且中标/成交供应商尚未确定。

- 必须保留已启动/进行中、活动未完成、供应商未定三个层级。
- 用“尚未形成采购决定”替代上述具体状态，造成阶段或对象丢失，判 `HARD_FAIL_STATE_ABSTRACTION`；具体状态均保留而另加抽象概括，只记 `STYLE_SCOPE_NOTE`。
- 写成采购尚未启动或供应商已经确定，判硬失败。

## 候选与准入

先跑 Baseline。只有至少两家有效 provider 出现目标上推、抽象替代或整体未决误删，才做一个 reference 单原子；优先修改 `information-selection.md` 的状态层级，不加词表禁令、不先改 Hook。

候选必须消除目标问题，且不得新增事实、状态、主体、程序、承诺、既成成效、文种或直接可用性硬回退。合理原因、影响、结论和论证按上文接受。若 Baseline 已稳定，无产品修改，记录 `CURRENT_PRODUCT_SUFFICIENT`。

Hook 只在 reference 候选确有目标收益后，用同一 D0 做关闭/开启观察；D0 安全回退不等于修复成功。未出现独立 Hook 目标收益时不新增 capability 或 adapter。
