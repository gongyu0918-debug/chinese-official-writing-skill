# WR-025d 反馈词路由与同总数重组原子预登记

日期：2026-09-02。

## 目的

冷审发现当前合作性建议反馈直达词覆盖“意见建议稿、建议反馈、优化建议”，未显式覆盖对外提交的“反馈意见、意见反馈”；机械补词又可能把收到的反馈、反馈办理结果误路由。另有一项独立风险：建议专叶要求存在同类项时归并后条目总数不能原样不变，可能误伤同时发生合并与按权限拆分、最终总数合理不变的真实重组。

## 固定基线与原子边界

- 固定基线：`f03081dbaf6dd946b1fb2c4d9edc7ca37e017327`。
- 路由候选只允许修改 canonical `SKILL.md` 中两处建议反馈直达说明，并由既有同步工具复制到五套公开镜像；不改建议专叶、Hook、description、版本或其他文种叶。
- 同总数重组题先只观察当前专叶，不预设产品改动。只有至少两家有效 provider 因总数规则出现共同的错误归并、错误拆分或遗漏，才另拆候选；模型合理保留三个重组后条目不算失败。

## 真实写稿题

1. `FEEDBACK-OPINION-OUTBOUND`：向政策材料起草方提交正式“反馈意见”。
2. `OPINION-FEEDBACK-OUTBOUND`：向申报平台运营方提交“意见反馈”。
3. `CONTROL-RECEIVED-FEEDBACK`：整理已经收到的反馈意见和反馈办理结果为内部情况说明，不向平台提建议。
4. `ADVICE-SAME-COUNT-REORGANIZATION`：两项同因同权责应合并，一项混合不同处置权应拆分，重组后总数可以仍为三项。

## 模型与准入门

使用五条低成本 DeepSeek V4 Flash / MiniMax M3 路线，思考强度 `max`。路由候选只有同时满足以下条件才准入：

- 两道对外正向题中，至少两家基线未读取建议反馈专叶，而候选读取并形成可直接使用的合作性正式稿；
- 控制题不得因新增词语读取建议反馈专叶，不得把已收到的反馈改写成向外建议；
- 日期、数字、主体、已决/未决状态和权限关系无候选独有硬回退；
- 只把与本 diff 有关的路由、文种、状态或正文交付回退计为候选失败。

同总数重组题与路由候选分别判定，不用一项失败否定另一项，也不以固定条数代替人工核对原因、对象和处置路径。
