# 连续否定全位置原子有效性修正

日期：2026-08-10

第5提交后的独立轻量 review 发现，首版 harness 仅检查 T1、T2、T3、C1、C2、C3 六个标题是否各出现一次，没有检查冻结 prompt 要求的标题顺序。

## 新发现的无效配对

`alibaba-r1-candidate` 的实际顺序为 T1、T2、C1、C2、C3、T3。虽然六项均存在，但违反固定输出顺序；对应 `alibaba-r1` 整对作废，原匿名包 P1 和两份裁决中的 P1 不再计入胜负或不劣证据。

连同此前缺 T3、C2、C3 的 `ollama-r3-baseline`，首轮最终有效性为：

- Alibaba R2、R3：2个有效配对；
- Ollama R1、R2：2个有效配对；
- Alibaba R1、Ollama R3：2个无效配对，均整对作废；
- 共4个有效配对、8份有效 final。

## 修正动作

1. 不重跑、不补稿、不覆盖旧输出；
2. harness 的 `headings_complete` 改为同时要求六标题各出现一次且位置严格递增；
3. 新建通用的有序标题筛选器，从 manifest 和原始 final 重新计算有效性，不硬编码本次五对结果；
4. 重新随机映射4个有效配对并独立盲审；
5. 旧五对匿名包、mapping、两份裁决和 superseded 文档继续保留，只作审计链，不进入最终裁决。

该修正发生在跨模型留出启动前；留出直接使用修正后的标题完整性定义。
