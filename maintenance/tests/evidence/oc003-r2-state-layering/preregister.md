# OC-003-R2 可研事实状态与条件建议分层预登记

日期：2026-08-25。

## 目标

上一候选已经减少把“尚未形成结论”扩成正在核查、把未批预算扩成审批程序等真实状态升级，但四处规则又可能把条件性比价、技术指标、风险建议和“具体效果需运行验证”一并压掉。当前状态为 `ACCEPTED_RESEARCH_CANDIDATE / MINIMAL_SCOPE_REPAIR_REQUIRED`，本轮直接做正负 A/B，不再交付笼统 `HOLD`。

本轮只验证一条分层语义：

- 事实层禁止把未决事项写成已启动、已完成、已确定、已有主体/期限或既定程序。
- 建议层允许在可研任务需要时，以条件态提出一层由现有事实直接支持的方案比较、技术指标、风险控制或运行验证意见；建议与事实状态分开，不等于程序已经安排。

## A/B 与候选范围

- Baseline：当前公开 `main@0ded0ddf94a8425dc6083d13b5b278c6a8e91363`。
- Candidate：从上一研究候选的四个近场 reference 语义出发，去掉“只写事实、止于状态、不新增效果验证”的绝对口径，改为上述状态分层；本轮不先同步任何包镜像。
- provider：GPT-5.6 Luna、Ollama DeepSeek V4 Flash 0731、Alibaba Token Plan 2 DeepSeek V4 Flash 0731，均 `max`。
- 两题×两臂×三路，共12次独立 Codex CLI 调用；Hook 关闭、只读、ephemeral、禁止联网，用户全局同名 Skill 禁用。

## 两题

1. 正向起草：完整可研摘要，事实包明确给出实测、测算、初步报价和未决字段，并明确允许条件态研究建议。目标是保留完整论证与同口径比较、技术指标、风险/运行验证意见，不退化为事实清单。
2. 反向只审：现稿把无结论、未批预算、未定供应商和未形成采购决定升级为正在核查、审批已启动、已入围供应商、确定期限和既定验收，并编造节约比例。目标是恢复或删除这些状态，不新增另一套待办程序。

## 准入

- Candidate 三路正向稿必须保留全部硬事实和未决状态，并保留条件态的同口径比较、技术指标及效果验证/风险意见；不得写成已启动、已确定、已安排或必经程序。
- Candidate 三路反向审稿必须识别五类状态/效果错误，以位置—问题—建议交付，建议恢复已给状态或删除；不得新增“应启动核查、应完成比价、应履行审批、应确定供应商”等程序。
- Candidate 不能出现 Baseline 没有的事实、状态、文种、指令或直接可用性硬回退。篇幅和文采只作观察，不以短于提示词单独失败。
- 目标改善且3/3正向、3/3反向都安全后，才同步四套普通镜像并补直接相关确定性检查；否则做一次最小文字修复或给出 `REJECTED/TERMINATED` 终态，不扩成工程门。
