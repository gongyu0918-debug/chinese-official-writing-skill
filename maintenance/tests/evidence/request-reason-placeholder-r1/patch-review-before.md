# 申请原因占位补丁快速核查

结论：规则主体边界正确，但引文豁免有一处高置信漏洞，建议修正后再收录。

## 实质问题

`plain_line_findings()` 通过“本段从开头匹配 `SOURCE_EXCERPT_PREFIX_PATTERN` + 当前命中位于任一引号内”判断原文保护。它没有把命中绑定到“原文”前缀直接引出的那一段引文，因此同段后续引号也会被误豁免：

```text
材料原文：“原定9月20日完成。”改稿写为“因＿＿＿，现申请延期。”
```

当前 `draft-body` 对第二处返回无 finding；换成下一行但不空段也仍无 finding。含空格的“空行”不会被 `rsplit("\n\n", 1)` 识别，误豁免同样延续。这样正文可在引用真实材料后，把新增占位藏进后续引号并绕过检查。

最小修正：不要按整段前缀豁免。对每个命中，确认它所在引号就是 `原文/原句/引文/引用（如下）：` 后直接开始的引号；可在当前行取命中所属 quoted span，再核对 span 左侧仅有该来源前缀和空白。跨行引号沿用现有 `quoted_spans` 状态，但应记录该 active quote 是否由来源前缀开启，不能因段首曾出现来源词而保护所有引号。

## 其余核查

- `unfinished-reason-placeholder` 独立置于 `DRAFT_BODY_PATTERNS`，未扩大既有 `unfinished-placeholder` 或其他 label；`generic/review-only` 不加载。
- `因/由于/鉴于 + 下划线`、`〔延期原因〕`、`因（延期原因待补）` 各只命中一次，无重复 finding。
- `延期原因：＿＿＿`、`延期原因：因＿＿＿，…`、表格同类空位、纯下划线、`---` 均不触发新 label；真实原因不触发。
- 标准 `文后提示` 继续由正文分区豁免。
- `python -m unittest maintenance.tests.test_review_regressions`：91 项通过。但现有引文测试只覆盖“材料原文引出的唯一引号”和跨行同一引号，未覆盖同段第二个引号，故未发现上述问题。

本次只读核查，未改脚本或测试。
