# 申请原因占位检测：独立脚本原子

基线 `f375e047`。本原子仅改 `scripts/prose_lint.py` 及普通镜像，references 和篇幅脚本没有随之修改。新增 medium 提示 `unfinished-reason-placeholder`，只在 `draft-body` 和 `gap-note-allowed` 的正文区检查。

## 检测与边界

真实写稿中三类原因空位原先漏检：`因＿＿＿＿＿＿＿＿，`、`〔延期原因〕，`，以及后续采样出现的 `因（延期原因待补），`。新检查要求原因句位置和逗号/分号衔接，不把普通字段、表格、横线分隔或真实原因一概判错。它只提示风险，保留现有 CLI 默认返回行为。

明确来源引文继续保留。独立[补丁核查](patch-review-before.md)发现原型会把“材料原文”之后同段的第二个普通引号也豁免，已修为将命中绑定到来源标记直接引出的引文，沿用已有跨行引号范围；新增同段、跨行及空格空行反例。其他 label 的引文行为保持原实现。

[原始漏检诊断](probe-before.md)、[初版重放](replay.json)、[最终重放](final-script-replay.json)和[CLI 样本](cli-smoke.json)均保留。最终脚本对 64 份已有实际交付重放，新增 4 个原因占位命中，逐项均为正文中的缺原因空位。这里证明检测能力，不证明模型会按提示正确修改。

这些结果支持补足检测盲点，也说明软性提示尚不能保证错误被处理。不能把脚本检出或调用次数写成写稿质量已稳定。正文缺原因、文后提示、模板识别和过程旁白仍需后续语义原子处理。
