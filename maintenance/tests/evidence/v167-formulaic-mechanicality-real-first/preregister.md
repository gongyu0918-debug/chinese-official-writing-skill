# WR-005 常用语机械化真实写稿预注册

## 目标

验证 v1.6.6 的 `formulaic-language.md` 是否使不同文种反复出现相同开头、承启、总结、尾语或段落骨架；同时验证“结构优先、惯用语稀疏可选”原型能否降低同质化，而不损失文种功能、事实边界、用户结构和直接使用性。

本轮先写稿后改产品。预注册、原型和题面不等于产品候选；真实结果未达到目标时，不修改 canonical 或普通镜像。

## 固定对象

- 发布基线：`v1.6.6^{commit}=b49da7f2a5a8ac2327252d29efd66f1d54ccbc35`
- 发布产品 tree：`7d9e56cfe4f33ad79de3c97e95be60a6db53ae9a`
- 当前 `formulaic-language.md` SHA-256：`278e36f7d1774551b28efb0d108107e01b82054380d79c260c3e9969ba2a3d40`
- 原型文件：`prototype-formulaic-language.md`，SHA-256 `7ed20aa24167e07e32a666efc0a4bf0d3074a73aed4a0035ce4c50c473087563`；正式运行中不修改。
- 题面：`cases.json`，SHA-256 `0bab8696cd2bc82cb6a8e40244cb41fcef717385bf684f7b5df541e3b5780ba9`；20类事务文体加4个用户自定义结构反控，共24题。

- A：发布版 v1.6.6 产品树。
- B：逐字复制发布版产品树，只用研究原型替换 `references/formulaic-language.md`。
- 同一题、同一 provider 各生成 A/B 一稿，共24对、48次调用。
- provider 各8题：`opencode-go/deepseek-v4-flash`、`ollama-cloud/deepseek-v4-flash:0731`、`alibaba-token-plan-2/deepseek-v4-flash-0731`。
- 全部 `max`、1200秒、0 retry、只取首个完整终稿；每臂独立 HOME、配置和临时目录。三条 provider lane 可并行，每条 lane 内串行，A/B 顺序按 case 固定交替。
- 普通 Skill 路径，无 Hook、无联网、无写文件；只允许读取对应隔离 Skill 根的 `SKILL.md` 和实际路由需要的 references。

## 技术有效性

终稿非空、exit 0、模型与 provider 精确匹配、无重试、无联网、读取范围没有离开当前隔离 Skill 根。任一臂无效则整对只记技术无效，不补跑、不换题。

## 质量判断

先做机械边界，再做匿名 SOL max 逐对复核：

1. 事实、数字、时间、主体、未决状态和用户固定字段不得丢失、改写或外扩。
2. 用户明确给出的标题层级、段落顺序、单段写法、不要总结段或指定尾语必须保留。
3. 文种功能必须成立；请示的请批、编者按标识、正式通知或函的办理关系不能为了“去套话”被删除。
4. 单个正式连接词不判机械化。只有固定开头、承启、总结、尾语或段落骨架成簇出现且没有功能贡献，才判同质化。
5. 统计跨稿重复只作线索：精确惯用语、标题序列和段落骨架重复须结合题面和文种解释，不用词频自动决定胜负。
6. 直接使用成本分为0—4；候选不得以生硬省略、口语化或破坏正式性换取低词频。

## 准入

- 24对中至少20对技术有效，且每个 provider 至少6对。
- B 的候选独有事实、状态、用户结构或文种硬失败为0。
- 4个自定义结构反控全部保留用户结构；正式请示指定尾语反控必须保留。
- SOL max 在至少三种文体中确认 B 减少无功能的套话簇或固定骨架，且没有相应正式性回退；若 A 本身未出现可复现机械化，则结论为“不改产品”，不为制造差异强行精简。
- A/B 总体胜负只作质量旁证，不以机械词频或“候选必须总胜”取代上述功能门。

## 停止与后续

出现模型路由错误、隔离失败、题面或原型哈希漂移时停止整批并记录，不重试。只有真实写稿显示可复现收益后，才把原型收敛为最小 canonical diff，并仅补镜像一致性、可达性、quick validate 与 `git diff --check`。
