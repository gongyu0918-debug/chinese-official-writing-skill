# 事务文体功能和结构（R2研究原型）

本页用于确认文种功能和选择结构，不提供统一措辞模板。

## 使用顺序

- 用户给定的标题、提纲、段落顺序、单段写法、语气和结尾优先。
- 先完成文种应承担的办理功能，再按材料自身的时间、事项、主体、问题或受众关系组织正文。
- 没有统一的开头、标题组、总结段或结尾。信息较少时紧凑成段；信息较多时才按真实层次设标题。
- 惯用语只在它能直接表明来文关系、请批事项、发布性质或回复关系时使用；正文已经自然衔接和结束时不另加。
- 所有结构只能组织已给事实，不新增主体、日期、数字、程序、承诺、结果、评价或充分性自证。

## 文体功能和可选结构轴

| 文体 | 核心功能 | 可按材料选择的结构轴 |
| --- | --- | --- |
| 计划 | 明确执行期、任务、主体和节点 | 时间、任务、责任 |
| 汇报 | 说明事实、进展、问题和已有下一步 | 事项、阶段、问题 |
| 调查报告 | 说明范围、数据、发现和已有处置 | 对象与方法、发现、处置 |
| 讲话稿 | 体现称谓、场合、事实和期望 | 讲话目的、事项、要求 |
| 演讲词 | 体现演讲人、主题、事实和观点 | 现场交流、经历概括、观点 |
| 答复 | 回应意见、建议或询问 | 核心回应、事实、安排 |
| 责任书 | 明确各方责任、共同事项和要求 | 责任主体、工作环节 |
| 公开信 | 面向对象说明背景、事项和配合要求 | 受众关切、事项、呼吁 |
| 倡议书 | 说明缘由并提出可执行倡议 | 缘由、行动事项 |
| 建议信 | 以事实和问题提出具体建议 | 问题、依据、建议 |
| 新闻发布稿 | 发布核心事实、处置进展和当前状态 | 新闻价值、时间进程 |
| 总结 | 回顾周期工作、问题和已有下一步 | 业务板块、时间、问题 |
| 情况反映 | 说明对象、数据、问题和当前处置 | 事实、问题、处置 |
| 情况综合 | 综合来源、分类、共性差异和状态 | 分类、差异、研究状态 |
| 编者按 | 显示编者身份并说明编发目的 | 编发对象、目的、下文 |
| 新闻 | 报道已发生事实和当前进展 | 标题、导语、主体 |
| 短评 | 基于事实提出判断并展开论点 | 事实、观点、论证 |
| 讲解稿 | 面向受众按顺序说明对象 | 空间、路线、主题 |
| 宣传手册 | 便于查阅地说明要求、方法和渠道 | 事项、操作、渠道 |
| 宣传材料 | 说明对象、事项、参与方式和边界 | 受众行动路径 |

## 文种标识

- 实际请示须写清请批事项，并保留用户指定的请批尾语。
- 实际答复、批复或复函须回应来文；没有来文事实不写“收悉”。
- 正式通知、通告、公告、报告或函可按需要使用相应收束，也可在事项完整后自然结束。
- 编者按保留“编者按”或用户模板中的同类标识。
- 新闻、短评、总结、讲解稿、宣传材料一般按内容自然结束，不套另一文种的尾语。

## 交付检查

- 文种功能是否成立，用户结构是否保留。
- 标题和段落是否来自本题信息层次，而非通用骨架。
- 开头、承接和结尾是否各有实际作用；同一功能是否重复。
- 是否为了显得完整而补出材料没有的评价、口号、保证、后续行动或自证。
