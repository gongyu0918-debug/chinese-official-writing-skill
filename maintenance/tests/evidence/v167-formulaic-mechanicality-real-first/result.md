# WR-005 常用语机械化真实写稿结果

日期：2026-08-16

固定基线：`v1.6.6^{commit}=b49da7f2a5a8ac2327252d29efd66f1d54ccbc35`

结论：**HOLD，不修改 canonical 产品。** 当前常用语叶确有固定开头反复出现的同质化信号，但两版“结构优先、惯用语稀疏可选”原型均未形成稳定质量改进。简单删减词表或增加反机械说明，会把问题转成篇幅不足、空泛开合、同义复述或事实外扩，不能据此上线。

## 判断边界

- 单个“现将”“综上所述”“特此通知”等在对应文种中可能承担真实接引、归纳或办理功能，不按词面判机械化。
- 只有固定开头、承启、总结、结尾或段落骨架跨稿成簇复现，且没有任务功能时，才计同质化风险。
- 用户给定结构、指定尾语、材料逻辑和文种功能优先于通用用语表。
- 目标是避免千篇一律，不是把正式表达改成口号、白话填充或统一的“反套话模板”。

官方与社区用法核验见 [`official-and-community-research.md`](official-and-community-research.md)。现行官方样本同时存在正式接引/尾语与自然开合两种合格写法；社区项目可借鉴“必备、常见、条件项”分层思路，不能复制其模板或固定话术。

## R1：完整稀疏化原型

矩阵为24题×A/B，共48次真实调用。三条路线分别为 `opencode-go/deepseek-v4-flash`、`ollama-cloud/deepseek-v4-flash:0731`、`alibaba-token-plan-2/deepseek-v4-flash-0731`，均为 max、1200秒、0 retry、每臂隔离。

- 48/48调用完成，44臂技术有效，20对进入匿名评审。
- 4个 OpenCode Go 候选臂的上游流缺少终止信号，按预注册记无效且不重试；因此 OpenCode 仅4个有效对，未达到每家至少6对的准入门，R1只作诊断。
- 有效稿中，基线固定开头命中12次，候选5次；词面频率下降，但候选没有同时改善整体可用性。
- SOL max 解盲：候选11胜、基线7胜、难分2；候选事实硬失败6稿、基线4稿；机械化硬失败候选5稿、基线3稿；直接使用成本均值候选1.65、基线1.70。
- 诊断：长篇反机械说明减少了部分固定开头，却诱发口号、空泛前后段、同义复述和充分性自证，不能采纳。

## R2：仅保留文种功能与结构轴

R2 删除 R1 的长篇反机械说明，只保留文种功能、结构轴和少量必要标识。固定12题×A/B，共24次真实调用，执行条件与 R1 相同。

- 24/24技术有效，12/12对进入 SOL max 匿名评审；三家 provider 均无无效臂。
- 基线固定开头命中6次，候选4次；两边均各有1个公式化簇。
- 解盲为基线6胜、候选4胜、难分2。
- 机械化分布完全相同：两边均为4 PASS、7 WARN、1 FAIL。
- 候选出现1个事实硬失败，并有1个状态 WARN、1个用户结构 WARN、1个文种 WARN；基线没有事实或状态硬失败。
- 直接使用成本均值为基线1.8333、候选1.6667，但不足以覆盖候选硬事实回退和总体胜负劣势。

## 产品决定与后续方向

1. v1.6.6 canonical 保持不变，不把 R1 或 R2 写入产品。
2. 已确认的产品要求是“避免所有稿件共享同一套开头、分层和尾句”，不是禁止正式常用语。
3. 后续只研究更小的结构拆分：默认入口提供文种功能和结构约束；具体惯用语作为按需查询材料，仅在用户要求格式、文种标识、开端、承启或尾语时读取。
4. 下一候选必须先用同一批真实稿证明：用户结构不退化、事实硬失败为0、机械化簇减少；通过后再改路由和镜像。不得继续靠增加反机械 prompt 压制问题。
