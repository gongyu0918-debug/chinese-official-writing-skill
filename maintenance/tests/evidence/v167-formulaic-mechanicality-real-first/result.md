# WR-005 常用语机械化真实写稿结果

日期：2026-08-17

固定基线：`v1.6.6^{commit}=b49da7f2a5a8ac2327252d29efd66f1d54ccbc35`

结论：**HOLD，不修改 canonical 产品。** 当前常用语叶确有固定开头反复出现的同质化信号，但两版“结构优先、惯用语稀疏可选”原型均未形成稳定质量改进。简单删减词表或增加反机械说明，会把问题转成篇幅不足、空泛开合、同义复述或事实外扩，不能据此上线。

## 判断边界

- 单个“现将”“综上所述”“特此通知”等在对应文种中可能承担真实接引、归纳或办理功能，不按词面判机械化。
- 只有固定开头、承启、总结、结尾或段落骨架跨稿成簇复现，且没有任务功能时，才计同质化风险。
- 用户给定结构、指定尾语、材料逻辑和文种功能优先于通用用语表。
- 目标是避免千篇一律，不是把正式表达改成口号、白话填充或统一的“反套话模板”。

官方与社区用法核验见 [`official-and-community-research.md`](official-and-community-research.md)。现行官方样本同时存在正式接引/尾语与自然开合两种合格写法；社区项目可借鉴“必备、常见、条件项”分层思路，不能复制其模板或固定话术。

## 产品决定与后续方向

1. v1.6.6 canonical 保持不变，不把 R1 或 R2 写入产品。
2. 已确认的产品要求是“避免所有稿件共享同一套开头、分层和尾句”，不是禁止正式常用语。
3. R3 已证明集中结构总表仍会形成补齐压力。下一候选撤掉该总表：普通任务沿用既有文种叶和事实边界；具体惯用语仅在用户要求格式、文种标识、开端、承启或尾语时读取。
