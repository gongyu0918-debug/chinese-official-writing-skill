关于版慎通智能审校系统新增公文AI写作功能的立项申请

一、立项必要性

（一）现有功能只覆盖审校环节，写稿能力存在缺口。版慎通智能审校系统已具备较为完善的图书审校功能，但尚不具备写稿能力，只能"审"不能"写"。用户起草稿件仍需借助其他工具，再回传系统审校，使用链条不完整；从用户反馈看，对公文写作功能的呼声持续较高。

（二）公文写作需求广泛且稳定。公文写作是机关、企业、事业单位的高频场景，覆盖请示、报告、通知、纪要、讲话稿等数十类文种，需求量大、专业性强。补足写稿能力后，版慎通可有效扩大用户群体，深入机关、企业、事业单位等垂直市场，并带动既有审校功能的连带使用。

（三）核心写作能力市场验证充分。拟引入的公文写作 Skill 已在 SkillHub 平台获得10.5万次下载，位列下载榜前50名，居公文写作领域第一；在 ClawHub 平台下载量约7000次，长期位居趋势榜前100名，同样居公文写作领域第一。其变体作品"公文写作智能体"获江西出版集团首届人工智能大赛专业组第三名。项目地址：https://skillhub.cn/skills/user_f3d82da7/chinese-official-writing。10.5万次下载量直接表明，用户对专业 AI 公文写作能力存在丰富且持续的需求。

同时，经代码指纹比对，市场上包括深知、WPS 等公司，均有复用本 Skill 部分模块开发公文写作系统的迹象，主要集中在去 AI 味模块、短稿路由模块、检测脚本模块。这一情况从侧面印证了本技术路线和关键模块的市场价值，也提示相关市场竞争正在加剧，宜尽早完成产品化布局。

二、建设内容与实施方案

（一）建设内容。在版慎通智能审校系统新增公文 AI 写作功能，主要包括 AI 智能写作、红头文件生成、格式修复、AI 味审校等能力，与既有图书审校功能衔接，形成从起草到审核的一体化能力。

（二）技术路线选型。项目候选形态包括完整 workflow agent 和社区广泛下载的 Skill 两种。综合考虑市场验证成熟度、与版慎通系统的集成适配成本和后续迭代速度，采用 Skill 方案更为适配。线上版本为开源方案，需开展闭源改造和版慎通适配；项目由个人项目转为公司项目，同步完成工程化改造。

（三）技术基础。该 Skill 已完成对各主流智能体运行框架的适配测试，由 references、scripts、hooks 三大模块构成。其中，references 是公文写作规则路由系统，按"从大到小、从粗到细"的方式组织写作，每次写稿热加载规则成本约1.4万 token，显著低于同类 Skill 约10万 token 的平均水平；hooks 在成稿后开展字数一致性、提纲与正文一致性、篇幅一致性、AI 味词汇、提示词遵循等检测，对可发现的错误自动返回模型重改，经三轮复核后最终成稿错误率约1%；scripts 负责显式 AI 味错误、Markdown 残留等清洗和格式校验。技术细节详见附件1。

三、开发方式与费用预算

（一）开发组织方式。项目采用 Codex 开发，开发循环为：需求登记为 OpenSpec 需求，在独立 worktree 预先修改，开展真实写稿 A/B 测试，通过后补充工程和胶水代码并入主分支；测试未通过时总结经验、另开 worktree，直至质量达标。该循环以真实写稿测试为质量门禁，迭代风险可控。

（二）资源消耗测算。按当前开发循环，日均消耗 token 约10亿，其中主力开发模型约7亿、测试模型约3亿，超出常规订阅额度，需采用高额度订阅方案。

（三）订阅方案。立项后前几个月，以每月1600元的 Codex Pro 20X 订阅作为主力开发工具，辅以适量 Alibaba Token Plan，用于 Qwen 系列模型的适配测试；待开发流程稳定后，可视需要转为每月900元的 Codex Pro 5X 订阅，降低月度支出。

四、预期效益

（一）补全"起草—审校"功能链条，将产品使用范围由"只审不写"扩展为"先写后审"，提升产品完整度和用户粘性。（二）依托市场验证充分的核心能力，缩短试错周期、降低开发成本，尽快形成差异化优势，为机关、企业、事业单位用户提供统一的公文写作与审校服务。

公文AI写作Skill技术方案说明

一、总体架构。本 Skill 由 references、scripts、hooks 三大模块构成，已完成对各主流 harness 的适配测试，可在不同智能体运行框架下稳定工作。

二、references 规则路由模块。该模块对公文和事务性稿件建立专门路由，规则来源于真实写稿实践和互联网成熟公文总结提炼；写作按"从大到小、从粗到细"组织，先定文种和骨架，再落到段落与论证，最后处理语言和格式。热加载机制使单次写稿只加载命中的规则子集，平均约14K token，远低于同类 Skill 约100K token 的平均水平，有效节约调用成本。

三、hooks 检测复核模块。成稿后自动检测字数一致性、提纲与正文一致性、篇幅一致性、AI 味词汇、提示词遵循等情况，重点覆盖"提纲—正文""成稿—交付"两个生命周期；对可发现的错误返回模型重改，经三轮 React 迭代后，最终成稿错误率约1%。

四、scripts 清洗校验模块。针对显式 AI 味错误、Markdown 残留等进行清洗，并对正文格式进行校验。

五、开发流程与资源消耗。开发循环为：idea 登记为 OpenSpec 需求；独立 worktree 预先修改；真实写稿 A/B 测试；通过后补充工程和胶水代码，并入 main；不通过则总结经验、另开 worktree。日均消耗 token 约10亿，其中主力开发模型7亿、测试模型3亿。对应订阅方案为 Codex Pro 20X（每月1600元）作为主力开发工具，辅以适量 Alibaba Token Plan 适配 Qwen 模型；稳定期可视需要转为 Codex Pro 5X（每月900元）。

六、闭源改造与适配。线上开源版本需完成闭源改造，并完成对版慎通系统的适配与联调。
