关于申请立项开发"版慎通智能审校系统——公文AI写作模块"的请示

公司领导：

为响应机关、企业、事业单位用户对公文智能写作的迫切需求，进一步提升版慎通智能审校系统的产品能力，扩宽用户群体和垂直市场覆盖面，经初步研究，拟立项开发"版慎通智能审校系统——公文AI写作模块"。现将立项必要性、市场需求、技术方案和所需经费请示如下。

一、立项必要性

（一）现有系统能力与用户需求存在明显错位。版慎通智能审校系统当前已具备较为完善的图书审校功能，覆盖正文差错检测、版式核查、敏感词筛查等环节，运行稳定并形成了一定的用户基础。但用户呼声集中反映"只能审不能写"是当前最大的产品短板，多数机关、企事业单位用户在日常工作中既需要审校，更需要起草、修改红头文件、工作总结、通知、报告、请示、函件等公文。当前功能无法覆盖用户的写稿需求，导致大量用户在使用审校功能后，仍需借助其他工具完成起草，跨工具切换和数据搬运成本较高，影响产品黏性和复购意愿。

（二）公文AI写作市场需求客观存在且空间较大。机关、企业、事业单位的日常运转对公文写作需求频次高、场景稳定，对智能化、规范化写作工具的接受度持续提升。在已有用户群体中，针对"添加写稿功能"的反馈持续增加；将审校能力与写作能力合并到同一系统，能够使用户在同一产品内完成从起草到审校的全流程，明显降低使用门槛，扩大产品的可用面。

（三）模块技术来源已经过大规模市场验证。承载该模块核心能力的"chinese-official-writing"技能，已在 skillhub 公文写作领域位列下载量第一，累计下载 10.5 万次，位居全站下载榜前 50；在 clawhub 累计下载 7000 次，长期保持趋势榜前 100 名次，同领域排名第一；其衍生项目"公文写作智能体"在江西出版集团首届AI大赛中获得专业组第三名。下载量、排名和获奖情况证明，公文 AI 写作在专业用户群体中具有稳定且持续的需求，相关技术方案经过不同社区、不同场景的反复验证，可直接作为本项目研发基础，避免重复造轮子。

（四）竞争环境要求加快产品布局。经指纹比对，目前市场上深知、WPS 等公司公开发布的公文写作产品中，存在复用本项目开源代码（尤其是去 AI 味模块、短稿路由模块、检测脚本模块）的迹象。如不加快自有产品的写稿能力建设，将面临功能同质化和先发优势流失的风险。

二、技术方案要点

项目形态采用与原 skill 长期线上验证一致的技术路线，即以 skill 方案为基础，结合版慎通智能审校系统进行闭源改造和工程适配，避免重新设计架构带来的不确定性和研发投入浪费。技术实现总体按 references、scripts、hooks 三个模块组织：

（一）references 模块为公文与事务性稿件的专用规则路由。该模块针对通知、通报、报告、请示、函、纪要、总结、调研、讲话稿等常见文种建立了从大到小、从粗到细的分级写作路由。规则来自真实写稿积累和互联网公开成熟公文样本的归纳总结，覆盖文种判定、要素抽取、段落组织和语言润色等关键环节。该模块采用热加载方式运行，单次写稿平均占用 14K Token 左右，远低于同类 SKILL 平均 100K Token 的水平，可在保证成稿质量的前提下有效控制模型调用成本。

（二）hooks 模块为成稿-交付两段生命周期提供一致性校验。该模块覆盖提纲与正文一致性、字数一致性、篇幅一致性、AI 味词汇和 prompt 遵循度等检测项，对 Agent 自动发现的成稿错误返回模型进行重改，经实测三轮 ReAct 流程后，最终成稿错误率约为 1%。hooks 不直接干预 references 的写作过程，定位为成稿质量门禁。

（三）scripts 模块为末端清洗与格式校验。该模块针对显式 AI 味词汇、Markdown 残留、版式偏差等进行最终清洗和校验，作为交付前的最后一道把关。

考虑到技术细节较多且与开发执行直接相关，技术模块的详细设计、调用关系、热加载策略、闭源改造方案与版慎通系统适配方案，作为附件《"公文AI写作模块"技术方案》随文报送，便于在审批过程中同步审阅。

三、所需经费

项目经费主要用于支撑主力开发模型和适配模型所需的 Token 订阅。

（一）主力开发模型。结合当前 CODEX 开发模式下"先独立 worktree 预修改、再真实写稿 A/B 测试、通过后补工程和胶水、最后并入 main"的开发循环，团队日均消耗约 10 亿 Token，其中主力开发模型约 7 亿、测试模型约 3 亿。在项目前几个月需保持高频迭代，参照当前市场行情，按 Codex Pro 20X 订阅测算，主力开发工具费用约 1600 元/月。

（二）适配模型。为满足对 Qwen 系列模型的适配测试需要，按 Alibaba Token Plan 提供必要的调用额度，具体额度按适配版本数和回归测试频次确定。

（三）后续调整。后续如开发节奏趋于稳定，可由 Codex Pro 20X 转为 Codex Pro 5X 订阅，对应主力开发工具费用降至约 900 元/月。经费调整按实际开发进度另行报批。

以上三项费用合计构成项目运行所需的模型开发费用，按月度列入项目预算。

四、其他事项

项目立项后，技术来源由原线上开源 skill 切换为内部闭源维护，相关代码纳入版慎通智能审校系统代码库统一管理。原 skill 在社区的下载、版本迭代和维护工作另行安排，与本项目并行推进。
