**关于申请"版慎通智能审校系统公文 AI 写作功能"立项的请示**

公司领导：

为对接机关、企事业单位和学校用户在专业公文写作方面的持续需求，巩固版慎通智能审校系统在垂直市场的领先地位，公司拟在现有图书审校功能基础上，新增公文 AI 写作能力，形成"审校 + 写作"一体化服务。现就立项有关事项请示如下。

**一、立项缘由**

（一）现有产品功能侧重审校，无法覆盖写作环节。当前版慎通智能审校系统以图书审校为主，错误识别与格式校验能力较为完善，但不具备公文起草能力。用户长期反映希望在同一平台完成从起草到审校的全流程操作，公司须尽快补齐写作这一关键环节。

（二）用户对专业公文 AI 写作的需求具有规模性。公司拟引入的公文写作 Skill 自上线以来，在 skillhub 平台累计下载 10.5 万次，位列平台下载榜前 50 名、公文写作领域第 1 名；在 clawhub 平台累计下载 7000 次，长期保持趋势榜前 100 名、公文写作领域第 1 名。该 Skill 的变体作品——公文写作智能体项目——曾获江西出版集团首届 AI 大赛专业组第 3 名。上述数据足以说明用户在专业 AI 公文写作方向上存在稳定且规模化的需求。

（三）该 Skill 的市场复用情况反向印证其技术成熟度。经指纹检测，包括深知、WPS 等在内的多家公司在其公文写作系统中复用该 Skill 的代码，重点集中在去 AI 味模块、短稿路由模块和检测脚本模块。这表明现有技术路径已经过同类产品验证，具备改造为公司自有能力的可行性。

**二、项目方案**

（一）形式选择：采用 Skill 方案而非完整 Workflow Agent。结合公文写作垂直市场的实际使用场景与现有系统的架构特点，Skill 形态更便于与版慎通既有审校工作流衔接，用户接入成本低、迭代速度快。公司不再另行建设独立的写作 Agent 平台。

（二）改造路径。该 Skill 当前以开源方式提供，需进行闭源改造并完成对版慎通系统的适配，包括但不限于：代码许可证切换、与审校模块的接口对接、用户数据隔离机制、调用链路埋点与计费埋点。

（三）开发方式与流程。开发采用 CODEX 工具链。鉴于该项目原为个人项目，本次转为公司项目，须按公司项目规范完成代码归属、知识产权、依赖梳理和安全合规改造。单次改动遵循以下流程：想法登记为 openspec 需求 → 在独立 worktree 预先修改 → 真实写稿 A/B 测试 → 通过后补工程与胶水代码 → 并入 main；未通过则总结经验并开新 worktree 继续迭代。

**三、技术基础（详细方案见附件）**

本项目所依托的公文写作 Skill 已形成成熟的规则路由与微调体系，主要由 references、scripts、hooks三大模块构成。

（一）references 模块。围绕公文与事务性稿件建立了专门的规则路由，按文种、行文关系、办理要素和论证链条组织写作路径。规则来源包括真实写稿案例、互联网公开公文和团队整理的成熟写法，整体采用"从大到小、从粗到细"的逐级收敛方式。平均每次写稿热加载规则约 14K token，显著低于同类 Skill 约 100K token 的平均水平，能够在保证成稿质量的前提下控制调用成本。

（二）hooks 模块。用于成稿后的微调与检测，重点覆盖字数一致性、提纲与正文一致性、篇幅一致性、AI味词汇、prompt 遵循等维度，关注"提纲—正文"和"成稿—交付"两个生命周期。对 Agent 能识别的错误，hook 会将稿件回退模型重改；在三轮 ReAct 流程下，最终成稿错误率控制在 1% 左右。

（三）scripts 模块。用于显式 AI 味清洗、Markdown 残留去除和格式校验，作为 references 与 hooks 之外的兜底保障。

技术细节、模块接口与质量指标详见附件《公文 AI 写作功能技术方案说明》。

**四、资源测算与开发费用**

（一）日常 token消耗。按当前 Skill 的开发节奏，项目日均 token 消耗约 10 亿，其中主力开发模型约 7 亿、测试模型约 3 亿。后续将结合模型升级和 prompt 优化动态校准。

（二）主力开发工具订阅。项目启动后前几个月按1600 元/月订阅 CODEX Pro 20X 作为主力开发工具；主力开发进入稳态后，可视需要切换为 900 元/月订阅的 CODEX Pro 5X。

（三）模型适配。考虑到用户环境中 Qwen 系列模型的存量使用情况，项目将使用适量 Alibaba Token Plan 进行 Qwen 模型适配，确保公司在主流国产模型上具备一致的写作能力。

（四）费用性质。以上费用为开发工具订阅与模型适配支出，不涉及服务器租赁或机房建设；后续如需新增算力租赁或模型 API 调用，将按公司采购程序另行申请。

**五、风险控制与下一步安排**

（一）合规风险。闭源改造涉及第三方代码清理与许可证切换，须在改造前完成代码审计与权属确认，确保公司知识产权清晰。

（二）数据安全。写作环节涉及用户稿件，须建立数据隔离、脱敏和日志审计机制，防止稿件内容外泄或越权调用。

（三）质量稳定。Skill 在三轮 ReAct 下最终错误率约 1%，改造后须在版慎通系统内重新开展 A/B 测试，确认接入审校流程后未引入新的偏差。

（四）下一步安排。如本次立项获批，计划于本月内启动闭源改造与接口适配工作，同步推进 Qwen 模型适配与版慎通审校模块联调测试，并在首批功能上线前组织面向机关、企事业单位的内测验证。
