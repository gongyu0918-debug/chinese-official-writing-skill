# 关于版慎通智能审校系统新增"公文AI写作"功能的立项申请

公司领导：

为落实公司产品线向"写审一体"延伸的发展部署，补齐版慎通智能审校系统当前"只审不写"的功能短板，巩固并扩大在机关、企事业单位垂直市场的服务覆盖，项目组就新增"公文AI写作"功能（含AI智能写作、红头文件生成、格式修复、AI味审校四项子能力）的立项事项请示如下。

## 一、立项必要性

**（一）当前系统功能与用户需求之间存在明显缺口。**

版慎通智能审校系统现有功能围绕图书审校环节建设，规则库、术语库和审校流程相对完善，已在出版、编辑审校场景形成稳定服务能力。但用户在系统使用过程中提出大量写稿诉求，系统目前只能对既有稿件进行审校，无法直接产出符合规范的公文、事务性材料或新闻稿件。这一缺口导致用户在工作场景中需要在审校系统与其他写稿工具之间反复切换，影响服务连贯性和用户体验。

**（二）写稿需求客观存在且覆盖面广。**

机关、企事业单位在学校教育、新闻出版、行政办公、党建群团、行业研究等场景中，存在大量通知、请示、报告、函、纪要、方案、总结、调研报告、新闻通稿等正式材料的撰写需求。这类材料具有较强的格式规范和文种边界要求，用户普遍反映在文种判断、要素齐备、语言规范、去AI味等方面存在明显负担，需要专业工具支撑。市场调研显示，包括深知、WPS在内的同类产品已陆续上线或强化写稿功能，垂直市场对专业AI公文写稿工具的接受度持续上升。

**（三）市场已对相关能力作出验证。**

项目组基于公司既有技术积累，已在SkillHub和ClawHub两个开源社区发布"中文公文写作"Skill。该Skill在SkillHub上累计下载10.5万次，位列平台下载榜前50名，居公文写作类目第一位；在ClawHub上累计下载7000次，长期位居平台趋势榜前100名，居公文写作类目第一位。其变体作品"公文写作智能体"获得江西出版集团首届AI大赛专业组第三名。上述市场数据表明，专业用户在公文写作领域存在持续、规模化的真实需求。经指纹检测，包括深知、WPS在内的多家公司产品存在复用该项目代码的现象，尤其是"去AI味模块""短稿路由模块""检测脚本模块"，从侧面反映了该Skill在写稿规则路由和质量控制方面的技术价值。

**（四）补齐写稿能力有助于扩大用户基础。**

版慎通智能审校系统在出版、编辑审校领域已积累一定用户基础。新增公文AI写作功能后，可在不增加获客成本的前提下，将现有审校用户延伸为写审一体用户，并向机关、企业、事业单位等更广泛的垂直市场扩展，对用户规模和经营效益均具有直接拉动作用。

## 二、技术方案概要

项目方案拟采用与社区Skill一致的技术路线，并结合版慎通智能审校系统的产品形态进行闭源改造和深度适配，技术细节见附件《"公文AI写作"功能技术方案》。方案要点如下：

**（一）总体架构。**

项目采用"规则路由+质量闭环+脚本兜底"的三段式架构，分为三大模块：

1. **references模块（规则路由）**：针对公文、事务性稿件和新闻稿件进行专门路由，规则来源于真实写稿样本和互联网成熟公文总结，按从大到小、从粗到细的方式组织，形成一套成熟且细粒度的公文写作规则路由系统。该模块平均每次写稿热加载规则约14K Token，远低于同类Skill平均100K Token的水平，能够显著节约推理成本。

2. **hooks模块（质量闭环）**：在references模块完成成稿后，由hooks模块对字数一致性、提纲与正文一致性、篇幅一致性、AI味词汇、提示词遵循度等进行微调和检测，重点覆盖"提纲—正文""成稿—交付"两个生命周期。对Agent可识别的错误，自动返回模型进行重写；在三轮ReAct循环下，最终成稿错误率约控制在1%左右。

3. **scripts模块（脚本兜底）**：针对显式AI味、Markdown残留等进行清洗，并对格式进行校验，作为references和hooks之后的最后一道质量关。

**（二）适配与改造。**

由于线上Skill为开源方案，本项目需进行以下工作：一是对Skill代码进行闭源改造，避免技术资产外泄；二是针对版慎通智能审校系统的用户体系、审校工作流、稿件类型进行深度适配，使其能够嵌入现有产品形态；三是建立公司内部的版本管理和发布流程，与原社区版本解耦。

**（三）开发与交付流程。**

项目采用与社区一致的LOOP开发机制：先形成需求想法，登记为OpenSpec需求，进入独立worktree预先修改，以真实写稿任务进行A/B测试；通过后补齐工程代码和胶水逻辑并入主干；不通过则总结经验后开新的worktree。该流程已在社区项目中经过长期验证，能够在保证代码质量的前提下控制开发节奏。

## 三、研发费用预算

**（一）费用构成。**

项目开发主要采用CODEX作为主力开发工具，辅以Alibaba Token Plan支持Qwen等模型的适配与验证。经测算，项目每日Token消耗约10亿，其中主力开发模型消耗约7亿，测试模型消耗约3亿。

**（二）月度订阅费用。**

根据开发进度，前几个月项目组需订阅CODEX Pro 20X作为主力开发工具，月度费用1600元，用于承担主力开发模型的调用；同步使用适量Alibaba Token Plan，覆盖Qwen等模型的适配、回归和对比测试。后续视开发进度和资源消耗情况，可由CODEX Pro 20X转为CODEX Pro 5X，月度费用约900元，预计可在开发进入稳定阶段后显著降低主力开发成本。

**（三）费用性质说明。**

上述费用为公司内部研发支出，不涉及对外采购或客户收费，可纳入产品研发预算专项列支。

## 四、预期成果与风险控制

**（一）预期成果。**

1. 在版慎通智能审校系统中新增AI智能写作、红头文件生成、格式修复、AI味审校四项核心功能。
2. 形成可复用的公文写作规则路由库和质量控制机制，与现有审校功能形成"写审一体"闭环。
3. 提升公司在机关、企业、事业单位等垂直市场的服务能力，扩大用户基础。

**（二）主要风险及控制。**

1. **闭源改造风险**：原Skill为开源项目，闭源改造涉及代码清理、依赖梳理和合规审查。控制措施：制定闭源改造清单，分阶段完成代码替换和依赖收敛。
2. **模型适配风险**：不同模型在公文写作能力上存在差异，需充分适配和验证。控制措施：保留多模型并行测试通道，以A/B测试结果作为模型选型依据。
3. **质量稳定性风险**：公文写作对格式、文种、要素的规范性要求高，错误可能影响用户对产品的信任。控制措施：保留hooks和scripts双重质量控制机制，并在产品中向用户展示关键质量指标。

## 五、请批事项

综上，为补齐版慎通智能审校系统写稿功能短板，巩固公司在公文AI写作领域的技术先发优势，扩大垂直市场覆盖，项目组申请批准本立项，并按以下事项执行：

1. 批准"公文AI写作"功能立项，纳入公司产品研发计划；
2. 批准按月订阅CODEX Pro 20X（1600元/月）及适量Alibaba Token Plan作为研发资源，列入研发预算；
3. 授权项目组开展Skill闭源改造及对版慎通智能审校系统的适配工作。

以上申请，恳请批准。
