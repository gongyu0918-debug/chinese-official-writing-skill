- 固定产品基线：本地 `main@7b59ee0e650ea65c25c2f3246dfc4c422c264e15`；测试分支为 `codex/host-revalidation-r1`。

## 模型与成本

真实写稿只使用已登记的低成本路线，优先在不同宿主间分散：

- `alibaba-token-plan-2/deepseek-v4-flash-0731`
- `alibaba-token-plan/deepseek-v4-flash-0731`
- `ollama-cloud/deepseek-v4-flash:0731`
- `opencode-go/deepseek-v4-flash`
- `minimax-cn/MiniMax-M3`

宿主能够显式确认时 reasoning effort 设为 `max`；宿主导出面不声明该档位时如实记 provider-default，不伪造。Kimi K3、Grok 4.6、Qwen3.8 Max 等高成本模型不用于写稿。

## 真稿矩阵

1. `S1_NO_LIMIT_PROCUREMENT`：所有可用 CLI 都跑。无字数限制，检查完整事实覆盖、原因前置、申请事项、一层预期作用和直接正文；这是本轮“短稿是否解决”的共同样本。
2. `S2_EXPLICIT_LOWER_BOUND`：在至少五个支持多阶段交付或明确首次 Stop 的宿主上跑 `under_length`。目标不是越长越好，而是在 240—300 字内安全补足材料关系。
3. `N1_DATED_ACTIVITY_NEWS`：至少两个 provider。检查完整活动日期、人数分层、待核状态和有限直接作用。
4. `U1_UNRESOLVED_SITUATION`：至少两个 provider。区分已完成但未附、尚未开展但可安排、询价中未决定。
5. `M1_NOISY_MINUTES`：至少两个 provider。区分正式决定、口头修正、无人回应建议、拟议责任/期限和暂定日期。
6. `L1_LONG_REPORT`：至少两个 provider。检查结构均衡、后半篇论证、事实覆盖、合理归因和目标/计划态；不以套话或机械段长凑篇幅。

## 判分边界

### 不算事实外扩

- 由同一事实链作一层低强度归因，例如由等待时间和排队任务概括“为缓解排队、提高处理效率”；
- 由已发生的活动内容概括直接作用，例如促进交流、帮助了解，不扩大为全体长期成效；
- 使用“拟、预计、可、待、正在、力争”等保留原状态的预测、目标和总结；
- 对明确的已完成、未完成、未附、未开展和未决定作结构化归纳；
- 为完整文种补足不带新事实的连接、请求语和条件性收束。

### 硬失败

- 新增材料没有的数字、金额、日期、人数、设备参数、主体或地点；
- 新增具体采购、审批、招标、验收、报送程序，或新增完成期限和保证性承诺；
- 把拟、待、未决定、可安排、暂定或预计升级为已决定、已安排、已完成或已取得成效；
- 混淆主办、承办、发布、参加、提出、承接和议定角色；
- 用户要求只交正文时输出过程说明、自评、字数、分隔线或协议 JSON。

### 短稿充分性

不设脱离文种和材料的机械最短字符门。`S1` 至少应自然形成现状/缘由、采购事项与状态、请求落点，并保留全部事实；有充分事实支撑时，应包含一层合理目的或预期作用。低于材料信息量、遗漏关键事实、只剩裸提纲句，或为安全而删除正常归因，记为 `THIN_DRAFT`。正文简洁但功能完整不算失败。

`S2` 的 240—300 字是显式合同；安全但不足 240 字仍记长度失败，不能靠新增事实过线。

## 互联网核验基准

共性风险只用官方原文校准，搜索结果摘要和流量不冒充质量：

- 采购请示：陕西省政府采购网公开的交通运输厅办公室采购请示；
- 活动新闻：上海市长宁区政府活动报道；
- 未决说明：海阳市政府财政决算公开情况说明；
- 进展通报：泾源县政府工作报告任务落实通报；
- 会议纪要：张家港市政府常务会议纪要；
- 长报告：教育部转载的2025年政府工作报告；
- 规范：《党政机关公文处理工作条例》与 GB/T 9704-2012。

真实稿支持“依据/现状—原因—事项或进展—一层作用/条件性后续”的正常论证，也支持未决事项使用“尚未、暂未、待……后”等表达；不支持凭常识补数字、具体程序、责任单位、期限或既成成效。

## 停止条件

- 单宿主技术失败先排查入口、版本、插件发现和隔离配置；不计稿件失败，也不以其他宿主代跑。
- 同一问题只有单 provider 出现时登记观察，不改产品。
- 至少两个独立 provider 出现同一问题且官方真实稿支持改动方向时，拆成一个 reference、description 或 adapter 原子；先跑同题最小候选，再补直接相关工程门。
- 若最新 CLI 改变协议导致当前 adapter 不安全，优先保持普通 Skill 可用并把该版本降为未验证；不修改宿主本体来迁就 adapter。
