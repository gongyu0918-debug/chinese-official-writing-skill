# `SHORT-NATURAL-REFERENCE-R1 / UL-006-R1` 预登记

> 状态注：本文保留 R1 开始前的固定100字试验假设，不是当前产品规则。后续 `UL-006-R1` 真实写后原型已将其改为“可分离事实材料 + 是否仅转述 + 文种功能”的动态判断；用户显式上限和其他旁路条件仍优先。

## 固定点与问题

- 基线：`main@c60e3ffaa12af012bf2a3910081ae70244a87a21`。
- 产品原子 A：普通起草在用户没有要求压缩、极短、逐字保留或给出不高于100字的上限时，不得把事实材料只换词或换序后更短地交回。正文应至少长于或等于提示词中可可靠分离的事实材料，并按文种完成实际功能；不使用统一的“原因—事项—作用—结论”模板。
- 产品原子 B：可选 `under_length` Hook 在普通正式起草未给明确下限时，以正文100字为绝对底线，再按文种使用更高的保守兜底值。用户给出不高于100字或更低的上限、要求一句话/极短/逐字回复、只审不改、纯格式或关闭 Hook 时旁路。
- 两个原子分开验证：先做普通 reference 真实起草，再对真实低于100字 D0 做 Hook 同稿修订，不用门禁成功替代普通稿件质量。

## 基线污染修正

## 基线后阈值校准（不改写预登记事实）

上表是运行基线前登记的初值。50 次基线输出完成后，按真实稿件而不是按预想结构校准后续候选值：情况说明由 140 调为 120，会议纪要由 160 调为 120，活动新闻由 180 调为 150；100 字绝对底线和大型文体 300 字观察值不变。原因如下：

- 情况说明 5 份有效正文为 102—274 字，其中 114 字、118 字稿已完整保留全部状态，只是缺少阶段归纳；140 会把安全、可用的简短说明误判为必须扩写。
- 会议纪要 5 份有效正文为 118—216 字，118 字稿已保留决定、建议未决和暂定日期。160 会把文种成立的短纪要误判为异常；120 只捕捉最薄边缘。
- 活动新闻 5 份有效正文为 150—286 字，150 字稿已经有导语、环节、完成/补测状态和一层直接作用，因此 150 是更合适的异常底线。
- 突发事故通报 4 份有效正文为 98—105 字，均完整承载事件、人员、现场处置、道路状态、原因待查和排查进行态，且均未补造事故原因。该组保持 100 字，只允许用题名、时间承接、处置归组或现状收束补足极小差额，不得为过线强写原因、必要性、整改或责任。

校准后的当前矩阵为 `100 / 120 / 120 / 150 / 300`。这是基于已观测 D0 收窄误伤面的工程校准，不是把结果反写成原始预登记，也不代表大型文体 300 字已经取得真实 D1 证据。

旧 `WR-013d/WR-018-R2` 和 `SHORT-CURRENT-CLI-R1` 提示词直接写入了“允许合理推断”、可写影响及所需结构，且采购材料较丰富。这些结果只证明模型可执行显式指令，不证明普通 Skill 会在自然用户请求下稳定展开。本轮所有目标题不出现“允许推断”、建议结构、预期影响或禁写项清单。

## 真实写稿矩阵

- `T1_SPARSE_COMPUTE_PURCHASE`：稀疏算力采购申请，不给金额、配置、供应商和方式。
- `T2_SPARSE_OFFICE_PURCHASE`：普通办公打印设备申请，只给任务量与拟购数量。
- `T3_REPAIR_REQUEST`：已有尝试但问题仍在的维修申请。
- `T4_ACTIVITY_NEWS`：完整日期、参与范围和局部完成状态的活动新闻。
- `T5_UNRESOLVED_SITUATION`：已完成、已形成但未附、未开展、进行中和未决并存的情况说明。
- `T6_INCIDENT_BULLETIN`：事故时间、地点、人员状态、处置和原因待查并存的突发通报；不要求原因或必要性。
- `T7_ACTION_NOTICE`：只按对象、动作、时间、材料和渠道形成办理通知；不要求影响或结论。
- `T8_UNRESOLVED_MINUTES`：会议基本信息、正式决定、无人回应建议和暂定日期并存的纪要；不补责任期限。
- `C1_EXPLICIT_COMPRESSION`：用户明确要求100—120字压缩，用于保护用户范围。
- `C2_EXPLICIT_SUB100_MAX`：用户明确要求不超过80字，用于证明100字和文种隐式下限旁路。

五条低成本路线均使用 `max`：Alibaba Token Plan 2 / 1 DeepSeek V4 Flash 0731、Ollama Cloud DeepSeek V4 Flash 0731、OpenCode Go DeepSeek V4 Flash、MiniMax M3。

## 裁决

### 目标改善

- 普通起草的有效正文低于对应事实材料，记目标失败；提示词中的任务说明、格式和禁写项不纳入这个长度对比。
- 只把事实换序、换词或压成一句，且没有完成该文种实际需要的功能，记功能性过薄。采购/维修稿检查必要性与事项，效果句、条件性结论和请批尾语均不作为扩写达标项；通知检查对象、动作、时间、材料/渠道；活动新闻检查事件事实与一层即时作用；说明检查阶段归纳；纪要检查状态强度；突发通报检查事件、处置和当前状态。未要求的原因、影响、结论、责任或期限不得反向变成必填项。
- 候选必须在至少两家独立 provider 上改善基线已观测的目标失败，且有效候选不得低于事实材料。

### 准入保护

- 基于已给事实和对象通常功能的一层原因、必要性、直接作用、真实归纳、条件结论和低强度影响均不记外扩；是否需要写由文种决定。
- 只有新增数字、金额、配置、人员、具体用途、程序、责任、期限、决定、承诺、新事件或把预期写成既成效果，才记事实硬回退。
- 候选独有的数字/状态遗漏、具体事实新增、文种错误、用户上限破坏或未交直接正文才阻断。两臂共有的模型风格问题不得冒充候选回退。

### Hook 原子

- 先从基线或候选中选择真实低于对应文种下限的 D0；没有真实 D0 的层级不先造对应工程值。
- 同一 D0 对比 Hook 关闭/开启和最终选择。成功需要最终正文达到对应隐式下限、解决功能性过薄且无上述硬回退；安全 D0 回退只算安全，不算目标成功。

## 停止条件

- reference 候选经两次最小化仍在不同 provider 间轮流出现候选独有硬回退，终止该措辞，不通过放宽硬事实门强行接入。
- Hook 无法稳定区分普通起草与压缩/精确回复/只审/纯格式，或真实 D1 只能依靠新具体事实达到100字，不接入当前 Hook。
