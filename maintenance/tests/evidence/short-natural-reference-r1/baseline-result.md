## 文种功能裁决

基线不支持统一要求每篇都写“原因/必要性、事项、作用、结论”。当前真实稿只支持按文种检查：

- 采购/维修稿：交代已给现状或可由现状直接支持的必要性，写明拟办事项；效果句、条件性结论和请批尾语均不作为扩写达标项，请批尾语只按用户指定文种和行文关系另行判断。
- 办理通知：对象、动作、时间、内容和渠道完整；可用动作直接支持的一层目的承接，但不补执行链、考核或责任。
- 活动新闻：事件事实、主要环节和完成/未完成状态之后，可写由现场动作直接支持的一层即时作用；不得把局部完成扩大为全体成效。
- 情况说明：对多项事实按阶段和当前状态归组；不强迫解释原因，也不续造“另行说明/通报”等承诺。
- 会议纪要：区分决定、建议、无人回应和暂定状态；责任和期限只在材料明示时写。
- 突发事故通报：事件、人员状态、现场处置和当前调查/排查状态成立即可；原因未知时不得为了篇幅补原因、必要性、整改、责任或影响。

因此，基于事实和常识的一层原因、直接作用、状态归纳或条件性结论不是硬失败；新增具体数字、用途、程序、责任、期限、承诺、新事件，或把预期效果写成既成事实才是硬回退。

## 阈值校准与后续原子

运行前登记的 `100/140/160/180/300` 对说明、纪要和活动新闻偏高。后续候选改用：

| 类别 | 校准值 | 适用边界 |
| --- | ---: | --- |
| 采购/维修申请、通知、函复、快讯、突发事故通报、未识别短事务 | 100 | 用户设定不高于100字上限时旁路；事故不强迫原因 |
| 情况说明/情况报告 | 120 | 只要求事实分层和状态归纳，不强迫下一步 |
| 会议纪要 | 120 | 只保护议题与决定/建议/未决强度 |
| 活动新闻/报道/通稿 | 150 | 快讯仍按100；直接作用必须有活动动作支撑 |
| 大型报告、总结、讲话、调研、方案等 | 300 | 仍只是待验证观察值，本基线没有证明其 D1 可用 |

普通 reference 候选先处理自然请求下的换词复述和文种功能，不写统一结构公式。Hook 候选只处理上述真实 D0；显式压缩和不高于100字控制必须旁路。
