# WR-024 R2 最小候选补充预登记

R2 保留官方研究结论，但撤回 R1 的宽泛合并句，改为三个可观察边界：

1. 请示通常先承载材料已有的缘由、依据、前序状态或事项直接用途，再明确请批事项；这些已经足以成立时，不另造必要性段。
2. 事实与常识只允许推一层可直接闭合的缘由、依据或用途，不继续推导具体用途链、工作流程或后续效果。
3. 缘由确实缺失且允许正文外提示时，只提示该实质缺口；不同时追加主送、署名、日期、工具运行或其他未问事项。

单项采购规则仍明确同时适用于请示和申请。除此之外不改 Hook、description、通用信息选择、其他文种、字数门或交付模式。

## R2 采用标准

- 同一 4 题 × 5 provider、`max`、每格一次、零质量重试；不得换题掩盖 R1 回退。
- Q1—Q3 至少保持材料事实、状态和一层合理缘由；不得新增候选可归因的具体用途链、程序、效果、数字、日期或批准状态。
- Q4 至少 3/5 只提示延期缘由或依据，0/5 用“因故”等泛称进入正文，且不得比 R1 增加无关缺项清单。
- “保障会议室正常使用”“卫生监督工作需要”“日常文件处理需要”等自然的一层推断不判失败；过程包装只作为交付形态问题记录，除非由候选新增且破坏正文可用性。
- 达标才同步镜像并进入工程门；不达标则恢复产品字节，状态记 `REJECTED/TERMINATED`，不留 `HOLD`。
