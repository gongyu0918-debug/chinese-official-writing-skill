## 原子收窄

R1 使用的负向枚举句虽然在目标词上 A/B 均5/5，但 A 提示本身点名禁止“拟安排”，不能证明 reference 归因；Ollama 还新增材料外后续经费安排，MiniMax 重复四组事实。该轮只作为安全性和副作用观察，详见 [`r2-amendment.md`](r2-amendment.md)。

R2 将产品增量缩为45字符的正向状态锚：

> “可安排、可开展”等能力或选项保持“可”；材料明确“拟、计划、将”等计划状态时保持原强度。

A 恢复 WR-017 原始提示，只禁止把“可安排”升级为“已安排”，不再在任务提示中出现“拟安排、拟开展”。因此模型是否自行保持“可”，由实际读取的 candidate reference 承担。

R2 B 的四个有效稿全部保留24份、7/3/4、9月18日、初步覆盖4项、会议室已预留、名单待定和方案尚待办公室审核；均使用“拟于”，没有降成单纯“可安排”，也没有升级为已实施或已完成。MiniMax 对字段口径作一层技术常识拆解，未增加主体、数字、计划、审核结论或成效，按用户要求不采用过严门禁，只记 WARN。

“为方案完善提供参考”“为分类处理提供基础”“为统一字段口径”等均是征集、分类或复核的直接目的/即时作用，没有写成已经取得的长期成效，按既有合理推断边界接受。

## 技术失败与停止

OpenCode B 两次都实际读取 Skill 和 `information-selection.md`，但没有形成最终正文；错误均为：

```text
stream disconnected before completion: Provider stream error: upstream stream ended without a terminal signal ([DONE] or finish_reason) — possible truncation
```

同 provider 的 A 有效，R1 同一 B 正向题也曾形成安全终稿，但最终 R2 不借旧稿冒充精确候选通过。按预注册只补一次后停止。该结果说明本轮有四家有效 B 质量证据和一家技术不可用，不构成稿件质量风险，也不再启动其他 harness。

## 产品决定

R2 解决 WR-017 暴露的“可→拟”目标风险，R1 的两个副作用在同题复测中消失，正向计划控制没有被压成“可”。将最终45字符状态锚同步 canonical 与四套普通镜像，不增加 Hook、状态表、审批模板或 description 文种枚举；当前只进入研究候选，不合入 `main`、不推送、不发布。共享修复只有以后进入公开 `main` 后，才按 `public-paid-sync.md` 同步付费分支。
