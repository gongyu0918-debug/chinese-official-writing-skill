# OC-003-R4 未决状态对象与谓语原子预注册

日期：2026-08-25。

## 目标

核对 `genre-checklist-feasibility-review.md` 中由合成题驱动的“尚未形成决定”专句能否改为通用规则：复核或改稿时按材料原有对象、谓语和状态强度恢复未决事项，不把未决状态另行概括为“不具备条件”，也不把合法的“不具备条件”机械删除。

本原子只修改一处可研复核叶，不修改入口、其他 reference、Hook、adapter、description 或版本。

## 固定比较

- Baseline：`main@65d85cc14983356a7469b8b3b95f4721c58ab34d`。
- Candidate：只把“尚未形成决定”专句改为按原对象、原谓语和状态强度恢复的通用句。
- 五个便宜写稿路线：OpenCode Go DeepSeek V4 Flash、Ollama DeepSeek V4 Flash 0731、Alibaba Token Plan 2 DeepSeek V4 Flash 0731、MiniMax M3、GPT-5.6 Luna。
- 每个 provider 对 Baseline/Candidate 各运行同一份五任务 prompt，共10次 Codex CLI 真实复核/改稿；reasoning effort 为 max，隔离用户级同名 Skill。

## 五个原子场景

1. 具体阶段与对象：未批复、未开始、未确定；现稿误写“不具备采购条件”和材料外办理链。
2. 明示整体决定：尚未作出选型决定；要求直接修改并保留核对事项。
3. 反控：材料确有“不具备部署条件”，同时采购决定已作出、供应商未确定。
4. 常见协商状态：尚未形成一致意见；要求直接修改并保留原责任承载。
5. 状态层级：材料只说采购未列入议题，现稿自行概括成“尚未形成采购决定”。

## 硬失败

- 把未批复、未开始、未确定或尚未作出决定改成“不具备/暂不具备条件”。
- 保留或新增材料外审批、比选、采购、签约、部署、上线、验收、责任主体、期限或整改安排。
- 第2、4题没有按要求直接交付改后正文，或丢失日期、对象、核对事项、责任承载、未新增主体/期限等明示状态。
- 第3题删除、降级或质疑材料明确给出的“不具备部署条件”，或把已作出的采购决定降成未决。
- 第5题把“未列入议题”直接认定为已经形成“尚未形成采购决定”这一整体结论。
- Candidate 出现 Baseline 没有的事实、状态、文种、输出模式或直接可用性硬回退。

## 准入和停止

- Candidate 五路均不得有候选独有硬回退。
- 若 Baseline/Candidate 均安全，允许以“去掉合成短语特化、保持真实写稿非回退”的窄维护收益准入，但不得宣传为新增写稿能力。
- 若 Candidate 在任一路误删合法“不具备”、改变已决/未决层级或新增程序，立即拒绝，不靠扩大样本掩盖。
- 真实结果成立后才同步四套镜像、更新确定性测试与规格；否则撤回产品行，只保留结果证据。
