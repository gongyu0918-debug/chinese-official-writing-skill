# R2 判定校准与最小修改

首轮五路 Baseline/Candidate 运行后，原预注册把任何由未决事项归纳出的“不具备采购条件”都判作硬失败。官方检索随后确认，明确前提缺口可以直接支持“暂不具备启动政府采购条件”。结合用户此前反复要求不得用过严标准压掉合理原因、结论和条件判断，原判定过严，不再沿用。

R1 Candidate 仍存在真正的目标失败：

- OpenCode Candidate 能把“采购未列入本次议题”恢复为会议范围，较 Baseline 有目标改善；Luna 两臂都能正确处理。
- Ollama Candidate 相对其 Baseline 新增“采购事项尚需进一步研究决定”；Alibaba2 Candidate 和 MiniMax Candidate 仍在建议中保留或重写“尚未形成采购决定”。这些表述把单次会议范围或局部状态上推为项目整体决定，不能准入。
- 五路两臂都保留材料明确的“不具备部署条件”，说明去掉合成专句没有形成机械删词风险。

R2 只改同一句：保留按原对象、谓语、时间范围和状态强度恢复；明确局部未定或单次会议状态不自动上推整体决定；材料明确前提缺口直接支持时，允许在保留具体状态后作低强度条件判断。随后使用全新三题 holdout 重跑 Baseline/Candidate，不修改既有 R1 原件。
