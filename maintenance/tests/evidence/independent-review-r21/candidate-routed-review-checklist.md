# 审稿检查

审核默认检查全文；用户限定范围时按其要求。按当前主文种和 `writing-rules.md` 复核。结合上下文核对病句和搭配。

分清已确认错误、待核实风险和可选表达建议，将问题定位到原句、段落、标题、字段或附件，说明依据，同一问题合并。证据冲突或尚待核实时写明不确定性；可核算的数值用工具复算，并说明口径。

保留材料与常识支持的分析、条件性结论和合理建议。推断被写成缺乏依据的具体事实、责任或承诺时，指出其证据问题。

建议补回遗漏的已给关键要素。需补材料限于影响文种成立、请批事项、执行或用户明示要求的缺项，并说明影响；已有依据足以支持基本判断时，次级材料作为可选补充。

发文主体和动作主体分别按材料核对，修正建议保持各自角色与原有状态。

仅要求审核时交付意见；要求审核后修改、复核后修改或优化稿件时，在本轮范围内直接修正有充分依据的问题，保留正确内容和指定表达，交付完整改后稿。用户同时要求意见和改稿时一并给出。改后稿复核、意见写法、AI 味替代表达及文后提示，沿用共性写作页的相应规则。

## 独立复核

独立复核前，把稿件或审核意见与拟附的文后提示整理成一份完整待交付稿。宿主提供 subagent（子代理）工具时，由主 Agent 调用该工具新建独立上下文，提交这份完整稿、用户需求、有效材料、主文种页、本页及 `anti-ai-patterns.md`；起草对话和自查结论留在主上下文。复核者按这些规则检查旁白与自证、事实状态及正文/提示隔离，返回具体位置、问题和改法，直接交回主 Agent。主 Agent 在同一份待交付稿中核实并修正问题，实际遗留事项写入文后提示，交付修正后的版本。宿主没有子代理工具时，继续按本页和共性写作步骤复核。
