# R31：2.0 独立产品验证结论

日期：2026-09-14。名称“中文公文写作 2.0”，标识 `chinese-official-writing-v2` 已由用户确认。本轮没有发布、推送或修改 1.x main。

## 决定

1. **选择性采用 Markdown 修复到 2.0 源线。** R30 两页文档原型、本轮旧 2.0 对照和最终脚本增量冷审支持这一局部修复；没有把外部线程整分支合入。采用范围为四页 references 和 `prose_lint.py`，兼容镜像同步。首页没有再写一遍格式规则，审核意见仍可使用 Markdown。正文内容上的差异保留观察，未证明由这项格式修改引起的系统性回退。
2. **尚不足以宣称 2.0 整体写作质量优于 1.0；2026-09-15 的公开发布建议 HOLD。** 架构与规则读取量有收益，但公告在两个通道新增材料未给的具体事项，新闻评论又出现材料处理旁白进入正文。小样本不能证明整个重构导致回退，也不能忽略这些实际输出而称“全场景无回退”。保留独立预览包，不替代 1.0。
3. **停止本轮追加采样。** 预登记 36 次，加最终脚本行为修复的 2 次原生 A/B，以及一次无最终输出的技术失效所对应的两臂重跑 2 次，共 40 次。没有为翻转质量胜负反复重抽；其余问题只列后续最小核验范围。

## 原生写稿与模型

真实宿主为 Codex CLI `0.154.0-alpha.6.2`；Python 只调度原生 CLI，不是直接向模型 API 发送拼接后的规则。每次独立上下文、独立工作目录、无用户文档/记忆/插件/Hook，按模型实际选读；最多两次并发。五条通道均接受 `max`：

- `alibaba-token-plan/qwen3.8-flash`
- `alibaba-token-plan-2/qwen3.8-flash`
- `command-code/deepseek-deepseek-v4.1-flash`
- `minimax-cn/MiniMax-M3`
- `ollama-cloud/glm-5.3-flash`

40 次调用中 39 次技术有效，19 个完整配对：16 对比较 1.0，2 对比较旧 2.0，1 对比较脚本增量。core 的 MiniMax 纪要基线进程返回成功但没有最终稿和读页轨迹，记作技术无效，不记为写作失败；两臂重新运行后稿件相同。初次候选单臂仍保存，不进入配对指标。

新增稿件由独立 Sol/max 在匿名包中评阅；主审回看原题、全文与轨迹并校准边界。冷审原文全部保留，排序不是自动门禁。正文外质检说明、审核意见 Markdown、草稿使用今天日期不算正文污染；合理目的分析、条件式下一步安排允许；“现款”推成“在售”等边缘判断不单独作严重回退。

## 公告与讲解题：具体材料和增补

以下是模拟题中的模型输出，不是现实新闻事件。

公告材料只给出：二楼展厅 2026 年 10 月 12—14 日更换照明、暂停开放；一楼阅览区及三楼活动室照常开放；咨询电话。Qwen 候选增补“已安排的培训活动不受影响”；MiniMax 候选增补“照明设备使用年限较长”“经研究决定”，以及“图书借阅、阅览自习及活动预约等业务均不受影响”。场地开放不能直接推出这些具体业务状态或已履行的决策程序。正常的施工安全目的、请观众安排参观计划可以保留。

基线 Qwen 写“10月15日恢复开放”并在文后明确标作暂停期间推定，按用户的合理推断标准不将它机械判作严重编造；MiniMax 基线未加上述业务。证据：[题面](runs/core/binding.json)、[Qwen 候选](runs/core/m0-publication-candidate.final.txt)、[MiniMax 候选](runs/core/m3-publication-candidate.final.txt)，对应基线同目录。

讲解材料只给出：2008—2015 年的三代产品、同一部件的四种加工样品和对应工序说明、两台现款设备供查看操作界面；不提问、不演示。MiniMax 候选将四种样品串成“毛坯到成品的几个关键节点”，并安排“按原路返回集合点”“稍后继续下一环节”。这些比给定的转场提示增加了实际工艺/活动安排。其“目前正在销售”与现款含义有关，作为需谨慎的状态细化观察，不单独算严重错误。

MiniMax 基线补得更多：毛坯→半成品→精加工成品→表面处理/装配前最终件，另给两台设备分配不同使用任务。故加工阶段是共有风险，不能将讲解题当作 2.0 独有损失。Qwen 候选反而明确“四种样品的先后顺序和具体做法，以墙上的说明为准”。证据：[MiniMax 基线](runs/core/m3-narration-baseline.final.txt)、[MiniMax 候选](runs/core/m3-narration-candidate.final.txt)、[Qwen 候选](runs/core/m0-narration-candidate.final.txt)。

## 减载、用量与耗时

以 16 个有效 1.0 配对统计，排除初次技术无效纪要及其不配对候选。完整返回页在单次调用内去重；只识别实际成功返回的整页，不计重复返回、不将未完整返回的片段冒充整页。因此以下“读页字符”是可核对的页覆盖指标，不等于总提示词或所有实际读取字节。

| 指标 | 1.0 | 2.0 | 变化 |
| --- | ---: | ---: | ---: |
| 成功完整返回的去重规则页字符合计 | 295,809 | 154,796 | −47.67% |
| input tokens | 4,238,280 | 4,134,278 | −2.45% |
| 未缓存 input tokens | 545,021 | 409,076 | −24.94% |
| output tokens | 152,131 | 137,800 | −9.42% |
| 各次耗时合计 | 2,119.43 秒 | 2,207.75 秒 | +4.17% |
| 单次耗时中位数 | 102.105 秒 | 102.870 秒 | +0.75% |

静态规则文本约减少 43%，首页约减少 66%，精确计数见 archive.json。未缓存输入下降是本批次观察；provider 缓存、服务负载、请求顺序和工具步数均影响结果。没有账单与单价校验，不宣称费用降低 24.94%；没有普遍速度收益，也不能用脚本调用增加替代质量提升。分题原始值见 [aggregate.json](aggregate.json)。

## 剩余范围
