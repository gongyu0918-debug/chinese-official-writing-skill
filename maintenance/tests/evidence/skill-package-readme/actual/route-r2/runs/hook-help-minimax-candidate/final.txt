下面只解释 Hook 的作用和默认行为，不安装、不启用。

## Hook 主要做什么

**性质**：本 Skill 的**可选**增强组件，名为「交付复核 Hook」，由 `hooks/` 目录承载，协议页为 `references/delivery-review-gate.md`。

**核心作用**：在 Agent 产出完整初稿（D0）之后再加一道**有界的交付复核**，用以捕捉已覆盖事实中的状态、结构、主体、办理表述、数字、未决事项等风险。本质上是给交付动作加的一道机器可复核门禁，不替代人工审签。

**默认工作流**（摘自 `hooks/README.md`）：

```
SKILL.md 与 references 形成完整 D0
  → 可选 prose_lint 只读提示
  → 已启用 Hook 保存 D0
  → 所选静态能力做一次有界检查
  → 候选通过机械与语义核验则选 D1
  → 其余情况回退 D0（不反复改写）
```

**顶层可选能力（静态互斥，组装前二选一）**：

| 能力 | 处理范围 |
| --- | --- |
| 既有交付复核（默认） | 通用的交付门禁 |
| 保护性外扩精确删除 | 只删不该保留的外扩内容 |
| 篇幅不足补足 | 命中用户硬下限且材料足以支持时补足 |
| 超长收束 | 超限时再压缩一次（先查重复、再压缩衔接与句式） |
| 交付洁净度 | 清除稿首附言等非正文干扰 |
| 重复句整理 | 只整理重复句 |

**关键边界**：

- Hook 不替代事实核验；正文事实是否正确仍需来源复核。
- 检查未通过或运行异常时，**优先交付原始完整稿**，不反复改写。
- 大多数场景最多修订一次；超长收束在首次压缩仍超限时最多再压缩一次。
- Hook 会增加事件处理和有限修订核验，**通常比普通 Skill 慢**；重要材料仍建议由责任人员完成事实核对和正式审签。
- Hook 与 `scripts/prose_lint.py` **各自独立运行**：前者负责交付复核，后者只提供只读语言与格式提示，不构成闭环。
- 本地数据：仅在宿主提供的插件数据目录暂存本轮原请求、D0、候选稿与核验包；正常到达终态 Stop 后删除正文，只回执 hash、字数、阶段、选择结果等脱敏状态；**不收集已安装 Agent 清单，不上传稿件或运行记录**。

## 安装 Skill 会自动启用 Hook 吗

**不会**。`hooks/README.md` 第 17 行明确：

> 下载、安装或调用普通 Skill 不会自动启用 Hook。

并且：
- 本目录只保存静态能力与兼容文件，**不自动识别宿主、不生成安装包、不安装插件、不修改配置，也不主动联网**。
- `SKILL.md` 第 138 行也声明：「普通起草、改稿、压缩和复核不加载该页，**也不自动启用 Hook**。」
- 必须用户**明确**要求为某个宿主启用 Hook，Agent 才展示宿主、目标目录和拟复制文件，等待用户确认后才组装胶水层；组装、安装、启用与宿主信任确认是**分开进行**的多步动作。
- 当前任务内还有更细一层的临时关闭方式：直接说"本次关闭 Hook，按普通 Skill 完成""跳过交付门禁"等即可只关闭本次门禁，不影响已启用的 companion。

## 关于支持的宿主

Hook 仅在用户确认后为目标宿主提供静态适配层（`adapters/<host>/`），目前文档中列出的有 Codex、WorkBuddy / CodeBuddy、Claude Code、ZCode、Qwen Code、Kimi Code CLI、OpenCode、Hermes Agent、DeepSeek Harness。其中部分有强约束，例如 Qwen Code 必须用 native extension、Kimi Code CLI 0.38.0 每回合只接受一次 Stop 阻断、Hermes Agent 0.20.5–0.20.6 只在新建不可恢复的 `chat -q/--query/--query-file` 单题同步复核、DeepSeek Harness 当前只在0.1.1-rc.2 headless 验证过；OpenClaw 仍为普通 Skill。

如果你想了解某个具体宿主的接入细节或临时关闭方式，可以告诉我宿主名，我再按 `hooks/adapters/<host>/README.md` 展开；当前不做任何安装或写入动作。
