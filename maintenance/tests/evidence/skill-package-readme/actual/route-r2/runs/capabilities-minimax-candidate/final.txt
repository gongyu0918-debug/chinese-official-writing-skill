## 这个 Skill 能做什么

按包内 `README.md` 的能力答复：

**能帮你写这些正式材料**：

- 公文文种：申请、请示、报告、通知、通告、意见、决定、决议、议案、公报、命令、函、复函、批复、说明、方案、纪要、公告、公示、通报
- 制度管理类：制度、规定、办法、管理办法、实施细则、操作规程、工作要点
- 总结调研类：工作总结、调研报告、述职
- 讲话致辞类：讲话稿、致辞、答复、责任书、公开信、倡议书、建议信、新闻发布稿、讲解稿、宣传材料
- 新闻类：新闻消息、快讯、活动报道、新闻通稿、新闻评论、时评、评论员文章、编者按、短评
- 专项材料：可研、审查材料、AI 算力相关正式材料
- 反映类：投诉、问题反映、情况反映、整改方案

同时支持改稿、新版生成、压缩、扩写、审校（只提建议）、去口语化、去 AI 味、Word 正文与排版。

## 只有零散想法，怎么请它写

README 里专门说："真实写作很少从一份齐全的材料清单开始。你可能只有几句想法、一段聊天记录，也可能已经写了半篇，临时想换个说法。这些都可以作为起点，不必先整理成标准提示词，也不必先填完要素核对卡。"

**可以直接这样说**：

- "下周要办个培训，帮我写个通知，把报名方式说清楚就行。"
- "活动记录贴下面了，帮我写一篇新闻消息。"
- "我只有这些零散想法：开座谈会、强调三个重点、要做会议纪要，帮我顺一顺。"
- "这是去年的总结，今年新增了 A、B 两项工作，帮我更新一版。"
- "这份稿子读起来太像套话，帮我改得平实些。"

把已有材料、关键数字、日期、单位、用途、希望保留或避免的内容一起丢过来即可。材料没整理也没关系，Skill 会顺着你的材料把稿子写出来，核对服务于写作，不会让你先填一堆表。**事实、数字、日期没有依据的不会编造**，模板里有但材料里没有的章节，也不会硬补成看似完整的稿子。

## 能写小说吗

**不能**。README 明确写了："这个 Skill 不用于小说和文学作品创作。"入口文件 `SKILL.md` 也把"文学创作"列为不启用本技能的任务。

它专注于**正式、平实、可执行的公文语言**，所以剧本、散文、小说、营销软文、社交媒体文案都不在它的服务范围。如果有这些需求，需要使用别的工具。
