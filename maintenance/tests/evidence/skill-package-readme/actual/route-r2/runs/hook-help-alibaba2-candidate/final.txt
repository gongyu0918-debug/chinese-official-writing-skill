## 一、Hook 主要做什么

**它是一道可选的"交付前复核门禁"，不是写稿能力本身。** 普通 Skill 本身就能独立完成起草、改写、压缩和复核；启用 Hook 后，Agent 会在完整初稿形成之后额外增加**一次有界交付检查**，专门盯住事实、状态和结构层面的风险（如数字、主体、未决状态、办理表述）。

- **工作方式**：`SKILL.md` + references 形成完整初稿（D0）→ 可选 `prose_lint.py` 只读提示 → 保存 D0 → 所选静态能力做一次机械与语义核验 → 通过则选择修订稿 D1，**不通过或运行异常则回退 D0**，不反复改写。
- **可选能力**：默认是"既有交付复核"，还可按需选择保护性外扩精确删除、篇幅不足补足、超长收束、交付洁净度、重复句整理（六种能力静态互斥）。
- **适用场景**：对数字、主体、未决状态等较敏感的正式材料，愿意用少量额外生成时间换一道机器可复核的检查。代价是**通常比普通 Skill 慢**，且多数能力最多修订一次。
- **数据边界**：只在本机插件数据目录暂存，正常到终态后即删除正文，只留 hash、字数、阶段等不含正文的回执；不联网上传稿件，也不收集已安装 Agent 清单。

## 二、安装 Skill 会自动启用吗

**不会，二者完全分离。**

- `hooks/README.md` 明确写明：**"下载、安装或调用普通 Skill 不会自动启用 Hook"**；本目录只保存静态能力与兼容文件，不自动识别宿主、不生成安装包、不安装插件、不修改配置、不主动联网。
- 只有**用户明确要求**为某个宿主启用 Hook 时，Agent 才会先展示目标宿主、目录和拟复制文件，用户**确认后**才组装；而且"组装、安装、启用和宿主信任确认"是分开进行的独立步骤，组装完也不自动进入安装。
- 宿主侧也需单独动作才会生效，例如 Claude Code 用 `--plugin-dir` 加载或 `claude plugin validate --strict` 校验，Codex、ZCode、Qwen Code、Hermes Agent 等各有自己的注册/启用命令。
- 普通起草、改稿、压缩、复核任务**不加载 hooks 资料，也不自动启用**；本次只解释、不安装，符合该说明的要求。

一句话总结：Hook 是装在 Skill 上的**可选增强门禁**，需要用户逐宿主、经确认手动启用，普通安装和写稿流程完全不受影响。
