## Hook 主要做什么

它是本 Skill 的**可选交付复核增强**（也叫"交付门禁"）。普通 Skill 本身能独立完成起草、改写、压缩、复核；启用 Hook 后，Agent 会在**完整初稿（D0）形成后增加一次有界交付检查**，重点排查它已覆盖的**事实、状态和结构风险**——如数字、主体、未决状态、办理表述等敏感项（`hooks/README.md:3`）。

工作方式可概括为：

```text
SKILL.md + references 形成完整 D0
  -> 可选 prose_lint 只读提示
  -> Hook 保存 D0
  -> 所选静态能力做一次有界检查
  -> 候选通过机械与语义核验时选 D1（修订稿）
  -> 其余情况（未通过或运行异常）回退 D0，优先交付原始完整稿，不反复改写
```

几点补充：

- **能力可选**：默认用既有交付复核；组装前还可明确选择"保护性外扩精确删除、篇幅不足补足、超长收束、交付洁净度、重复句整理"等能力，六种顶层能力静态互斥（`hooks/README.md:52`）。
- **代价**：会多处理事件并做有限修订核验，通常比普通 Skill 慢；多数能力最多修订一次，超长收束最多压缩两次。
- **数据边界**：正常到达终态会立即删除原请求、初稿、候选稿等，本地只保留 hash、字数、阶段、交付状态等不含正文的回执；不收集 Agent 清单、不上传稿件、不主动联网（`hooks/README.md:20-28`）。
- **多宿主适配**：有 Codex、Claude Code、CodeBuddy、ZCode、Qwen Code、Kimi Code CLI、OpenCode、Hermes Agent、DeepSeek Harness 等适配层；OpenClaw 目前仍只是普通 Skill（`hooks/README.md:36-48`）。

## 安装 Skill 会自动启用吗？——不会

明确结论：**下载、安装或调用普通 Skill 不会自动启用 Hook**（`hooks/README.md:17`）。`SKILL.md` 也写明了普通起草、改稿、压缩和复核不加载 Hook 页、不自动启用（`SKILL.md:137`）。

启用是有意、分步且需用户确认的流程：

1. 只有**用户明确要求**为某个宿主启用时，Agent 才进入组装清单步骤；
2. 先展示**宿主、目标目录和拟复制文件**，用户确认后才组装胶水层；组装、安装、启用和宿主信任确认**分开进行**（`hooks/README.md:19`）；
3. 组装完先跑宿主 validator 和离线事件 smoke，**再由用户决定是否安装或加载**，不会自动进入安装步骤（`hooks/README.md:78`）。

即使已启用，也可随时关闭：当前任务直接说"本次关闭 Hook，按普通 Skill 完成"即可；完全关闭按宿主对应命令（如 `claude plugin disable`、`codebuddy plugin disable` 等）处理（`hooks/README.md:90-106`）。

**总结**：Hook 是"写稿闭环之外的增值检查"，默认永远不启用；只有你明确要求并逐步确认后才可能被组装、安装和启用。本次仅按你的要求做了解释，未触发任何安装或启用动作。
