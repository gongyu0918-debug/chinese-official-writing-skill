# OC-003 可研建议边界重新裁定

日期：2026-08-24。

## 结论

`ACCEPTED_RESEARCH_CANDIDATE / MINIMAL_SCOPE_REPAIR_REQUIRED / NO_MAIN_PRODUCT_MERGE`。

对预登记、基线稿、候选稿、只审结果和四个 reference diff 重新逐项核对后，确认原裁判把两类不同内容混在了一起：一类是把“尚未形成结论”升级为“技术组正在核查”、把“预算来源未确定”升级为“审批程序尚未启动”，属于真实状态回退；另一类是用“建议、可进一步、如后续实施、具体效果需运行验证”等条件态提出比价、指标、风险或验证建议，属于可研和完整性审查允许的一层判断，不应一概判为材料外程序。

候选已经在 Luna、Ollama 和新事实盲样中减少前一类回退，因此不应拒绝；但当前四处规则又可能压掉后一类合法建议，不能原样合入公开产品。

## 重新裁定

- “采购决定及相关程序也未启动”“预算审批程序尚未启动”“技术组仍在核查”“经费来源未落实”：材料没有给出相应进行态或结论，属于状态升级，应恢复原词或删除。
- “上述事项需在后续研究中进一步明确”：没有新增责任主体、期限或已启动动作，属于未决状态提示，最多记自然度问题。
- “后续应重点研究同口径比价、超时原因、需求假设和经费安排”：若明确写为研究建议或完整性缺口，可以成立；若写成已经安排、必须履行的固定程序，则属于回退。
- “如后续实施，具体效果需运行验证”：与预登记允许的一层预期一致；只有把服务上线、运行验证或验收写成已经决定的流程时才失败。
- 用户明确要求完整性核对时，指出成本比较、技术指标、验收主体和验收依据缺项属于合法审稿功能；建议须与正文事实状态分开。

## 下一最小验证

只在研究候选中做一次状态分层修复：禁止已启动、已确定、已完成、已有主体/期限或必须履行的程序；允许直接绑定现有事实、以建议态表达的一层研究、风险控制或验证意见。用 Luna、Ollama、Alibaba 各跑一组正负对照，确认正向条件建议得到保留、反向状态升级得到删除或降级，并检查正文不因程序克制退化为事实清单。
