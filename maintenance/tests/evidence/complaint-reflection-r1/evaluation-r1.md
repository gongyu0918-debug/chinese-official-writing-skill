# WR-027 R1 真实写稿判定

日期：2026-09-02。

## 有效性

第一轮使用 `--ignore-user-config` 的 25 份基线输出没有形成 Skill 读取轨迹，全部作废，不进入质量判断。R1 重新使用 Codex Desktop CLI 0.152.1，保留只读命令能力并关闭插件、Apps 和 Memories；Baseline 与 Candidate 各 25 份，50/50 均实际读取隔离运行时 `SKILL.md`，没有全局同名 Skill 或产品 Hook 污染。

## 路由和目标结果

- 新叶在平台投诉、独立情况反映、带明确请求投诉中分别被 3/5、3/5、5/5 个 Candidate 实际读取，共 11/15。
- 三道正向题的 15 份 Candidate 均未擅自提出退款、补偿、平台改造、流程优化、责任分工或办理期限；材料允许的一层直接影响和状态归纳不据此判失败。
- 带明确请求题 5/5 均保留核实与反馈请求，没有把请求误删，也没有把请求扩成解决方案。
- 两道控制题共 10 份 Candidate 均未读取投诉叶；意见建议仍提出具体建议，收到投诉的内部说明仍保持办理方视角。
- 机械摘要把同年后续日期`8月9日`误判为缺少`2026年8月9日`，把`仍未收到`误判为缺少`尚未`，并把`后台核验过程中`误判成正文外`核验过程`。这些属于 verifier 过严，不作为稿件失败。

## 候选独有风险与处置

R1 不直接进入工程门，继续最小修复而不作 HOLD：

1. Alibaba Token Plan 2 的独立情况反映漏掉用户给定标题，并新增`待后台核验结论明确后按后续要求办理`，属于结构遗漏和材料外安排。
2. Alibaba Token Plan 1 的独立情况反映用 `&nbsp;` 模拟落款缩进，纯文本不可直接使用。
3. MiniMax 的带明确请求投诉在正文前新增已读取 Skill 的过程说明；虽然 R1 总体正文外包装少于 Baseline，仍是 Candidate 独有直接可用性回退。

下一步只增强新叶的标题锁定、未决状态结尾和纯正文交付三项，再用三道正向题复测五家。控制题没有读取新叶，产品路由也不再变化，因此不重复消耗。
