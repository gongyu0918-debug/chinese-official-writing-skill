# r14 采购公告、编者按及函语气定向查证

核查日期：2026-09-13。仅核对上一份规则审计已定位的功能，使用官方发布平台或发布者原站；未改产品，未读真实测试输出，未运行模型。采购和编者按部分是少量真实稿件的写法比较，不把出现过的字段、段数或措辞认定为普遍法定要求。

## 结论与归页建议

1. **采购公告宜保留一个主叶，按征集响应、结果告知、终止事项选择不同要素。** 三种样本都以识别采购项目及公开当前事项为共同功能，差异可以用三条短分支完整表达。把结果、终止另转普通公告页会丢失采购对象、包次、结果及状态的专项核对收益，并增加跨页判断。这是依据样本作出的架构建议，公开稿件本身不规定 Skill 如何拆页。
2. **编者按有独立的编辑说明功能，宜独立主叶；不套消息标题、导语及事件主体。** 两例共同交代编发背景、编发目的和阅读方向，标识形态却不同。独立主叶仍可很短，不必扩成新闻理论页。
3. **“函保持平行商洽语气”作为全部函的规则过窄，“不使用审批式口吻”需修改。** 官方条例定义明示函包含请求批准和答复审批事项；语气应随商洽、询问答复、请批或审批答复的用途及实际职权确定。

三例的稳定区别是读者需要“如何参加”“结果是什么”还是“什么活动已停止”。共同需要把采购对象与当前发布事项对应起来；项目编号、包次、采购人和代理机构等已有信息服务于这一对应关系。结果公告里的金额属于结果，不能与征集公告的预算或上限互换；终止也不能自行改成重新采购、已经成交或项目永久取消。

**不应从样本提升为统一硬门槛**：采购方式、公告天数、文件售价、保证金、特定资格、专家名单、代理收费、厂家型号、供应商数量及表格栏目均依具体采购及适用要求判断。尤其不能因为结果或终止公告没有新的响应条件、递交期限，就报为缺项。终止样本确有后续再公告的条件句，这只能说明该项目给出了安排，不能生成所有终止稿的固定承诺。

### 可直接据此整理的精简规则

- 先按发布目的选择要素：征集响应写清采购内容、已给条件及取得文件、提交响应的时间和渠道；结果告知写清项目或包次、已定供应商、金额及主要标的；终止事项写清项目、终止范围、当前状态和已有原因。
- 联系方式、公告期限、附件和后续要求按材料、用户模板及适用发布要求保留。只对影响本次用途的缺失作提示，不把另外一种公告的字段补成固定栏目。
- 三种目的都使用客观告知语气，明确已确定、尚待确认及附条件事项。具体采购合规要求有疑问时，再定向核验相应规则；本页不承载采购法律手册。

**两例支持的共性**：以编辑或编发者身份，说明编发对象、选题背景、编发缘由或目的，提示内容及阅读方向。可有与材料相称的概括、评价和期望，功能不限于重复事实摘要。

**非强制惯例**：两段或三段不是固定段数；“编者按：”起笔、以“编者按”为标题、末署编者是样本中出现的不同标识方式，不应要求同时具备。样本没有为按语另套消息标题和导语，因此不能把两者设成按语硬要素；用户已有题名和版面模板仍应保留。新华社例中的栏目沿革、系列起播日期和评介，均是该发布者已有内容，不可成为其他稿件的默认事实。

### 可直接据此整理的精简规则

- 编者按说明编发什么、为何编发及希望读者关注什么；按材料多少合并为简短自然段。独立交付时以“编者按”标题、“编者按：”起笔或用户已有模板清楚标示编辑身份。
- 以编发者视角概括背景、主题与价值，说明内容关系及阅读方向；具体编发安排、评价结论、栏目来历和作者经历采用材料依据。
- 完成按语即收束；用户只要编者按时不继续生成被编发稿件，不自动添加新闻标题、导语或完整事件报道。合并交付时，把按语与被编发正文的身份和内容边界分清。

## 三、函的请批与审批答复功能

### 官方定义

工信部公开的[中办、国办印发《党政机关公文处理工作条例》](https://www.miit.gov.cn/xwdt/szyw/art/2020/art_6afb8ee6d07540dcacccbeb47dbc0fd4.html)，页面发布时间为 **2013-02-22 16:41**，注明来源为中央政府门户网站。第八条第十四项在不相隶属机关间商洽、询问答复之外，明确包含“请求批准和答复审批事项”。本次只使用这一文种定义及其相邻的请示、批复关系，不扩查其他程序。

### 一份官方实际用函

[教育部关于同意设置深圳理工大学的函](https://www.moe.gov.cn/srcsite/A03/s181/202406/t20240612_1135115.html)，教发函〔2024〕106号，主送广东省人民政府，承接省政府报请批准设校的来函，正文作出同意设立的决定并交代有关事项。**正文成文日期为2024-05-30，页面生成日期为2024-05-31，页面标注发布日期为2024-06-27**，三者不混用。

该例表明，来文请求批准与有权主体的批准答复均可以采用函；实际明确同意及相应事项不能被一律改成商请考虑。本例正文及日期来自教育部原 URL 的搜索提取内容，直接打开该页超时；条例全文已直接打开核对，定义结论不依赖该超时页。

### 对 r13 规则的最小修正建议

`genre-playbook-correspondence.md:11` 中笼统排除“审批式口吻”，以及 `genre-routing.md:74` 把函统一约束为平行商洽语气，范围均过窄。建议改为：

- 函用于不相隶属机关或单位间的商洽、询问答复、请求批准及有权范围内的审批答复；先明确本次用途与收发双方职权。
- 商洽用平等沟通语气；请求批准写明请求事项；审批答复准确保留材料已有的同意、不同意、条件和范围，不因使用函而改弱已定答复，也不在缺少依据时替有权主体作决定。
- 上级机关答复下级请示仍按批复处理。称谓和结语随本次用途及模板选用，不把商请结语强加给所有复函。
