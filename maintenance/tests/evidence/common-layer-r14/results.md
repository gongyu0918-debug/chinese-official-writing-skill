# R14 共性伴读减负结果

基线为冻结 R13，分别测试办理要素转读条件 A、固定用语去重 B 及两者组合 AB。两个原子互不修改对方的页面，组合只包含两项变动；所有原始请求、模型输出、读取与脚本轨迹保留。它们是 2.0 内部对照，不是与旧 1.x 的最终验收。

## 原生写稿与实际暴露

三组各 8 次调用、4 对稿件，共 24 次，全部技术完成。通道为 `alibaba-token-plan/qwen3.8-flash`（medium，沿用前期 max/high 不收束后的可执行强度）和 `command-code/deepseek-deepseek-v4.1-flash`（provider-default）。原生 Codex CLI 自主读页、保存并扫描稿件；未通过预拼接 reference 或主代理改稿代替写作。

- A：普通办公椅申请与复杂设备附件申请。普通题两边均未读办理要素页，复杂题两边均读，故本组不能证明触发条件调整降低了这页的实际读取率。
- B：函件与报告的固定用语。八稿均实际读取固定用语页，覆盖日期语境、来文引叙、请批与报告收束。
- AB：带常用申请用语的分项采购及附件，与复函。两通道的四次申请调用都同时读取办理要素和固定用语页，覆盖同稿组合；函件作为固定用语的重复观察。
- 24 次均返回抗 AI 味页，均出现文稿扫描命令；字数扫描同样可见。脚本命令数不等于独立进程数，也不证明所有风险已被处理。

## 独立判读

A 原包一条 Windows 反斜线临时路径未被屏蔽。原审阅保留为带此限制的补充；另冻结 A-sanitized 包，交由未读原包的独立审阅者重新评四对。B、AB 使用独立身份映射外的完整消息包，正文和整条交付分别判断；没有删掉旁白、文件链接或文后建议后再送审。

| 组别 | 正文候选较好 / 基线较好 / 相当 | 完整交付候选较好 / 基线较好 / 相当 |
| --- | --- | --- |
| A | 2 / 0 / 2 | 1 / 2 / 1 |
| B | 3 / 0 / 1 | 2 / 1 / 1 |
| AB | 3 / 0 / 1 | 2 / 1 / 1 |

这些是指定小样本的偏好，不是总体胜率。A 的主要问题是两边都扩写了具体会议频次或错峰情形；候选另有文后误称主体、接收方未给，假定幕布套件范围及末尾起草标记。正常办公需要、借用归还影响、通常下一步建议和当天草稿落款不按无据事实一概扣分。正文更好不能抵消错误文后提示；一次复跑没有出现错误也不能证明纯模型波动。

B 主要为轻微自然度和交付负担差异。日期、已有状态与请批功能未见确定损失。明确可借用的语境下，普通承接和场地准备意向按合理表达评估；示例里的具体文号前缀只作为文后模板精度问题，不混说成正文已经伪造文号。

AB 的两份基线采购申请增加了具体会议频次、共用一套设备或已开展梳理活动等情形；候选按已有设备需求和可直接计算的金额展开，未出现对应具体新增事实。两份复函主要是轻微表达和完整消息的负担差异。24 稿均超过 80 字，金额、附件、状态与文种动作在本次组合中保留。

## 负担与归因限制

| 组别 | 实际返回规则字符，基线 → 候选 | 未缓存输入 token，基线 → 候选 |
| --- | --- | --- |
| A | 44584 → 41018 | 59791 → 71996 |
| B | 45939 → 46000 | 52648 → 65809 |
| AB | 52288 → 48429 | 77278 → 67493 |

规则字符按每任务实际完整返回页面去重计算。A/B 未缓存输入反而增加，AB 减少；全部三组汇总未缓存输入仍增加，不能据组合一组宣布费用降低。差异包含索引、称谓、格式、细查等其他读取和反复操作，未将它们全部归因于被改规则。

DeepSeek 在 B、AB 的基线与候选复函任务中均读了批复页和函页，最后按函写作。应作为可复现的无关读取线索保留，不能因为最终选对文种就宣布单叶读取已完全达成。两边的过程旁白也仍明显；不能把“扫描完成”解释成旁白已被可靠压住。

## 落地与下一步

整套统一共性主线已先在 `db1761fa` 落入 2.0 工作树，见 [整合记录](canonical-integration.md)。A、B 的页内职责调整有原规则归属支持，独立及同稿组合未发现可确认的功能损失，故两原子继续纳入 2.0 开发候选并同步五份仓库镜像。只在两目标文件应用已测改动，保留此前八处整合修正；共同页面和两个普通脚本没有再改。

纳入不表示文后错误和旁白已经解决，A 的不利完整交付原样保留。减载与具体任务的正文表现支持此次取舍，缺少稳定的 token 和完整交付优势，不能扩大为普遍提升。落地后 29 项重构合同及 2 项唯一性检查通过，`git diff --check` 通过；不重复未变化脚本的单测或运行发布门。最终 1.x 对照、全体文种与 Word 的验收另有未完成项。
