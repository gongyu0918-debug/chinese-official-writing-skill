# 当前2.0与1.x：多模型冷审及Markdown实写

本轮保留当前产品。冷审支持架构和部分实稿有收益，也确认采购审改与交付格式仍有局部错误；不能据这些样本宣称全面更好、零回退或普遍更快。没有把评审票数当成规则因果，也没有因评审用了“确定回退”就直接恢复旧限制。

## Markdown约束到底有没有丢

**能力仍在，但实际执行没有做到稳定清洁。** 当前入口保留纯文本形态与用户明确Markdown的例外，anti页有交付格式核对，校对页有Markdown残留检查，`prose_lint.py`保留加粗、标题井号、代码围栏和横线风险，Word页有正式Word残留约束。并非删掉首页枚举就只剩模型猜测。

新增默认正式申请题的观察：

- Qwen旧版：正文纯文本，无外层代码框。
- Qwen当前：扫描文件已去标记，最终回复重新套`text`代码框。
- MiniMax旧版：最终也套代码框。
- MiniMax当前：代码框内仍有`#`标题；扫描已报风险，模型却错误地认定获得用户授权。

因此有三层问题需要区分：稿内符号、包住整稿的围栏、正文外审核意见自己的Markdown。最后一类不等于正文残留；用户明确要求Markdown时正确保留标题与列表，也是本轮的正向对照。不能为消除第一题问题，把第二题的合法格式一并禁掉。

当前最值得关注的是**底稿格式与用户交付偏好混淆**、**扫描文件与最终消息重新包装**。本轮两版整体A/B无法把它们单独归因于某句删除，未做单句恢复的第三臂，不声称已证恢复旧句有效。保持原产品和反例，避免再堆一组同义禁令。

## 规则冲突、路由和可达性

文件路径审计通过，manifest核对67页通过；GLM完整回读全部67页，未发现硬断链或明确强制死循环。静态可达不等于每次实际选对：新增MiniMax采购先读项目增项申请叶，随后纠正到普通申请叶；通知候选仍出现漏anti页的调用。这些都保留轨迹，不改写成“每次必读已保证”。

父侧对GLM发现的处置：

| 冷审建议 | 父侧核对与处理 |
| --- | --- |
| 兼容路由末句“完成稿件后执行编号检查步骤”没有明确对象 | **确认轻度路由歧义。** 路径本身不死链，但“编号”可被理解成检查序号，或首页的带编号步骤。最小修法是准确指向首页“写作与交付步骤”，不用加新页或第二套流程。本轮先记录，产品仍冻结 |
| 审稿意见未恢复禁止加粗/表格，属于确定回退 | **不按当前标准接受为质量回退。** 这是正文外意见的呈现；用户已弱化整条消息零包装门槛。只在用户明确要普通标签或可复制格式时按要求处理，不恢复全面禁止 |
| 字数步骤没有独立失败降级句 | **降级路径表述可关注，未证死锁。** 共性页已有运行受限如实记录，脚本行为可报告错误；不能只因没有在第二步重写一遍就认定强制循环。此次所有写稿完成，无故障降级用例 |
| 显式防复扫循环句、进行态例子等删除 | **待验证风险。** 现有规则允许合理命中保留，并限定实质修改后复扫，没有命令要求扫到零风险。旧例子删去不等于语义缺失，不直接补回 |

“完全一文种一叶”的说法也需收窄：当前公开发布页仍同页区分公告/公示/通告，请示/申请及讲话/致辞/演讲亦按同族共享。相比旧综合枢纽，主体职责已清晰得多；但不能按文件数量宣称所有文种绝对分离，是否还需拆须由真实误路由决定。`genre-playbook-procurement-review.md`是条件专项核对，不能把全部41个同前缀文件都计成独立主叶。

Sol与GLM独立指出同一兼容路由歧义；Sol另指出方案页第9行“另读相应的事实选择或复核页”缺准确文件名。后者下一行已有`writing-rules.md`处理信息选择，首页也有文种判断与审核路径，因此是可按上下文找回的模糊指针，不是功能完全不可达。最小修法应将复杂材料、文种冲突和审稿分别指向已有承担页，避免再新增一组兜底页。本轮没有改动这两处冻结规则。

Sol的其余三项“确定问题”按用户明确选择重新定级：

- 取消默认80字下限：**不采纳。** 用户明确要求真实硬下限，现规则也为局部任务、明确更短要求保留例外。可以观察是否诱发凑字，但不能把用户的产品要求当错误删除。
- 删除独立上下文清理动作：**不采纳其“构建残留”定性。** 用户明确要求可使用独立上下文清理旁白，这是写作运行能力。可审其条件是否足够清楚，但不应在冷审中擅自撤销。
- 全部审核加读anti和扫描应改成可选：**不采纳通用降级。** 用户明确要求审核也做抗AI检查；限定任务如何节省无关检查属于待验证优化，不能据一个极窄边界取消通常审核链。新增实稿已经显示扫描可以运行后被误判保留，不能把“少扫”直接算更优。

## 父侧撤回或降级的冷审判定

- 把今天的草稿日期视为未经授权发布、将合理目的推断算编造：与当前用户标准不符。
- 把P03“工作时间拨打”一概算新增服务制度、把常规“按程序办理”一律算已定程序：需看它是否具体限定了未经提供的流程或承诺，不能按词语判错。
- 断言`C:/...`或`/C:/...`格式的本地文件链接一律无效：不成立。宿主支持本地路径；只有缺盘符、占位路径、目标不存在或交付不可用有实际证据时才判文件问题。临时目录本身不等于虚假产物。
- 把阿拉伯数字与“两台”并用、缺固定尾语、层级多少自动计质量差：只作可选编辑，不据此排名。
- 将稿件前独立质检话术纳入正文扣分：按既定分界撤出；不准确的自评也不能用来证明正文已复核无误。
- 将“121字”只数两段而漏请批语，或临时改用只计中文字符：不作为硬长度判负。计数以题面约定及现行默认口径为准，详细原计数及稿件边界留存。
- 将新增MiniMax误读Markdown归因于串题：原生调用各自隔离目录和会话，不承接另一题上下文，没有串题证据。该模型是在自己的调用中作了错误解释。
- GLM把已从审查包排除的旧`review_gate.py`说成旧产品本就没有：这是包范围与产品事实混淆，不能作为旧能力缺失证明。

Qwen两题都更慢，MiniMax两题都更快。候选执行脚本更多，Qwen采购还多次按不同稿件范围计数；完整读页少不等于调用总token少。并发负载、缓存、思考长度和provider统计口径均不独立受控。本批支持**规则读取量减少**，不支持普遍提速或账单更低；无价格/费用结算证据。

冷审自身的调用量单列：例如GLM全包审阅141条命令、provider报告input约504万，反映审计中的反复上下文读取，不是2.0一次写稿的消耗。不能将其混进两臂写稿费用，更不把此类昂贵冷审变成用户每次写稿流程。

## 本轮处理边界

本轮新增实稿、其他模型冷审和归因记录已经完成其范围，不做全叶全模型统计保证。未重跑Word实物、新闻组合、技术需求、公开信、纪要局部修改等原场景；已有证据可参考，但本轮未把其旧结论重新包装成当前新测试。

产品暂不修改。明确保留：路由歧义一句、采购主送/格式误判、最终消息重加围栏、假链接、讲解局部错误及提示漏检这些待办；它们的严重度和归因分别记录。必要后续修复可以逐项做最小原型并同题验证，不用再全面恢复旧兜底和关键词门禁。

验证为8次原生写稿、六次外部CLI冷审、Sol独立全包审阅，以及快照/终稿哈希、冷审输入未改、文件路径审计、manifest和文档检查。原始报告有分歧与误报，全部保留。未合main、安装、推送或发布。
