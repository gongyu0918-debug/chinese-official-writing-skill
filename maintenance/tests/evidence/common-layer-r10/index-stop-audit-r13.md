# R13 索引“停止规则”归属核对

结论：可以删除索引末尾的流程复述，不需要另写一套伴读或复读管控。建议将“独立附件也按自身用途选文种”并入首页现有逐份选路句，然后删除索引的“停止规则”标题及整段。必读共性页、抗 AI 味、脚本和交付均由现有入口承担，不依赖该段。

## 逐句判断

| 索引第 65 行内容 | 判断与既有归属 |
| --- | --- |
| 首叶覆盖文种功能后，直接进入成稿或审查 | 首页第 39 行已规定选定文种后进入 `writing-rules.md` 完成取材、成稿、复核及交付；第 54 行也给出总流程。索引再次描述“直接进入”没有新增文种选择能力，反而容易被读成另一条省略共性页的执行顺序。可删。 |
| 共性页按任务信号叠加 | 若仅指索引第 48-51 行四种可选能力，则是对表格触发条件的重复；若理解为所有共性页，则与首页第 39 行必读 writing-rules、共性页第 33、35 行必读抗 AI 与 prose 的要求存在解释冲突。删去总括句，保留表格中实际条件即可。 |
| 每份独立稿件和附件按各自用途选路 | 多份独立稿件逐份选路已在首页第 27 行。独立附件的用途选择虽可由这条原则推知，但在本次指定页面中，没有另一处同样明确的通用表达；索引第 27 行只覆盖技术需求附件这一具体类型。将独立附件并入首页原句后，索引此句可删。 |
| 文内引用或背景不另选主文种 | 首页第 27 行已规定同一稿件中的会议、采购、整改等内容按稿件用途判断；第 23、31 行也以稿件用途确定文种。该句是在同一原则下补举引用和背景情形，适合与首页原句合并，不需要留在索引末尾再设规则。 |
| 文种仍有冲突时再读 genre-routing.md | 首页第 35 行已明确覆盖文种或行文关系冲突，索引第 42 行也有未命中文种时的入口。末段再写一次没有独有功能，可删。 |
| 脚本调用保持在脚本页范围 | 当前字数命令已直接写在 `writing-rules.md:21-27`，prose 由第 35 行转至使用页。“脚本页范围”不再清楚对应当前职责，容易被理解为不允许在共性写作页执行字数命令。删除不影响脚本定位、参数、必经要求、复扫或失败处理；这些均由实际调用位置承担。该句属于可撤的流程管控。 |

以上是文本解释歧义与重复归属判断，不等于已经观察到模型跳过必经检查。

## 最小修改方案

首页第 27 行后两句可统一为：

> 多份独立稿件及具有独立用途的附件分别选文种；同一稿件中的会议、采购、整改、引用和背景等内容，按所属稿件用途判断。

保留该行此前“信息足以判断时继续处理；稿件用途尚无法确定时，集中询问影响选路的信息”。随后删除索引第 63-65 行的“停止规则”标题和段落。

这样只在首页保留一次选择对象的边界，不在索引补写“仍须读取共性页”“禁止复读”“完成后跳转”等替代条款。现有索引仍负责文种及能力映射，首页仍负责何时进入共同流程。

若仅删除索引流程句而保留一句选择规则，也不会损失功能；但它继续与首页第 27 行重叠。按用户要求由首页承担选择流程的方向，以上归并后整段删除更清楚。

## 不会因删除而丢失的功能

- 普通完整短稿 80 字下限及独立字数核查仍在 `writing-rules.md:17,21-27`。
- 事实、状态、主文种要素及局部关联范围复核仍在第 31 行；抗 AI 味与 prose 仍在第 33、35 行。
- 审核、完整审后改稿、默认文后提示及正文隔离仍在第 41-45 行。
- 可选办理、论证、语体、称谓及专项伴读的具体条件仍留在索引表格和专项条目，删除末段不取消这些能力入口。
