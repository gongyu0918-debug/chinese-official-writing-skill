# 渐进路由审核与减载 R1 预注册

## 授权与固定范围

用户先要求审核 MIT 公开 Skill 的 references、构造、Hook 和长程 loop，随后明确本轮继续构建；每次减载均以与既往相同方式的真实写稿验证。此次不合并 main、不推送、不发布。

- 固定产品基线：`5fbb2d26c49d0b780ad11fc4cff008854995ad3f`。
- 开发分支：`codex/reference-route-audit-r1`。
- 唯一产品原子：`chinese-official-writing/SKILL.md` 的渐进加载条件归一。核心流程描述写稿动作，参考资料表决定实际加载；删除 workflow 条件中泛化的“任务模式路由”。
- 保留事实、未决状态、最新版底稿、文种功能、篇幅、正文交付和复核要求。不在本原子修改 Hook、description、references 正文或镜像。
- 候选提交由 fixture 记录精确 SHA；真实结果准入前仅为实验原型。

## 为什么先测

当前入口一面要求只读命中表项，一面在完整流程逐步指向文种路由、办理要素、论证等通用页。WR-028 一份 MiniMax 短整改真实 trace 读取 SKILL 加 8 份 references，包含普通方案叶；这只证明单路实例，不能推广为所有任务的稳定过载。历史减载试验也出现读取不减、正文包装或状态遗漏，故不凭静态文件大小准入。

## 首轮真实 A/B

复用 WR-028 的 `REMEDIATION-SHORT-SERVICE`、`REMEDIATION-EDUCATION-LONG` 原提示词与材料，不添加强制读页、输出模版或答案提示。使用原有五条路线和 `max`：Alibaba 两条 DeepSeek、Ollama DeepSeek、OpenCode DeepSeek、MiniMax M3。它们是五条服务路线，不声称五种独立基础模型。

共 2 题 × 2 臂 × 5 路 = 20 份真实稿。同一路交错 baseline/candidate 次序；所有运行使用同一 Codex CLI 和既有 desktop_writer 隔离方式，普通 Skill、无 Hook。记录完整正文、原始 trace、技术隔离检查、实际成功读取文件、读取字节、usage、耗时、提示词及产物哈希。

## 判定

1. 技术有效须完成、实际读取导出的对应 Skill、无用户同名 Skill 或 Hook 污染。技术无效独立保留，不当产品失败，也不在看到结果后替换测试题。
2. 人工逐稿检查事实、状态、责任与期限、文种、合理归因和未来措施边界、正文可直接使用性。自动 required/forbidden 匹配仅作线索，允许等义表达；保留原始误报。
3. 候选独有的事实、状态、文种、用户指令或直接交付硬回退为不准入。长稿结构和实质措施不能为少读而缩水。
4. 实际减载至少须在两条有效路线看到减少非必要通用页或加载正文体积的收益；仅文件字节变小、某一条路线偶然少读或 API 总输入 token 下降，不单独证明路由改进。
5. 不满足时保留失败证据，针对具体原因最多做一次更小修复；不扩大评分表或全量测试掩盖失败。所有后续减载再次真实 A/B。

## 后续门

真实准入后才同步五套兼容包并跑直接相关 smoke、quick validate、链接和 diff 检查；无合并/发布计划时不重复全量回归。Hook 缺陷在独立 worktree 处理，不混入本实验。

用户随后澄清 loop 指“初稿—发现错误—修订—再核对”的成稿质量收敛。允许 D0 存在错误；Hook 的收益以同一 D0 的修正、遗漏和新增错误判断，按短长稿分别检查。当前路由 A/B 先保持普通 Skill、无 Hook；随后选择其真实 D0 做有界 Hook 复放。只有发现具体规则缺口时补充官方真实稿件研究，不把主任务扩大为多轮会话或 compaction 工程。
