# WR-005b 短稿语义路由去魔法数字预登记

日期：2026-09-01。

## 问题

当前入口用“不超过300字”和“200字左右”决定短稿专叶直达。Git 历史表明，这两个数随 2026-08-17 的四个 260/280 字上限题接入，能证明当时样本有效，但不是跨文种的通用分界。固定数字还会漏掉“简洁、精炼、紧凑”等无数字意图，以及 300 字以外但仍属紧凑交付的任务。

OpenAI 官方模型指南建议从已工作的提示词出发，一次只删改一组指令并用代表性任务复测；本原子只改短稿路由条件，不改短稿正文规则。

## 候选

- `SKILL.md`：明确“简短、简洁、精炼、紧凑”直接路由；只给上限时结合文种、材料密度和交付形态判断，不按固定字符数切分；明确下限或区间仍不得以短稿规则代替篇幅要求。
- `references/short-draft-naturalness.md`：只移除同一组数字示例并改为上述语义范围，不改五条正文行为。
- 不修改 description、其他文种叶、Hook、镜像、版本或包体。

## 真实写稿矩阵

固定基线为 `main@69515dbc216e6e057e497fbaa0c1cebb9dac6547`。五家低成本 provider 均使用 `max`：Alibaba Token Plan 2、Alibaba Token Plan、Ollama Cloud DeepSeek V4 Flash 0731、OpenCode Go DeepSeek V4 Flash、MiniMax M3。

六题分别覆盖：无数字“简洁”采购申请、480字上限情况说明、360字左右通知、无上限但事实密集的“紧凑”报告、800—1000字硬区间报告、1500字上限且明确不要求简短的讲话稿。

## 判定

- 新增路由价值：候选在语义短稿或合理紧凑上限题中读取短稿页，减少缩小版长报告骨架、重复和正文外包装，同时保持全部必要事实、状态和文种动作。
- 路由保护：事实密集的紧凑任务不得因读取短稿页删除必要事实；明确下限/区间不得被写短；1500字完整讲话不得仅因存在上限机械走短稿。
- 基于给定事实和常识的一层原因、直接作用、条件性结论、正常文采与合理篇幅差异不判失败。只有候选实际读取或候选路由文字直接造成的事实、状态、篇幅、文种或交付回退才计入失败。
- 至少两家 provider 证明新增语义路由有可复现收益，且控制题无跨 provider 硬回退，才进入工程门；否则恢复产品并终止，不留 `HOLD`。
