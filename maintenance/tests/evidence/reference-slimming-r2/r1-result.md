# `AI-COMPUTE-BASIC-LEAF-R1` 首轮 A/B 结果

## 裁决

R1不准入，但不直接终止。25次真实任务全部技术有效；简单申请窄叶在部分 provider 形成真实省读和可用正文，但全新 holdout 只有2/5 provider 总读取字节下降，Ollama在完整可研同时读取窄叶后遗漏4项已给技术事实，另在 holdout 输出 Skill 过程旁白，MiniMax holdout Candidate 遗漏全部未决字段。按预登记只做一次更小路由修复：完整专项页前置并显式排除简单申请窄叶；不改窄叶内容、不增写作规则。

## 控制题

- 完整算力可研：5/5有终稿。Alibaba 1/2和OpenCode仍读取完整专项页；MiniMax两轮均只读入口。Ollama Candidate同时读取完整页和窄叶，随后遗漏已给的2台服务器、每台4张GPU、5.8千瓦和71%，而冻结Baseline完整保留，属于必须修复的完整任务串叶与事实覆盖回退。
- 普通打印机申请：5/5 Candidate均未读取算力窄叶或完整算力页，未出现专项路由污染。OpenCode过程旁白、MiniMax占位与外扩发生在只读入口的随机样本，既未命中新叶，也不是本原子可稳定解释的差异，不用来否定或美化候选。

## 质量复核

- 原题 Candidate中，Alibaba 1/2、OpenCode完整保留排队、尝试、资源、服务期、验证和未决字段；Ollama遗漏全部未决字段，MiniMax把“内部知识检索服务”扩成“内部知识检索等服务”并补“外部资源、另行报批”。
- Holdout Candidate中，Alibaba 1/2、OpenCode可直接使用；Ollama出现正文前过程说明；MiniMax遗漏全部未决字段。以上均按明确材料状态和输出形状判定，不因候选稿更短、少写预期作用或未复述提示词而判失败。
- Candidate没有压住全部模型的未决字段，也没有稳定减少总读取；R1不能合并。

## R2最小修复

只交换 `SKILL.md` 两条算力路由的优先顺序：完整可研、成本/部署比较、技术指标、SLA、安全、验收、技术方案和完整技术审查先命中完整页，并明确不读简单申请叶；只有未命中上述条件的简单采购/租用申请再读窄叶。窄叶内容保持逐字不变。

R2只复放原简单申请、完整可研和新 holdout Candidate，共15次；与已冻结 Baseline 和R1 Candidate比较。若完整任务仍串叶或遗漏技术事实，或两道简单申请仍不能形成至少3/5稳定负字节且存在候选独有硬回退，则恢复产品并终止当前窄叶方向，不留HOLD。
