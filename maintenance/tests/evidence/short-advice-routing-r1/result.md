## 官方校准

北京市人民政府公开的典型建议把标题、建议时间和建议内容拆成页面字段，紧凑正文可以只交代实际情况和具体建议；上海市人民建议规定同时要求主题、问题、办法、理由依据和建议人信息等要素，但允许书信、邮件、电话、走访和网上信箱等不同载体；牡丹江市指南则给出适合独立成文建议件的标题、建议人信息和问题—依据—办法结构。三者共同支持“按交付载体分配形式要素”，不支持按固定字符数决定壳层。

详见 [`official-corpus.md`](official-corpus.md)。

## 真实写稿

五家低成本 provider 均以 `max` 思考强度运行：Alibaba Token Plan 2、Alibaba Token Plan、Ollama Cloud DeepSeek V4 Flash 0731、OpenCode Go DeepSeek V4 Flash、MiniMax M3。

- 基线：25/25 技术有效。
- R1 意见建议专叶：23 份落盘，22 份技术有效；Ollama 1 份全局 Skill 污染无效，MiniMax 通知题在单题上限后发生 Windows runner 回收卡死，后两题明确缺失且未补跑。
- R1 通用短稿专叶：25 份落盘，24 份技术有效；Ollama 正式长意见控制题全局 Skill 污染无效。
- R2 意见建议专叶：25/25 技术有效。
- R3 意见建议专叶：25/25 技术有效。
- 合计 123 份真实写稿输出，其中 121 份技术洁净、2 份污染无效；另有 2 个明确缺项。原稿、trace、provider JSON 和汇总均保存在忽略目录 `output/short-advice-routing-r1/`。

## R1 放置消融

基线的正文外包装为：平台栏 2/5、邮件正文 1/5、独立成文短意见 0/5。

- 意见建议专叶臂为 3/5、1/5、0/5。只看实际读取目标叶的样本，Alibaba 1 邮件题改善；MiniMax 平台题和 Ollama 邮件题回退，净为 1 改善、2 回退。
- 通用短稿专叶臂为 1/5、1/5、1/5。只看实际读取目标叶的样本，OpenCode 平台题改善；Alibaba 2 独立成文题新增技能说明和横线，净为 1 改善、1 回退。
- 正向题目标叶读取次数为意见建议专叶 10/15、通用短稿专叶 7/15。通知控制题读取新增句为意见建议专叶 0、通用短稿专叶 2/5。

因此 R1 两臂都拒绝；尤其不继续把意见建议语义写入通用短稿叶。

## R2 最小收窄

R2 只在意见建议专叶把候选收窄为“平台栏、邮件正文回答第一字起即为可粘贴正文”，显式点名技能说明、`以下为/正文如下`、自检和横线，独立成文仍保留完整形态。

R2 平台栏包装从基线 2/5 降为 1/5，但没有通过直接可用性门：

- 实际读取候选叶的 Ollama、OpenCode 平台题去掉了基线包装；Alibaba 2 平台题却从正文直出回退为`建议内容如下，可直接粘贴`。
- Alibaba 2 邮件题新增大段方法说明、`成稿如下`和横线。
- Ollama 独立成文短意见新增英文说明、成稿说明和`正文`引导；正式长意见控制题又新增技能说明、横线、Markdown 标题及文后邀约。
- Alibaba 1 正式长意见控制题新增技能说明和`以下为`引导。

上述回退均发生在实际读取候选意见建议叶的样本，直接命中本原子的交付形态，不能归为无关文采波动。R2 终止，不继续堆同义禁令。

## R3 正向结构重试

R3 不再增加包装禁令，只把意见建议专叶原有结构句改为正向载体关系：完整独立稿按材料保留题名、建议方和日期；平台建议栏、邮件正文将实际情况和具体建议连续成文，不另起“问题”“建议”两层。五家同题25/25技术有效，目标叶读取为平台栏3/5、邮件4/5、独立成文3/5。

人工只统计实际读取候选叶且与交付形态直接相关的变化：

- Ollama平台栏、Alibaba 1邮件正文由包装转为直接正文，共2项改善；
- Alibaba 2平台栏由直接正文回退为“根据材料按……成稿”并附横线；Ollama邮件新增“以下为可直接发送”；OpenCode邮件新增较长Skill/处理过程，共3项包装回退；
- Alibaba 2独立成文稿另补“总体便利”、附件（略）、持续关注和适时反馈，属于材料外扩展。

OpenCode平台题虽然改善，但没有读取目标叶；MiniMax平台题虽回退，也没有读取目标叶，均不拿来替候选加减票。R3为2项目标改善、3项目标包装回退并有1项材料外扩展，净结果仍为负。该正向结构路径据此终止，不换一种近义句继续重试。

## 保留能力与后续边界

基线已经能区分主要载体：平台栏 3/5、邮件正文 4/5 直接交付，独立成文短意见 5/5 保留标题、给定建议方和日期；短通知 5/5 保持已批准通知语气。未逐字出现`尚未决定`不单独判失败，只要仍使用`建议研究`且没有把功能写成已经上线。

短意见继续由现有意见建议文种语义和通用短稿交付规则共同覆盖。既不把短意见塞进通用短稿页，也不在意见建议页增加载体结构提示。残余正文外包装归既有 `CL-001-NOHK-R2` 通用“只交正文”原子。只有新的真实用户样本跨 provider 复现“短意见被套完整壳层”或“独立成文短意见被剥壳”时，才重新开启本原子。
