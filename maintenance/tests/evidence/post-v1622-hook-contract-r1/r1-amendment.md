# HK-009 R1 冷审修正

日期：2026-08-31。

固定基线、原子边界和 25 秒 Stop 总预算继续以 [`preregister.md`](preregister.md) 为准。本修正只处理候选实现冷审发现的回退风险，不扩大版本范围。

## 新发现的候选独有风险

- `emit` 子进程失败后，候选曾直接在宿主进程内调用 `review_gate.emit_transaction()`。该函数会把正文写入 stdout，而 host adapter 随后还会写 JSON Hook 响应，可能形成“正文 + JSON”的非法宿主协议输出。
- 候选曾在已选 D1 无法可信恢复时继续调用 `emergency_d0()`，可能把 `TERMINAL_D1` 静默降为 D0。D0 是安全原稿，但不是该事务已经锁定的交付选择，不能冒充已选终稿。

## 修正边界与验收

1. 进程内恢复必须调用无 stdout 副作用的可信选择解析入口；host adapter 主入口 stdout 必须仍能整体解析为单一 JSON 对象。
2. `TERMINAL_D1` 的选择证据缺失或损坏时停止自动交付并立即脱敏，不输出 D0、D1、核验包或内部状态。
3. 只有事务明确处于 `TERMINAL_D0 / selected=D0` 且 D0 hash 匹配时，才允许在 `emit` 子进程失败后恢复 D0、请求一次精确回显并完成脱敏。
4. 不修改 25 秒总预算、单子进程 20 秒上限、宿主 30 秒 Stop 上限、能力路由或写稿语义。

验证先用上述三条行为测试复现候选失败，再做最小实现修正；任何协议污染或 D1 降级都终止本候选。
