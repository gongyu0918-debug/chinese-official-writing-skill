关于在版慎通智能审校系统增加公文AI写作功能的立项申请

版慎通智能审校系统拟增加公文AI写作功能，包括AI智能写作、红头文件生成、格式修复、AI味审校等，现申请立项。

一、立项必要性

系统现有图书审校功能比较完善，但不具备写稿功能，只能对已有稿件进行审校，用户对增加写稿功能呼声较高。增加公文AI写作功能后，系统可在审校之外承担公文起草，用户群体由图书审校延伸至机关、企业、事业单位等公文写作场景，形成较为广泛的垂直市场。

二、写稿需求与方案验证情况

拟采用的公文写作 Skill 已在 skillhub 上线，累计下载 10.5 万次，位列 Skill 下载榜前 50 名，在公文写作领域排名第一；在 clawhub 下载 7k 次，趋势榜长期保持前 100 名，同为公文写作领域第一。10.5 万次下载表明，用户对专业 AI 公文写作能力的需求量较大。该 Skill 的变体作品公文写作智能体项目获江西出版集团首届 AI 大赛专业组第三名。经指纹检测，深知、WPS 等公司均有复用该 Skill 代码建设公文写作系统的迹象，复用部分集中在去 AI 味模块、短稿路由模块和检测脚本模块。该 Skill 项目地址为 https://skillhub.cn/skills/user_f3d82da7/chinese-official-writing。

三、实现方式与改造内容

公文 AI 写作功能有两种实现形式，一是完整的 workflow agent，二是受社区广泛下载的 Skill。结合市场行情和系统实际情况判断，采用 Skill 方案更为适配。

该 Skill 经测试已对各家 harness 进行适配，由 references、scripts、hooks 三个模块构成：references 按公文和事务性稿件类型做规则路由，每次写稿热加载规则平均压在 14K token，远低于其他 Skill 100K token 的平均水平；hooks 在成稿后检测字数一致性、提纲与正文一致性、篇幅一致性、AI 味词汇和 prompt 遵循等情况，对 agent 能够发现的错误返回模型重改，三轮 react 下最终成稿错误率在 1% 左右；scripts 清洗显式 AI 味错误、Markdown 残留等，并对格式进行校验。三个模块的具体机制和研发流程见附件。

线上 Skill 为开源方案，需进行闭源改造，并完成对版慎通智能审校系统的适配。项目目前采用 CODEX 开发，由个人项目转为公司项目，需对项目进行相应改造。

四、开发费用

按目前的开发流程，项目日均消耗 token 10 亿，其中主力开发模型 7 亿、测试模型 3 亿。根据开发进度，项目前期需订阅 codex pro 20X 作为主力开发工具，每月 1600 元，并辅以适量 Alibaba token plan，用于 qwen 模型适配；后续可视需要转为每月 900 元的 codex pro 5X。

附件：公文AI写作Skill技术方案说明

公文AI写作Skill技术方案说明

一、总体情况

该 Skill 用于中文公文和事务性稿件的写作，经测试已对各家 harness 进行适配。项目地址：https://skillhub.cn/skills/user_f3d82da7/chinese-official-writing。Skill 分为 references、scripts、hooks 三个模块，工作流程为 references 完成规则路由和成稿，hooks 对成稿做微调检测，scripts 做清洗和格式校验。

二、references 模块

references 模块对公文和事务性稿件做了专门路由，规则来自真实写稿和互联网成熟公文的总结，写作按从大到小、从粗到细的方式展开，是一个成熟、复杂的公文写作规则路由系统。每次写稿热加载的规则平均压在 14K token，远低于其他 Skill 100K token 的平均水平，可节约 token 成本。

三、hooks 模块

references 成稿后，由 hooks 做微调检测，检测项包括字数一致性、提纲与正文一致性、篇幅一致性、AI 味词汇、prompt 遵循等，主要关注提纲—正文、成稿—交付两个生命周期。对 agent 能够发现的错误，返回模型进行重改。在三轮 react 下，最终成稿错误率在 1% 左右。

四、scripts 模块

scripts 模块针对显式 AI 味错误、Markdown 残留等进行清洗，并对格式进行校验。

五、研发流程

项目采用 CODEX 开发，构建 LOOP 为：idea—登记为 openspec 需求—独立 worktree 预先修改—真实写稿 A/B 测试—通过后补工程和胶水—并入 main；测试不通过时，总结经验另开新的 worktree。该流程下日均消耗 token 10 亿，其中主力开发模型 7 亿、测试模型 3 亿。
