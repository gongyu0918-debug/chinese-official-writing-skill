根代理核对全部12次调用的实际final、实际文件及工具轨迹，并复核两份独立匿名报告。选择精简混合的有限路由和组织收益，不宣称总体文采或正确率全面提高。

## 必须保留的问题

- Qwen旧复杂稿把日均10亿、主力7亿、测试3亿写成100亿、70亿、30亿，文件与final都有。这是明确数字错误，修正范围集中；不能据此推定旧规则必然诱发数量换算错误。
- Qwen混合普通稿省略了材料已给的工期未定。原路径差错稿的实际正文保留该状态。候选补回一句即可，不能为显得紧凑删掉有用的已知状态。
- MiniMax混合普通稿的培训人数增长、已验证候补排序和提醒发送等细则没有充分材料；“下一步将……排定开发与上线节奏”也给用户补了确定安排。旧稿的“具备接入条件”有语气强弱争议。两侧均可局部改进，原稿事实方面略优，候选组织与交付更紧凑。
- MiniMax复杂两稿都需实质修改：旧稿已完成研究、既有数据分级与留痕能力、确认复用；候选具体分群反馈、按量结算、公司现有团队承担且不另收费。候选把规则热加载14K写成单次总消耗也是口径错误。两侧自拟项目组与当日日期均应去掉或取得材料，不因称作草稿就自动成为已给事实。
- 两侧复杂MiniMax稿都已在正文介绍技术，不能说完全没有技术内容；问题是另列附件却未实际落实附件形态，以及把编排建议写进正文。可以整理现有内容，不应补造技术清单。

## 合理分析与交付的边界

沿用已有页面减少入口切换，提醒便于及时归还，以及写作与审校组合有助于拓展场景，均可作为有据分析保留。宽泛的“公司领导”等主送称谓不单独用于否定整稿；明确捏造承担团队、已完成步骤或数字与之不同。

复杂原题允许讨论技术细节放在正文还是附件，正常文后说明不违规。两道短题明确“我只想要正文”，其机检前言或文件介绍仍需清理；这与全局分析许可无关，也不因一行包装就否定整套规则。

独立评阅建议两份Qwen预算稿补明后续费用未获批，根代理认为这样更完整；原稿已经写明本次不申请后续费用，并以申请语气请批，没有反写成已批准，不将这处省略等同于状态升级。两稿正确区分四个月购买额度与未知开发工期，预算1460也准确。

Qwen旧复杂稿附件增加具体路由步骤与能力范围，独立评阅认为需核实。根代理将其列为来源口径提醒：模型实际读过用于写作的Skill页面，但这些页面的能力不自动等同于材料所述项目的既有实现。该稿取舍主要由明确的十倍数字错误决定，不依赖这项争议。

## 为什么保留组合

新专页让复杂申请的当前需求、方案依据、费用和技术附件集中起来；旧规则的紧凑组织能在普通增项和预算题形成完整自然段。两种模型的同批表现各有长短，未显示总体质量优势，但在可用稿件上实现了实际旁支读取减少，且没有以禁止正常原因分析、禁算预算或机械截短获得表面安全。

因此保留已测试的组合，不再逐个追加禁令或扩大评测矩阵。现有失败继续作为首稿事实和同稿Hook复核的真实材料；本轮不声称虚构已被Hook压住，不报百篇或多版稳定率。
