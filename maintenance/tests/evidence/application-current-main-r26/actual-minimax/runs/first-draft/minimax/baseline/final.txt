**关于"技术细节放在正文还是附件"的判断**
按当前立项申请的层级和读者需要,采用 **"正文概述 + 附件详单"** 的折中处理:
- 在正文"项目方案—技术细节"小节里概述 references / scripts / hooks 三大模块的功能定位、加载成本与质量控制(三轮 ReAct 下成稿错误率约 1%),让决策层不打开附件也能判断技术路线是否成立。
- references / scripts / hooks 三大模块的函数清单、规则条目数与提示词模板放到附件,避免在立项申请正文里堆技术清单冲淡论证。

理由:技术细节放在中间讲解,有助于论证立项必要性和可行性;但全量清单放在正文会让立项申请读起来像可研摘要,分散对必要性、费用、合规等关键决策点的注意力。
