# R7 联网补证与判读校准

查阅日期：2026-09-13。用途是核对拿不准的写作惯例、需求展开及推断强度，不是给普通稿件增加一套行业合规门槛。本轮未把互联网材料中的项目事实写入测试稿件。

## 查阅资料与适用范围

- [NASA：如何写好需求](https://www.nasa.gov/reference/appendix-c-how-to-write-a-good-requirement/)：需求应可理解、可验证并追溯到目标，假设可以记录并在基线确认前核实；同时关注过紧公差与不必要实现约束。可据此接受任务内的合理需求细化及讨论方案，不套用其全部航天工程文档、责任和时间要求。
- [财政部《政府采购需求管理办法》公开文本](https://fgw.sh.gov.cn/ys-zfcg-1.3.1.1/20240325/64ee177fe6944c2fbaa409c3ec55a78f.html)：采购需求包括目标所需的技术和商务要求，验收与相应要求对应。本轮借鉴需求功能及可核对性，普通技术附件、需求确认稿不直接套用完整政府采购文件的所有栏目与程序；未据此完成全量现行法规核验。
- [Microsoft API Guidelines 开源项目](https://github.com/microsoft/api-guidelines)及[Azure API 指南](https://github.com/microsoft/api-guidelines/blob/vNext/azure/Guidelines.md)：接口规范具有明确的服务适用范围，技术选择和约定可以作为设计讨论内容。Azure 的强制约定不是任意用户项目的既定参数，尤其不能据模板改变既有账号权限。
- [吴忠住建：老旧小区改造的常见生活影响](https://www.wuzhong.gov.cn/ztzl/zcwdpt/wzszfhcxjsj/202311/t20231123_4361230.html)：独立复核在网页工具超时后通过同一官方 URL 读到正文，支持施工出行安全及老人、儿童保护等一般提醒；不据该网页推定本案的具体现场、施工措施或事故。
- [广州市博物馆规定](https://www.thnet.gov.cn/thqzdlyxxgkzl/wh/bwggwgk/zcfg/content/post_9522812.html)：讲解应面向不同观众，兼顾准确与生动。用于支持受众化解释和自然讲述，不把博物馆参观规定直接变成企业展区已定规则。
- [Microsoft .NET：Instructions Hygiene](https://devblogs.microsoft.com/dotnet/instructions-hygiene-what-frontier-models-still-need-you-to-say/)：指令应集中于无法从上下文稳定推知的事项，减少通用警告，把细节指向有明确职责的资料；强制语气用于真正的硬边界。这是软件指令工程经验，可借鉴于此次重构，但不是本 Skill 写稿质量已改善的实验证据。

## 本轮判读原则

1. 正常衔接、一般目的、常识安全提醒和有据影响分析，不因材料没逐句写出而判错。对施工工具进出、合理安全培训提醒、确认参数写入清单等表述，检查其实际功能和确定程度，不机械当作新增事实或程序。
2. 技术需求确认稿可以包含可追溯的细化、建议和假设。结合整份请求与草稿状态判断，不要求每一句都重复“拟”；共同核对、不同账号测试、联调记录内容等有正常编制空间。
3. 需要区分“某指标可能过强或需澄清”与“捏造已经实现的结果”。用语不够明确时提出修改建议，不能一律记为事实硬回退。
4. 对材料明确约束、实际事实状态、权限范围及实质履约范围的改变，仍按具体证据判断。特别具体的现场屏幕内容、已发生经历、未经授权日期，以及将现有权限替换成另一套规则，不能仅凭行业模板获得依据。
5. 保留原稿和初审意见，另记校准，不篡改历史胜负；初审相对较弱不等于规则造成回退。新一轮匿名包仅替换运行目录与版本标识，保留过程旁白，生成文件与最终消息分开判断。

独立联网校准已完成，见 [T01–T08 逐项报告](inference-calibration.md)。报告仅读取匿名稿件及指定一手来源，未读取身份映射和产品规则，也没有判版本胜负或因果。原始初审保留，后续验收按 [根任务校准](result.md) 区分已纠正的尺度与仍需验证的问题。
