# CR-001-R2 最小回退修复预登记

## R1 实际结果

三家 provider 共12份真实稿全部技术有效。机器必含项报8次，但人工逐稿复核后只保留与目标有关的判断：

- 讲话基线/候选各3份，短稿页读取均为1/3，R1未形成共性路由收益；
- Alibaba2 候选把材料中的“2026年上半年”弱化为“今年上半年”，属于候选独有的时间锚精度回退；
- MiniMax 候选虽更长，但新增平台运维牵头、讨论落实等材料外安排，不能用篇幅增加抵销；
- 三份建议信均正确区分审核部门和平台运营方处置权，以“建议研究”保持未决状态；不要求逐字重复“尚未决定”；
- 三份征求意见复函均保留主送、来文、修改建议、其他条款无意见、落款和日期。MiniMax 的代码块包装是单家交付噪声，不构成共性路由缺陷。

因此：`CR-001-R1 = SUPERSEDED_BY_R2`；`CR-002 = BASELINE_RETAINED / WAIT_NEW_COUNTEREXAMPLE`。

## R2 单原子

仍只修改短稿参考资料表的一句，在 R1 同义修复基础上增加一个直接边界：用户要求完整文稿或材料较多时，不因只有篇幅上限而读取短稿页。不开新 reference，不改入口第26行，不改 Hook、description 或其他文种。

## 真实写稿

- 原讲话题只重跑 R2 候选，和固定 R1 基线比较；
- 新增一题材料密集、只有1200字上限的政务数据共享工作情况报告，运行固定基线/R2候选 A/B；
- 首轮仍用 Alibaba Token Plan 2、OpenCode Go、MiniMax 三家低成本 provider，`max`；技术失败才启用登记的两家备用。

## 判定

- 两个候选任务不得因只有上限读取短稿页；若模型明确读取，须检查是否另有“简短正文”触发，不机械判错；
- 必须保留材料中的年份、数字、未决状态和文种主体结构；
- 合理原因、直接作用、总结和条件性后续不算外扩；具体责任分工、时间表、程序、决定和既成成效仍需材料支持；
- 至少两家有效 provider 在原讲话或新报告上出现可归因的路由/结构改善，且候选无共同或独有硬回退，才选定；否则终止，不留 `HOLD`。
