# WR-009 文后提示与正文分区真实结果

## 目标

验证允许文后提示时，提示不会成为正文末段、连续章节或 Markdown 包装块。题面要求根据同一组采购材料先完成请示正文，再短列影响正式报送的主送机关、申请单位和成文日期缺口。

## 执行

- 模型：`opencode-go/deepseek-v4-flash`
- 档位：`max`
- 基线：`main@5b42946f2c057f9d37eb420ab5bccea23ece9c59`
- 候选改动：只修改 `references/information-selection.md`，另补 `prose_lint.py` 的高信号分区检查。
- 首次基线外层会话只留下初始化记录、没有 stream 或终稿，记为环境无效；随后以同一题面完成一组有效基线/候选，不把无效调用计入结果。

## 结果

基线终稿 SHA-256：`0ba0a8068278f46edf7c2b73f6c9f3cdcc8a61e4a219433fc50397fb0366b78e`。正文结束后使用 `---` 横线，再写“影响正式报送的待确认事项”，分区可见但带 Markdown 包装。

候选终稿 SHA-256：`cb6c37faf1b85eef74719baa5b90253ef28c38619742eb7f4b59797728dfd85b`。正文以“妥否，请批示”完整结束，空一行后另起 `待确认事项（正文外）：`，没有沿用正文层级号或横线包装，目标功能通过。

候选 lint 回放把基线横线分区判为 `external-note-boundary` 高风险；候选不再出现该 finding。lint 同时补认真实出现的“影响正式报送的待确认事项”标题变体，使提示后的编号项不再被当作正文扫描。

候选标题出现 Markdown 加粗，属于同一模型的独立格式波动，不是文后提示分区规则引入的问题，本原子不借机扩张范围。

## 边界

文后提示内容仍由语义层按文种、材料和输出模式选择。lint 只检查提示区是否独立、无正文层级序号、与正文间有空行且不用 Markdown 横线；Hook 不生成缺项清单，交付洁净度能力只可能在用户未要求时清理多余包装。
