# SkillHub 公文写作竞品研究

日期：2026-09-08。状态：研究完成，建议尚未真实写稿验证或准入。基线：本地 main `c7778f2627d025bc34f106cb8cb74bcf03fb011b`，同时区分已发布 `v1.6.30`；不将 main 的后续规则当作已发行功能。

## 优先结论：具体文种理解，而非工程路线

用户明确本轮应寻找竞品对专业写作的更好理解，不以架构差异或无法判定优劣的路线充数。重新深入文种页后，最值得借鉴的是：经验交流材料的可借鉴做法、普通工作人员发言的权责视角、面向领导的汇报如何重排事实。前两项适合优先做真实写稿原子；汇报属于现有方向的细化。

这些是源码中可以明确比较的专业指导差异，尚非真实成稿胜率。立项增项申请目前未发现更优的竞品规则；本项目已对原因、项目基础、新增内容与费用的关系作出更具体规定，不应为了学习竞品退回通用模板。

### A. 经验交流材料：让别人学会做法，而不是再写一份工作总结

来源：[govwriting](https://skillhub.cn/skills/user_087fbff2/govwriting)，`07-事务公文下.md:195-273`。

**更专业在哪里：**它把这类材料的读者需求放在“能学习怎样做”上，要求突出具体做法及可操作的经验，区别于全面交代本单位完成了哪些工作。关键不是增加一个“经验启示”标题，而是解释这项做法为什么有用、具体如何实施。

**我们哪里还薄：**当前 `genre-playbook-work-summary.md:5-11` 主要规定总结骨架、结果及计划边界；`argument-chains.md:29-39` 也主要是报告和总结的一般顺序。检索当前 references 未见同样具体的经验交流专项指导。已有“事实支撑”不能代替这种文种目的上的区分。

**具体例子（本报告构造，用于解释差异，不是竞品实测稿）：**材料给定“过去三个科室分别要求填表，现统一一次采集、按职责共享；重复填报减少”，用户说“帮我整理一篇到兄弟单位交流的材料”。一般总结可能围绕完成整合及取得变化展开。经验交流更应把原来为何重复、怎样将重复采集改为共享、这种做法与重复填报减少的关系讲清，让听者看懂可借鉴的操作。这里不需要增加制度名称、责任岗位或新数据。

**建议吸收：**按材料说明具体问题、对应做法、已知变化及可借鉴的方法；已有适用条件一并说明。不要照搬竞品偏好的排名、首创或必有对比数字，也不要替其他单位保证复制效果。此项是明确的文种指导增益候选。

### B. 普通工作人员发言：内容应受本人身份与职责约束

来源：[ydxc0511](https://skillhub.cn/skills/user_0a48355b/ydxc0511)，`SKILL.md:219-221,245`，`references/staff-speech-genre-templates.md:161-163`。

**更专业在哪里：**它明确区分一线工作人员的小型会议发言与领导讲话。普通工作人员主要谈个人理解、岗位经历及本人能做的事，通常不承担向各部门部署工作的功能。这比简单要求语气谦逊更具体：改变的是正文内容和说话权限。

**我们哪里还薄：**`genre-playbooks.md:40-45` 与 `argument-chains.md:89-99` 把讲话、致辞、述职放在通用框架下，虽要求身份、场合和听众匹配，却没有同样明确地展开个人发言的内容重心。不能据此断言当前模型一定写错，但专业提示的精细程度确有区别。

**具体例子（构造说明）：**用户是窗口经办人员，材料给“有时向办事人解释所需材料不够清楚，准备先整理常见疑问”，要求写服务作风交流发言。应谈自己对解释工作和办事体验的认识，再承接整理常见疑问的打算；若写成“各部门要建立考核机制、强化督导问责”，就把个人发言写成了领导部署。只改几个敬谦词解决不了这个问题。

**建议吸收：**让岗位身份决定可谈内容和行动范围；有岗位材料时具体写，没有时不强行造一条承诺。无需照搬固定结构、典故、篇幅和强制补材料步骤。此项适合作为个人心得、青年交流、研讨发言的局部规则候选。

### C. 向领导汇报：把发生顺序转成读者需要的信息顺序

来源：[govwriting](https://skillhub.cn/skills/user_087fbff2/govwriting)，`05-事务公文上.md:16-39`。

**更专业在哪里：**它给出材料取舍的方法：组织过程可简述，重要现状、变化和问题应醒目，按事项整理而不机械复述月份。这是帮助作者从“我做过哪些事”转换为“读者需要先知道什么”。

**对比与场景：**我们的 `argument-chains.md:31-37` 已要求总体判断，新增价值只是进一步讲清如何重排。比如材料列了三月开会、四月摸排、五月协调，最后才说仍有两项跨部门问题，向领导汇报时可以先让读者看到当前进展和这两项问题，再交代有关做法。事故经过、办理经过等任务仍可能需要时间顺序，不能一律套用。

此项值得优化，但优先级低于 A、B：它是把已有规则讲透，不是缺了一整类专业理解。

### 立项增项申请：本轮没有找到可替换现有规则的更优理解

深知申请页主要列通用申请结构；govwriting 的请示范例说明任务、用途与预算；official-document-skill 的 `SKILL.md:381-389` 给出一般缘由和请求顺序。这些没有超过本项目 `genre-playbook-project-application.md:7-17` 对“用户需要是增项原因、原成果是实施基础、增项不是重建整个项目”的区分。

因此不建议用竞品通用模板替换当前申请规则。若后续发现首稿仍丢原因，应对具体失败稿继续修正并验证，不能把竞品没有更好方案等同于本项目问题已经解决。

## 附录：工具与流程观察（不作为本轮优先借鉴结论）

### 1. 来源对应具体正文，正式稿与核验材料分开

深知 `scripts/source_note_html.py:108-170` 将正文、来源链接、原文摘录、对应段落等转成独立 HTML；`reference/revision_workflow.md:27-34` 规定检索结果复用，引用发生变化才更新报告。这比仅在文后列链接更有操作性。

本项目 `references/external-research.md:7` 已要求说明来源及使用位置，因此新增价值主要在交付和引用变化的跟踪，不是重写事实规则。可优先尝试只对容易出错的金额、工期、主体、审批状态建立内部来源对应，普通用户仍直接收到稿件；需要核验时再给简短依据或独立报告。

限制：该脚本 `180-185` 只检查有素材时正文是否至少存在一个编号角标，不能据此认定每个事实都获支持。其 SKILL 第 351 行把检索召回默认视作可信并限制提示核验，不宜采用：搜索到来源与来源支持本句是两回事。

### 2. 路由写清触发条件，而不只是把长文拆成目录

`ydxc0511/SKILL.md:44-71` 区分任务，只有需要范文时选读一个对应文件，并隔离原范文事实。这是具体的加载约束。govwriting 的小入口主要罗列模块与素材索引，没有同样清楚的触发、选取和停止条件。

对本项目可以检查高频路由是否存在同一任务重复读相近页；若存在，逐个减少重复读取，用真实自然提示验证。不能依据文件更短直接认定收益，也不要把现有范文隔离规则再抄一遍。其余入口里的修炼、成长和营销内容不应进入每次写作路径。

### 3. 让论证随已有事实展开，评价随证据控制

`official-document-skill/SKILL.md:160-170,198-208` 强调按事实推进，先写问题表现及对应行动、完成事实后再谈经验，避免用连接词和宏大评价代替内容。这可以用于检视立项申请是否围绕同一诉求展开。

适合验证的自然任务是：在已有项目基础上增加服务，材料已给原项目情况和新增需求时，首稿能否写清“现有基础—新需求—本次申请”的关系；缺少既有成效时，不强夸原项目。允许结合给定事实与常识分析必要性，禁止顺势新增预算、工期、审核流程或具体调查结果。

这与本项目已验证的全局有据分析和 R26 混合规则相近，不能直接证明替换现有规则更优。竞品第 352-360 行的具象化范例加入具体流程问题及措施，若脱离其材料依据照搬，反而可能放大虚构。

### 4. 改稿只重做受影响部分，保护已有文档对象

`ydxc0511/SKILL.md:315` 要求条件变化时保留未受影响结果；深知进一步明确复用搜索结果。`gov-doc-format/format_body.py:79-87,106-120` 检测图片相关 XML 并跳过相应段落，是真实的小范围保护实现。

本项目 `references/workflow.md:74-89,143` 已有最新底稿、结构修改粒度及 Word 保留要求。值得继续验证的是这些规则是否真正保持参与，是否会在第五、六版重新引入删除项，而非新增一套六步流程。图片保护属于文件交付专项，不应扩大为当前申请类写稿的必需依赖。

## 不建议照搬的设计及可复核问题

- **七专家不等于七个独立审稿代理。** official-document-workflow 的入口 `12-20` 明确是逻辑角色，包内现有脚本用于 DOCX 生成、重排与检查。本轮没有发现独立模型调用与汇聚实现；不能据角色数量给稳定性加分。
- **有检查器不等于事实门禁可靠。** 国企新闻稿 `scripts/validate_news.py:127-155` 将正文数字与素材裸数字集合比较，忽略单位、主体和状态；`47,86-104` 又把“共”等词当作本地数据检查的跳过条件。按代码可推知，素材“12人参加”与正文“共投入12万元”的数字部分会匹配，两项检查不足以发现该错配。这是静态反例，未执行该脚本，也不声称整套写作流程实际必然放行。约、预计等限定词也可能触发错误级提示，需防止正确状态被删。
- **格式检查的 pass 可能只覆盖少量样本。** official-document-workflow 的 `scripts/check_format.py:28-29,85-136` 检查首节及一个正文样本，部分属性不可读时不产生检查项；格式重排 `scripts/format_docx.py:36-74` 会统一覆盖诸多段落和 run 属性。gov-doc-format 的 `validate_doc.py:233-238` 跳过非右对齐日期，`281-288` 只查首节。这些不能用作整份长文格式已验证的证明。
- **修订例子本身可能教出虚构。** official-doc-proofread 的 `SKILL.md:442-457` 给出调整申请金额、补充差额以及改写具体会议层级等建议，虽部分附有语境提示，仍不宜自动实施。应指出冲突并依据实际材料处理，不能为了前后一致自选一个金额或程序。
- **流程齐全可能阻碍正常写稿。** govwriting `02-写前准备.md:15-27` 三问答不上来先不写；ydxc0511 `SKILL.md:317,343-351` 六步不可跳并要求追问后沉淀记忆；official-document-skill `39-47` 默认缺项占位。这些与用户直接成稿的体验不合。
- **自评分数不能替代真实质量。** press-release-writer-cn 的 `references/quality-gate.md` 是提示词评分标准，包内没有对应独立执行器；`references/evidence-and-boundaries.md:10` 将常识和模型推演统一归为假设，可能抑制本项目允许的有据原因分析。
- **供应商和文件交付依赖要与任务分离。** 深知的大入口含初始化、搜索服务配置、默认 Word 交付等流程；应学习具体能力，不整体引入到普通聊天写稿路径。

## 附录：此前工程方向建议（保留记录，低于上述文种候选）

第一优先：现有同稿事实复核中，针对金额、工期、主体、事项状态，检验能否准确找到支持材料，保留合理原因分析；不先增加新评分体系或更多审稿角色。使用同一 D0 比较 Hook 开关，另用自然语言任务观察首稿质量，明确区分两类证据。

第二优先：同一申请连续修改 5—7 版，包含补原因、改金额、删除事项、压缩和局部改口吻，观察未受影响段落及旧检索材料是否被正确保留或淘汰。每个错误分别记为事实、指令执行、表达或交付问题；不要把少量样本折算成通用稳定率。

第三优先：若读取轨迹证明确有重复加载，再做一个路由原子，与当前基线用相同自然提示和强弱模型真实写稿对照。量化读取文件、字节及重读次数，同时检查结构自然、事实状态和可直接使用程度。

本轮未修改产品、未运行真实写稿、未安装竞品，因此上述均为待验证研究建议。没有发现足以直接整体替换现有申请 reference 的证据。独立工作树仅提交本报告、来源清单和规格索引；不合 main、不推送、不发布。
