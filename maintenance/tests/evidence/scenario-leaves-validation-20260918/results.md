# 专项规则验证与采纳

本轮在main `70d241ca`（2.0.4）上构建最小候选 `d0fec357`，以 `1cffe2e4` 绑定原生快照。结论是**纳入经费预算、信息化建设两张附加页及采购专项核对、整改报告补强；暂缓采购更正公告骨架增量**。这是场景能力补强，不宣称普遍降低费用或每个文种都变好。未推送、发布或更新桌面包。

## 实际验证

- 首轮16对、32次原生写稿；另对Qwen采购审改、DeepSeek整改汇总各复测1对，共36次、18对。所有调用技术有效，无超时、降档或替换通道，原始不足保留。
- 写稿通道为 `alibaba-token-plan/qwen3.8-flash`、`command-code/deepseek-deepseek-v4.1-flash`，均max。隔离的Codex CLI，明文stdin，两个版本同题、新上下文、同工具权限；无Pro、Hook或维护规范参与。
- 独立规则审阅及四批匿名稿件评阅由 `alibaba-token-plan-2/deepseek-v4.1-flash` max完成。它看不到版本/通道和映射。原判、过严判断、串稿引用及维护者复核分开保留。
- 盲审原判：首轮候选3优、11平、2劣；两对复测均相当。不是通过率，也不以多数票替代对原文的判断。对应记录见 [复核说明](blind-adjudication.md)。

## 逐项决定

| 内容 | 真实观察 | 决定 |
| --- | --- | --- |
| 经费预算 | B1/B2/I2相关5个候选均实际读到新页；总额、年度上限、折扣计价、本次申请额保持正确。正文多数持平，部分候选更长；不能宣称本页单独显著提质 | 纳入400字符附加页，按多项费用/分期口径需要选读 |
| 信息化建设与运维 | I1/I2四个候选均读到新页；两个I1候选不再读取方案主叶来补信息化规则；保留两组40多个部门各自口径，组合题保留原查询和服务器、分清建设与运维 | 纳入450字符附加页；信息化仍按稿件用途选择主叶 |
| 采购专项核对 | 价格含项与已计费安装服务对应验收有具体收益。Qwen首次候选过度展开，复测回到两段，与基线相当，未形成稳定的候选特有回退 | 保留两条价格/验收对应规则，不扩展一套采购流程 |
| 整改报告 | 问题、事项、单位三类口径及69/25/9不同状态均保留；小稿可提出合理建议。首次汇总候选过长且补“分年度”，复测未重现。最终消息偶发加粗另记 | 保留统计口径、阶段证据和合理建议规则，维持已选主文种 |
| 更正公告 | Qwen候选减少正文占位，但把原公告内容与后来签约供货混写；另一通道持平，独立收益不足 | 撤回本次公告页增量，原实现保留；实验和原稿不删除 |
| 少读控制 | 两把办公椅申请、无关会议通知都未读预算/信息化页；原因、金额、参会要素完整 | 控制路径保留 |

终选只改5个产品文件，净增加1143字符：首页、description、共性规则、抗AI、脚本、Hooks保持基线。撤回的公告页与联合候选不同，其余产品文件一致。18对中有15对候选实际读取页未涉及撤回文件，读到的产品内容与终选一致；其余3对仅作联合实验记录，不冒充终选覆盖。见 [读页对应](retained-path-coverage.json)、[快照范围](snapshot-scope.json)。

## 风险与范围

- 字段缺项、合理原因、拟议做法、当天落款不因未逐字来自材料而机械判错。1200元另行报价可按本次总安装费理解；94项已完成或阶段达标不等于把全部完成率写成91.3%。
- 规则冷审有把“附加页跨文种使用”误判为冲突的意见，已逐条解释，未照搬成新的限制。没有发现新增强制循环或不可达路径。
- 两臂都有偶发正文外自述、冗余提示及多读邻近主叶。另发现基线“××”占位漏检、扫描后消息再加粗；本轮仅留证，不扩为脚本/首页重构，详见 [既有风险](observed-existing-risks.md)。
- 该矩阵覆盖本次四组改动、组合应用与少读控制，不能外推到所有部门模板或所有模型。未测试Skill自动发现率，也未验证新Hook生命周期。
