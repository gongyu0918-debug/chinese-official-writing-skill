# 开场称谓排序：真实写稿复核

## 范围与比较口径

这是新增功能，不是减载实验。针对演讲、讲话、致辞、会议主持开头的具体职务、姓名与泛称排序；分段分行、通用敬称改革不在本原子中。用户已确认：需点名的具体人物先于泛称；同组依据已知职务与正副；确认的模板、礼宾次序优先；未知跨单位次序不猜级别。这是本项目功能约定，不宣称所有场合存在统一礼宾标准。

基线是完整本地 main `dafc35f9aad594ac6cebf76bd4caf2e1b80a1ba8`，候选产品冻结于 `72a1d4009716da73a07fd9f764e8e431c83e8f66`。仅新增人物排序专页及四处条件指针；首页和原正文、质量保障叶不删改。冻结指纹见 `harness_writer_receipts.json`。旧广义开场原型及旧 medium 结果保留，不与本次 max 对照混算。

按LF文本字符计，首页仍7516；references从44页/83803字符增至45页/84623字符（+820），其中新页432字符。canonical为5文件、17行新增。这个维护成本如实记录，不以未缩短否决新增功能。

两条精确 Flash 通道各自同题配对，8 对、16 次真实写稿；独立 A2 Max 对预登记的4对逐对匿名冷审，另4对由根任务按原题核对。max 是客户端配置证据，原生 init 不证明上游实际执行档位。两个已结束的通知可用性 probe 不计入本功能样本；按用户后续要求不继续单独验证模型。

## 冷审误判与门槛校准

原始冷审 JSON 不改写，以下是根任务对其具体判断的裁决，不以多数票代替核对原题。

- P01 将上级泛称先于兄弟单位泛称判为“偏离材料顺序”：原题材料是登记名单，并未确认该顺序为礼宾次序；项目规则允许依据明确的上级/同级关系排序。这不是双方共有缺陷。正常讲话标题也不是原题禁止的附加内容；“各位”替代“其他”在本句中不单独构成硬事实错误。保留其“候选具体人物前置更符合约定”的结论。
- P02 正确区分“尊敬的”有无只是起草风格；基线没有逐字复述“不安排新的整改流程”，但未新增流程，不因此扣硬分。正向差异是人物排序，不是必须重述禁止项。
- P03 的“受邀主宾”或“本中心”未逐字保留，以及两个人物在一句中依次介绍，不自动成为事实/交付错误。候选仍落实确认的主宾优先和已给身份，介绍与发言顺序均正确。口头衔接较简可以保留为风格偏好，不升级成排序硬回退。原始冷审为 tie。
- P04 为 tie，确认双方核心材料与责任顺序保持，同时指出双方无据扩写。其将这些问题概括为“轻度扩写”不能豁免素材边界，尤其基线把“本周先梳理”强化为“本周内完成”。15%可由9/60直接计算，不是外部新事实。原题未逐字要求只输出正文，因此过程说明是项目交付质量问题，不能冒充原题禁止项；也不能把全文已交付等同于事实质量全部通过。
- unknown_rank 的“下面我先说自己带来的这一份”中，“一份”也可作指示当前对象的量词，不能只凭该词判定增造样本总数。基线“之后请各位介绍”同样属于正常发言衔接；原题不是逐字锁定的议程。这一对不凭机械关键词触发补测或改规则。

## 长讲话既有问题的单独记账

R10两稿都在正文前解释读页、选路，基线还带较长修改说明和正文后取舍表；这不符合项目直接交付写稿的目标，不能因排序正确而掩盖。基线保留/新增了“本周内完成”、反馈时讲清调整时间与依据、未经审定不作为答复依据等额外要求；候选“几种说法混着用”“就是9次往返”和部分后续检查表达也超出所给素材，不能将旧稿中的无据说法自动升级为事实。

候选本题未读取人物排序新页，原“同志们”保留。两个独立生成稿存在不同残留，单次采样不足以确定每个措辞差异的因果；也不能只因未读新页，就断言入口指针对生成绝无影响。结合共享缺陷、未触发新页、局部编辑精确控制和两组目标题同向改善，判断本原子时不把这类既有缺陷机械记为候选独有回退。本轮不顺手扩大修复长讲话事实边界，未声称所有写作质量已全面提升。

## 功能准入结论

4个预登记冷审均完成有效JSON，精确 `alibaba-token-plan-2/qwen3.8-max`、客户端0.22.0、max配置，原生 `init.tools=[]` 且实际工具调用0。匿名标签解开后，2次偏好候选，2次tie。冷审只评稿件，不判实现因果或合并；另外4题根任务核对不能包装成独立冷审。

证据支持新增这一窄范围功能：两条Flash上的目标题出现同向排序收益，其余已测边界保持；未发现可归因于新增规则的实质独有退化。这里的“不劣于当前main”是本批受控对照的准入判断，不是统计意义上证明普遍非劣，也不声称旧有长讲话问题已经修好。没有出现需要消融确认的新规则硬负点，不追加抽样到通过。
