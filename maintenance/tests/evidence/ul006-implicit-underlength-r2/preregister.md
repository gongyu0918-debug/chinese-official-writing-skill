## 固定对象

- 产品候选：`389b43f48341a25b35f4df45c71efd4f19c1acc1`。
- 宿主：Codex CLI `0.144.6`，从候选组装并注册到逐调用隔离 `CODEX_HOME` 的 `under_length` companion。
- 写稿模型：`cases.json` 登记的五条低成本 provider，均为 `max`。先跑 `alibaba2` 的三道目标题和一道旁路控制；只有真实生命周期可运行后才扩其余 provider。
- 不控制桌面 GUI，不读取或改写用户 Codex 主配置，不安装到用户插件目录，不联网检索。

## 目标原子

无显式字数下限时，不设统一100字门槛。只有当前 Skill 已实际读取、事实材料可可靠分离、D0 接近材料换词或换序转写，并且命中已由真实写稿验证的情况说明、办理通知或阶段性事故通报时，才启动一次同稿修订。

修订允许由同一主体、对象、范围和状态直接支持的一层常识关系，包括原因、目的、即时作用、合理归纳、条件结论或低强度预期；不得因这些关系没有逐字出现在材料里就判失败。硬失败限于新增具体数字、用途、程序、责任、期限、承诺、新事件、既成成效，或升级未决状态。

## 真实题与控制

- `U1`：事实较多且状态未决的内部情况说明。
- `U2`：完整日期、人员状态、现场处置、道路影响和原因待查并存的阶段性事故通报；“后续情况将及时通报”属于可接受而非必写的自然收束。
- `U3`：对象、动作、期限、字段、渠道和豁免明确的办理通知。
- `C1`：同类通知明确要求正文不超过80字，必须旁路动态短稿事务。

## 判定

技术闭环要求：真实 `UserPromptSubmit`、Skill 读取后的 `PostToolUse`、`Stop` 连续发生；目标题若启动事务，终态必须为 `under_length_complete`，选择稿 hash、交付 hash 与 Codex 最终消息 hash 一致。旁路题不得启动动态事务，并记录 `explicit_upper_bound`。

质量目标不是机械超过整数。每份目标题逐字检查给定主体、数字、日期、状态和范围；合理衔接或一层推断不记外扩。候选只有在至少两家有效 provider 选择安全 D1，或某题初稿已自然充分而不需启动时，才支持产品说明；只会安全回退 D0 不算解决过短问题。失败后先定位触发、修订提示、机械反控、语义台账或宿主续写中的直接原因，做最小修改并重跑同题，不交付悬置 `HOLD`。

控制题、用户限长、压缩、精确回复、极短、只审和纯格式旁路不受动态短稿机制影响。与候选差异无关的模型文风、包装或宿主技术失败不计产品回退，但如实保留。
