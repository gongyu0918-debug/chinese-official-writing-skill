# AH-002 新闻完整日期写后恢复预登记

日期：2026-08-29。

## 问题与固定基线

固定公开基线为 `main@31dacd0805035521ad848bdc10e70c0a366d554c`，即已发布 v1.6.19 回执后的主线。此前当前产品真实稿中，Ollama Cloud 与 MiniMax CN 都曾把材料明确给出的 `2026年8月27日` 缩为 `8月27日`；在新闻叶或入口重复提示完整日期的 R1/R2 已终止。本轮不再增加新闻提示词，只验证另一机制：完整 D0 形成后，能否把材料中明确给出的完整日期精确恢复到同一日期位置，而不改动其他正文。

本轮不修改 description、新闻叶、普通 reference、Hook、adapter、镜像、包体或版本。先完成真实写稿和同稿修订；只有目标修订稳定、安全，才另行预登记最小产品实现。

## 阶段一：全新自然写稿

三题均为全新活动新闻，材料分别给出 `2026年9月2日`、`2026年9月6日`、`2026年9月9日`，同时包含人数、完成范围和未决状态。先按固定顺序运行：

1. `ollama-cloud/deepseek-v4-flash:0731`
2. `minimax-cn/MiniMax-M3`

两家均使用 Codex CLI 隔离 Skill、Hook 关闭、read-only、ephemeral、`max`，每题只运行一次。若六份技术有效稿中少于两份自然漏掉年份，则按固定顺序逐家扩到：

3. `alibaba-token-plan-2/deepseek-v4-flash-0731`
4. `alibaba-token-plan/deepseek-v4-flash-0731`
5. `opencode-go/deepseek-v4-flash`

扩样在累计找到两份可修复的自然漏年 D0 后停止；若五家十五份仍不足两份，状态为 `BASELINE_NOT_REPRODUCED`，不造人工坏稿、不实现产品。

可修复 D0 必须同时满足：技术有效；正文没有完整日期；正文只出现一次对应 `M月D日`；其他核心事实足以形成可用新闻稿。选样按题面顺序、再按上述 provider 顺序固定，最多取前三份，不按文采挑选。另取第一份完整保留日期的技术有效稿作原样控制。

## 阶段二：同稿精确修订

将阶段一冻结的每份 D0 连同原材料交给五家便宜 provider。修订请求只允许把唯一的 `M月D日` 恢复成材料中的 `YYYY年M月D日`，其余标题、正文、标点、段落和顺序逐字不变；完整日期控制稿必须逐字返回原稿。输出仍只交完整正文。

每份目标稿的机械期望值为：仅将唯一短日期替换为完整日期。空白和换行按原稿保留。以下均单独记录：

- 精确恢复：逐字等于机械期望值；
- 日期恢复但有其他变化：目标命中但不是安全局部修订；
- 未恢复、改错日期或新增日期：目标失败；
- 新增金额、人数、活动过程、责任、程序、决定、完成结果、正文外说明或 Markdown 包装：硬回退；
- 一般学习、交流、实践作用若已存在于 D0，保持原文不判失败，也不要求删除。

不把日期之外的两臂共有文采问题归因本原子。完整年份存在与否是硬锚目标，但活动新闻使用月日还是完整年月日在公开稿件中均可能成立；本轮只保护用户材料已经明确提供且要求保真的日期，不建立所有新闻必须写年份的通用体例。

## 产品启动条件

只有至少两份不同题面的自然漏年 D0 均满足：五家中至少三家可精确恢复，且原样控制至少四家逐字不变，才进入最小产品原型。原型优先使用请求中已给的完整日期与 D0 中唯一短日期做确定性 source-bound 替换；不得调用自由改写，不得把年份补到多个同月日位置，不得处理来源冲突、缺失年份或多义日期。

任何产品候选还须以同一批冻结 D0 验证：目标修复、无目标原样、哈希、异常回退和普通无 Hook 路径。真实修订不成立时，直接终止，不用增加裁判、全量测试或更多提示词掩盖。
