# v1.6.10 后状态与责任主体细分结果

## 目标

本原子只细化两类边界：公共处置进展应由材料已有责任主体承载；已形成或已收集的待处理对象，在材料同时给出责任主体和对应职责时，应写为该主体正在办理。只有一般职责或孤立的“尚无结果”时，不据此推定工作已经开始。

## 真实写稿

固定5个小样本覆盖案件新闻、会议纪要、单位总结、意见卡统计和采购请示。基线两路写稿均出现两项相同缺口：案件新闻写成无头的“案件正在侦办”；意见卡说明保留“尚无统计结果”，没有用中心的汇总职责承载当前进展。

第一轮三文件候选已把案件新闻改为警方承载，同时保留“嫌疑人尚未抓获”；会议、总结和采购稿没有新增事实、状态升级或下游程序。意见卡聚焦复测两次仍只省略结果缺失状态，没有写出进行态。规则进一步收窄为“对象已形成或收集＋责任主体＋对应职责时，应写主体正在办理，不能只省略状态”，并加入意见卡窄例后，最终真实稿为：

> 市公共文化中心已回收读者意见卡120份，意见卡由中心留存，中心正在对意见进行汇总分析。

最终稿未增加期限、统计结果、采纳状态、计划或承诺。

## 独立复核

独立 `gpt-5.6-sol` max 只读取5题、实际稿和三文件增量，结论为 `PASS`：公共处置进展已由警方承载且未决状态保留；意见卡场景只在对象、主体和职责同时成立时使用进行态；S02—S05 未见新增事实、非授权状态升级或下游程序外推。两份未通过的聚焦稿保留为规则迭代事实，不计最终通过样本。

## 边界

- “责任主体承载”不等于每句机械重复主语；近邻句能够自然继承时仍可省略。
- 只有一般职责、孤立“尚无结果”或外围事项未发生，不足以推定工作正在进行。
- 供应商未定不推导验收、付款等下游环节正在办理。
- 本原子不改 Hook，不把进行态生成责任交给删除型门禁。
