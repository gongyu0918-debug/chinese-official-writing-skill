# SKILL 与 reference 整体重写前评估（2026-09-12）

## 结论

有必要做一次架构级重写，但不宜把 50 个 reference 的现有文字一次性无差别重写后直接合入。当前主要问题是长期叠加形成的工程债：入口、workflow、总审、反 AI、校对和检查页重复承载交付边界；部分旧 playbook 混合多个文种或专项；路由条件与停止条件分散，造成少读、晚读和无关叶伴读。

推荐的范围是“全量语义重写旧路由与混合叶，保留已验证专叶的事实内容作为基线素材”。第一阶段重写 `SKILL.md`、`reference-index.md`、`genre-routing.md`、`workflow.md`、`final-review-layers.md`、`review-checklist.md`、`anti-ai-patterns.md`、`proofreading-checklist.md`、`handling-elements.md`、`argument-chains.md`、`task-route-cards.md` 及仍混合的 `genre-checklist.md`、`ai-compute-docs.md`；通知、纪要、函、讲话、研究、采购等已完成拆分的专叶先保留原语义，后续只做逐叶复核。

## 当前基线

- canonical `SKILL.md` 按 LF 计 7,516 字符；`references/` 共 50 个文件、约 84,899 字符。文件字数不是 token，也不是实际上下文成本。
- “正文外/交付边界/未决状态”等语义在多个共享页重复出现；脚本检测和可选 Hook 还各自维护一套边界。入口虽有硬约束，真实写稿仍会出现过程旁白，说明重复文字没有转化为稳定遵从。
- 当前合入的 `prose_lint` 窄修复能检测此前漏掉的“已按 Skill 读取……正文如下”等变体，但只有宿主实际调用并按高风险结果重试时，检测才会转化为交付压制。

## 历史证据对重写方式的限制

- 会议纪要、通知、采购公告和复核层拆分实验曾出现基线本来不读大页、候选读错控制叶、对象扩大、材料外安排或减载不足；这些实验均未因静态字节变短而准入。
- 反 AI 单面拆分的基线在 15 次中仅 1 次读取完整反 AI 页，说明先按表达主题切叶没有稳定路由前提。
- 过往 workflow 分块实验出现弱模型 Markdown 残留、材料外管理动作和标题问题，候选已撤回。不能把“规则更短、更像清单”直接当作注意力改善。

## 预期收益与风险

在路由真实命中、共享规则去重且专叶承接完整的前提下，常见任务有机会减少无关 reference 伴读，并降低过程说明与文种混用的注意力竞争。当前证据不足以给出可信的固定百分比；任何 20% 或 30% 的上下文、token 或旁白率改善都不能在重写前承诺。

主要风险是重写后路由少读必要叶、过早停止、旧文种质量衔接丢失，或把质量建议改成过严门禁。旁白也可能继续出现，因为它受模型、宿主和是否实际调用脚本共同影响。重写只能验证“在相同调用条件下是否减少”，不能保证零旁白。

## A/B 验收矩阵

候选与当前 `main` 使用相同用户提示、当前五条模型通道和 `max` 优先，保存实际读取轨迹、首个技术有效终稿及脚本调用回执。题包至少覆盖：稀疏通知、报告、请示、函、纪要、讲话开场、研究/可研、采购审查、算力技术需求、Word 纯文本结构、只审不改、局部改稿、长文压缩、新闻兼容场景和过程旁白控制。

逐稿分开记录：事实/数字/日期/主体/状态、文种功能、输出形态、旁白与 Markdown 包装、实际 reference 读取、脚本调用及技术失败。只有候选独有硬回退才阻断；模型措辞波动、通道延迟和两臂共有问题单独记载。路由收益必须同时满足目标叶确实被命中、无关叶减少且正文不劣。

脚本成功标准不是“模型偶尔主动调用”，而是：命中旁白变体可稳定返回高风险；调用方在高风险时重试或 Hook 进入洁净流程；正文事实、状态、顺序和用户要求格式不被删除。若只提高检测而不改变调用链，收益限于可观测性。

本文件只记录重写必要性、范围和验收边界，不修改当前 `main` 的产品路由或 reference 内容。
