# v1.6.33 正式词语语义审校验证

## 范围与结论

本次只更新 `anti-ai-patterns.md` 的“高频正式词”段。以具体语义、专业含义和必要强调判断是否保留，不因词本身或出现次数机械换词；空泛表述仍按已有事实压实。没有迁入当前 main 的其他路由、详情下放、术语页或 Hook 功能。

发布基线为 `v1.6.32`，提交 `236784efe2a7a0bf9acd3a49f1d3ad0cff1586a8`。写稿候选冻结于 `dded78a783aaac897a024ca77a331de6eefe9809`，canonical tree 为 `1331873457aa7798d2e5d92e40b5f511ff22d0c9`。冻结时版本字段仍为 1.6.32；后续版本工程与写稿输入分开记录。

当前五组对照未发现候选新增业务事实、升级未决状态、损失文种功能或缺少完整正文的硬回退，支持这个单原子进入后续发布工程。这个结论是本次范围内的工程准入判断，不是统计学非劣证明，也不表示每项文字都更好。定向审稿的过程自报和理由措辞噪声、普通说明的尾语均保留记录。

## 冻结与执行

Q1来源提交为 `b997a0ffff1f1aa3e26f5be53766e9f073efea49`，旧独立候选为 `8c44630ed5b1cfef92cbd44a8648627bffb9ce19`。逐字核对确认：v1.6.32 的整个反AI叶与旧Q1基线 `e8103f53` 相同；仅替换目标段后，整叶与旧Q1独立候选相同。字符量按LF从5409降至5340，减少69；末尾术语指针继续指向 `ai-compute-docs.md`。

旧五组max实稿可作为该叶行为证据，但旧实验的首页、索引及信息选择页与发布基线不全相同，因此本轮重新以发布基线和单原子候选的冻结输入执行原五题。任务文字、分配通道完全沿用旧 `word-guidance.json`，每题各用一个原通道，并非每题覆盖五通道。两条阿里通道属于同一Qwen模型家族。

实际执行12次，11份技术有效终稿，形成5组同effort完整对照：4组max、1组high。GLM候选max因502及`ollama-native duplicate tool result`退出失败，CLI自动重连未恢复；按预登记仅将该题两臂各补一次high。原max基线及失败轨迹全部保留，不用max/high混配，也没有按文采重抽。

调用命令：

```text
python maintenance/tests/evidence/release-v1633/run_writing.py maintenance/tests/evidence/release-v1633/cases.json
python maintenance/tests/evidence/release-v1633/collect_writing.py
```

实际解释器为本机Python 3.13。模型由已验证的本机原生CLI适配器调用；每臂独立上下文与冻结Skill目录，不启用Hook或插件。主工作树后续版本修改不进入已冻结的模型输入。

定向审稿中，同句前半已给出甲乙分工，“上述”有正常承接对象。候选提出删除重复分句本身有依据，但“自指式”理由措辞欠准确；不能把它扩解为材料没有分工依据。候选同时将其列为低风险、允许保留，没有把正常专业词或承接词当作硬错误。该局部噪声不因其余检查正确而抹掉。

GLM候选还自报“按路由读取了……未执行脚本……”，不属于用户需要的逐项意见。它是审稿输出中的过程噪声；本轮不把其包装成改善，也不把正文外审稿意见机械按正式正文清理门判定。普通说明的“特此说明”同样作为简洁度差异保留。

## 路由与减载证据

四组完整对照的两臂实际返回了修改叶全文，每臂均一次；普通说明两臂均绕过该叶。四组直接曝光足以检验本次目标段，旁路组用于观察邻近任务。

确认的静态收益只有目标叶减少69个LF字符，首页和路由不变。各次命令还包含目录枚举、重复读取和附加页，因此不能把全部输出差额称为Q1节省。空泛评价和具体闭环两题，候选全部命令输出反而更长；这与事实保持、目标叶是否读取及文字质量分开报告。

本轮没有新Hook能力，没有以并行的当前main Pro宿主检查替代此普通版本验证；没有运行全量工程或重新打包。工程代理在真实写稿结论之后接手版本、包生成及一次全量检查。
