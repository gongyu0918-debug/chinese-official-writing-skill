# 全量重写蓝图：SKILL、references 与脚本（2026-09-12）

## 目标

以当前 `main@1ce71123` 的行为规则为基线，从零重写规则组织方式，得到一份功能等价、引用更短、路由可解释、每次只加载必要资料的 Skill。重写的对象包括 `SKILL.md`、全部 `references/` 和脚本调用说明；Hook 目录冻结为基线资产，不在本轮重写。现有 Python/Node 命令代码可以复用，只有调用契约、参数说明或结果回流需要变化时才改脚本。

## 总体结构：两条轴，四层页

### 轴一：交付模式

起草、改稿、压缩、只审、格式交付是第一轴。它决定输出形态、事实选择和复核方式。

### 轴二：文种或场景

请示、报告、通知、函、纪要、讲话、方案、可研、采购、新闻等是第二轴。它决定正文功能、骨架和办理要素。

两条轴通过唯一首叶合并：一个任务先选一个主文种叶，再叠加本轮确有信号的共性能力页。脚本是终稿工具，Hook 是宿主门禁，均不承担文种选择。

### 四层页

1. **最小入口层**：`SKILL.md` 只保留触发边界、五类模式、核心事实契约、首叶选择和交付形态。
2. **路由层**：`reference-index.md`、`genre-routing.md`、轻量任务卡只负责选叶和停止，不写完整骨架。
3. **能力与文种层**：每个文种一个主叶；事实选择、办理要素、论证、结构编辑、字段编辑、压缩、称谓、格式、反旁白、校对分别由唯一共性叶承担。
4. **执行层**：`prose_lint.py`、`review_gate.py` 及现有命令保留可复用实现；脚本负责可观测检查，`prose-lint-usage.md` 和交付说明只规定何时调用、如何解释返回值。Hook 目录只读，不重写。

## 文种叶原则

已通过真实写稿且职责单一的新叶直接复用并重新接入：新闻消息、新闻评论、意见建议、投诉反映、整改方案、增项申请、制度、通知公告、部署、函、纪要、讲话、研究、采购及人物顺序。旧的混合总页只保留短分流或功能反查；如果一个叶子仍有两套以上骨架，就拆成“一个分流页 + 两个稳定主叶”，而不是继续增加交叉链接。

算力是稿件应用场景的附加规则，不是文种。主文种先按报告、方案、采购或技术材料等路线确定，再按算力信号叠加唯一的 `ai-compute-docs.md`；公共术语和示例只作可选叠加。`genre-checklist.md` 只做未覆盖法定文种的功能反查。

## 每条路由的合同

每个首叶必须写清：

- 触发信号；
- 读取的共性页；
- 不读取的相邻页；
- 输出完成条件；
- 何时升级到另一条路线。

没有停止点的“按需读取”不算路由完成。共享页不能反向要求加载总索引，避免引用环。

## 脚本与 Hook 边界

脚本实现按功能复用：语言、格式、结构和交付模式检查仍由现有命令承担。重写只改变入口页何时调用以及如何把风险结果送回交付链；不把脚本返回码改成文种硬门，也不让脚本自动改写正文。Hook 配置、宿主适配、停止门和能力运行时均冻结，作为独立回归对象。

## 验收顺序

1. 规则映射：旧 `SKILL.md` 与 50 个 reference 的每条可执行语义都有新归属或明确保留。
2. 静态工程门：链接可达、无引用环、镜像同步、脚本语法、Hook 零差异。
3. 同题真实 A/B：当前 main 与候选使用同一提示、同一五条便宜通道，记录实际读取集合和停止点。
4. 组合测试：先测单叶，再测文种叶与共性页组合，再测跨文种和 Hook/脚本调用；模型措辞波动和两臂共有问题单独记账。
5. 只有候选独有事实、状态、文种、格式或必要内容硬回退阻断合并；静态字符减少本身不构成收益。
