## 组合真实写稿补测

沿用交接的五条便宜通道，优先max。以已保留场景路由ead为对照、914为候选，按交汇风险分配13个任务，每任务一条通道两臂，不伪称完整文种×五通道矩阵：

- MiniMax M3：新闻改稿、采购申请、材料单一编者按。
- Alibaba Qwen通道1：新闻评论、培训讲解稿。
- Alibaba Qwen通道2：合作建议、既有系统增项。
- DeepSeek V4 Flash：整改方案、普通函重组、含“整改”的普通进展报告。
- GLM 5.3 Flash：投诉正文、可研点名只审、投诉点名只审。

两条Alibaba仍属一个模型家族。主对照27次调用形成26份final，其中投诉候选max因网关502及重复tool result无final，预定high回退成功，故12组同强度、1组混合强度；混合组只支持功能观察，不支持max因果比较。原receipt的technical_error为null不能掩盖trace中的真实技术失败。

主代理逐对读稿并核对实际工具返回。五类场景均能进入场景页及对应专页；新闻改稿、评论、投诉命中所需语言/论证/anti-ai/校对衔接；编者按由公式用语轻叶覆盖，没有被迫加载新闻长流程；普通报告虽含“整改”仍走报告卡；函重组和采购申请由索引找到相应叶；增项及可研点名只审保持首页直达；投诉只审完成状态纠错而未改全文或添投诉请求。

## 负点与归因，不用全绿遮盖错误

| 观察 | 裁决 |
| --- | --- |
| 合作建议候选初稿增加“承担日常填报/平台承接日常填报”，且未明确保留技术方案、负责人、时间均未决定 | 属真实的现状扩大和状态遗漏；不能解释成正常合作口吻。对同一模型/max、冻结产品及提示字节，两臂各复跑一次，发送前校验原prompt SHA-256。候选复跑未再扩大日常承载，且明确三项未定；基线两次也保留该状态。初次失败保留，结果不稳定复现，不认定为已确认组合回归。静态子代理独立核对四稿，主代理复核。 |
| 新闻评论两臂都有把清单结构、办理环节或可能不便说得过实的表述 | 记录共有的推断强度风险；没有迁移或新增相关正文规则，不将单次差异直接归因于索引。 |
| 采购申请两臂均写现有打印机“一台”，原任务只明确拟购一台 | 共有的数量补足问题，仍是真实风险，不因双方都有就称稿件完全合格；不是候选独有回归。 |
| 讲解稿把示例展示时点具体化；编者按有泛化的自称/适用语句 | 区分原材料支持的讲解功能、自然收束与新增安排；保留表达及顺序具体化疑点，不用字面长度或固定短语机械判质量退化。 |
| 执行旁白、新闻正文代码围栏、部分审稿过严 | 属交付或审稿质量问题，保留记录；正常审稿意见、用户允许的一般纠正措施、合作意愿及一般风险分析不按新增事实一律扣分。没有趁机修正文规则。 |

合作建议复跑是2次额外真实调用，不替换初稿、不择优计分。一次复跑支持采样波动解释，但不能估计失误率，也不能证明上下文长度对概率完全无影响。本轮没有确认候选独有且稳定复现的事实/状态退化，关键结构与质量衔接缺口均有当前组合证据。结合前轮已收束的原子对照及覆盖缺口，继续整批加测的边际价值不足以构成合并前必要条件。

## 合并判定的边界

准入目标是结构减负保真：入口与专页可达、材料事实及未决状态没有已确认的候选独有回归、旧质量增强保留、兼容包与测试适配完毕。不是以软规则保证每次输出无旁白或无推断失误，也不是顺手修复所有既有审稿问题。

本组合达到上述本地main合并标准。剩余的是已识别的模型波动与共有质量风险，以及OpenClaw通用校验器的平台schema差异；这些没有被冒充修复。公开main与本地main的分歧、版本发布、跨平台发布及安装同步不在本次执行范围。合并后才应按仓库既有授权流程另行处理对应本机同步，当前main未变，不提前操作安装。

原始调用、冻结输入、失败和复跑都按 `maintenance/tests/evidence/skill-lightening-merge-check/archive.json` 索引归档并校验。复核时按案例读取final和trace片段，无需整批加载。当前结论是“可合并、尚未合并”。
