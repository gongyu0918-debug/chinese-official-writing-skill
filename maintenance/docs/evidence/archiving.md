# 证据分层与按需提取

日常维护先读当前需求、预注册和结果摘要。只有定位失败、复核分歧或复放具体测试时，才取对应原始材料；归档不改变原有通过、失败、HOLD 或未验证结论。

- 热区：必要测试用例、当前测试直接依赖的原稿或 harness、预注册、结果与发布摘要。保留在原路径，避免改变测试含义。
- 冷区：逐轮原稿、完整盲包、回执、运行流水、候选快照和历史运行脚本。文件元数据在 `archive-index.jsonl`，包含原路径、大小、SHA-256、Git blob 和来源提交；由工具查询，不整篇加载索引。
- 临时区：新的运行配置、临时宿主、重复清单、盲包及生成安装包放 `output/`，不提交；待形成必要结论后再归档。新回归用例放测试 fixture 区，不用流水代替测试代码。

查找路径，不读取原稿：

```powershell
py maintenance/tools/evidence_archive.py find "stream.jsonl" --limit 3
```

提取查询得到的一个完整原路径：

```powershell
py maintenance/tools/evidence_archive.py extract <original-path>
```

默认只写入忽略目录 `output/evidence-extracted/`，校验大小和 SHA-256，并拒绝覆盖已有文件。不会联网、运行历史脚本或加载其他稿件。浅克隆缺少历史对象时，可使用完整 Git 克隆，或增加 `--archive <evidence.zip>` 从已保存的归档提取。

来源为提交 `0721297298b72be7a37b93c6598172791b58e421`；[归档摘要](archive.json)记录 ZIP 校验值。现有结果页指向冷文件的链接改为该提交的 GitHub 永久链接。当前文件树移除冷文件，Git 历史及独立 ZIP 均保留原始字节。旧脚本如依赖外部 runtime 或多个输入，应按其说明逐项恢复后再复放，不能把“可提取”称为“已重新执行”。

新增归档沿用这些原则，不要求每次生成一套重复总清单。完整证据只保留一个原始副本集合；结果、模型、强度、来源指纹、失败与回退状态由简短元数据关联。
