# 办理要素

起草前和复核时，根据当前主文种或用户模板抽取实际需要的办理要素。

## 核对项目

| 项目 | 核对内容 |
| --- | --- |
| 主体与对象 | 谁提出、报告、执行或接收，称谓与材料是否一致 |
| 事项与依据 | 要处理什么，材料给出了哪些事实、政策、会议或工作依据 |
| 动作与状态 | 请求、要求、答复或协调的内容，进行中、拟议、待核与已定状态 |
| 条件与期限 | 适用范围、资源金额、责任配合、时间节点及其确定程度 |
| 支撑与反馈 | 附件、数据来源、联系人和反馈渠道，实测、测算与估算性质 |
| 文内字段 | 标题、主送、落款和日期等已给字段及其位置 |

按当前主文种判断哪些要素为必要项。正文、表格和附件中同一要素的名称、数值、顺序和状态保持一致。

## 处理缺项

从用户材料和最新版底稿查找缺项，区分未提供、尚未确定和存在矛盾。涉及专门业务字段时按已选场景参考核对。尚不熟悉通用写法或必备要素时读取 `external-research.md`；检索所得通用规则用于核对，具体业务信息仍取自材料。

按 `writing-rules.md` 判断缺项是否影响文种成立或办理。已给要素照实使用，未定要素保持原状态；正式稿清理无用途的占位，模板稿或用户指定空字段按原要求保留。
