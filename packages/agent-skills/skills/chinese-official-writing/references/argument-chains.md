# 论证链

本页用于组织段落和小节。链条是内部写作方法，不把“事实→判断→行动”等标签写入最终正文；只使用材料已有依据，不以补全链条为由创造事实、责任、期限或成效。

## 基本链条

多数正式材料可按“主要事项或核心判断 → 事实、数据、政策依据或现实条件 → 问题、必要性、可行性或风险 → 安排、请求、责任、时限、验收或后续管理”组织。复杂任务可进一步使用：事实/需求 → 判断或问题 → 目标 → 方案/措施 → 资源与条件 → 风险与控制 → 结论或请求。

一个段落服务一个判断。同一事项再次出现时只保留新增数据、理由、决定、责任、风险、期限或验收要求；需求、成本、安全、进度混在一段且各自承担判断时拆开。

## 按主文种取用

### 请示、申请和请批附件

请批事项先明确拟请审定或批准什么，再写依据和背景、必要性和紧迫性、方案/预算/资源/实施安排、风险控制和责任，最后使用符合任务的请批语。不要把成绩铺陈放在请批事项前，也不要在一文中合并多个无关请求；材料没有批准事实时保持拟请、建议或待审状态。

### 报告、总结和情况汇报

先交代报告事项、时间范围和总体判断，再写已完成工作或已发现情况、数据事实和典型做法、问题原因或风险、下一步安排/建议/整改。报告用于汇报，不把建议改成审批请求；需要决策时按材料写“拟按程序另行报批”等状态，不虚构已报批结果。

### 通知、函、复函和协调材料

通知重执行，函重协商，复函重回应来文。顺序通常是要办理或协调的事项 → 对象责任或配合范围 → 材料、动作或反馈 → 截止时间、渠道和联系人 → 后续处理、监督或结果运用。办理要求早于一般背景；材料未给责任人、期限或渠道时保留缺项。

### 方案、实施方案和建设材料

需求来源和目标 → 现有基础、差距或问题 → 建设内容、实施路径或任务分工 → 资源、经费、责任和协同机制 → 进度、运维、保障和风险 → 验收、成效和持续优化。必要性回答“为什么做”，建设内容回答“做什么”，两者不要重复同一套话。

### 可研、调研、研究和审查材料

先定研究/审查对象，再写事实、数据、样本或材料来源、主要发现或判断、方案比较/风险分析/合规审查、建议或可行性结论、已给条件/整改/补充材料/后续程序。实际数据、测算数据、估算数据和假设条件分开；审查材料列依据、条件和补充事项，不只写“基本可行”。条件性建议与事实状态分开，不写成已经启动或已经确定的程序。

### 讲话、致辞和述职

先确定场合、身份和听众，开头进入主题或态度，主体按事实基础、成绩/问题、任务/要求或体会展开，结尾回到责任、目标或共同事项。讲话可以有感染力，但不用空泛排比、概念堆叠或材料没有支撑的评价；具体人物开场顺序另读 `speech-person-order.md`。

## 约束与回收

材料只支持问题陈述时，停在问题和待核事项；建议、预测、假设、拟议与已完成结果分开。技术或算力稿件的指标、成本、服务和验收链条转读对应场景附加页；本页只负责已有依据的段落关系。链条完成后回到主文种叶和终稿复核，不在本页启动总审、格式或脚本路由。
