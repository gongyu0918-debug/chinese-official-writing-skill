# GB/T 9704-2012 常用格式参考

本文件只提供公开国标样式中常见的版式核对点，不等同于完整红头文件制作规范。正式发文、套红、编号、印章、签发和归档应以用户单位模板、办公室要求和人工复核为准；企业材料、项目材料和内部工作材料优先保留用户模板，不强行套用党政机关公文格式。

## 使用边界

- 用户要求“符合国标”“红头文件”“正式发文格式”时，先询问或沿用用户模板。
- 用户只要求起草正文、方案、说明、可研、审查材料时，采用相应稿件的正文格式；版头、发文字号、签发人、印章和正式签发信息按用户要求及已有材料处理。
- 正式发文需要使用的编号、密级、紧急程度、签发人、印章等缺少依据时，提示缺口，不能编造真实信息；最终正文不要残留 `〔签发日期〕`、`〔会议时间〕` 等未完成占位。
- DOCX 排版修改应另存新版本，保留原样式、批注、页眉页脚和修订痕迹。

## Word/排版交付衔接

用户明确要求 Word、docx、GB/T 9704、红头、发文字号、版记或“排成正式文件”时，先核对内容和办理要素，再交给 DOCX/document 技能或现有文档工具处理。本轮允许修改内容时修正已确认问题；只处理格式时保留原文，将影响使用的内容问题和格式缺项列在正文外。

Word/docx 交付按本轮任务确定正文修改范围。用户只要求排版时，保留原文的用词、数字、标点和字符；允许同步改稿时，先在授权范围内修正内容。正文定稿状态按用户信息表述。排版步骤处理版式、样式和已明确要素；影响本次使用的缺项按 `writing-rules.md` 的交付规则处理。没有明确覆盖指令时默认另存新版本。

### 按交付用途核对要素

普通 Word/docx 稿按当前文种、用户模板和实际使用的字段核对内容与版式。用户要求正式发文、红头、签发或相应正式要素时，再按适用要求核对发文要素；影响本次交付的缺项按 `writing-rules.md` 列在正文外。只起草正文时，先完成所需正文。

正式发文按适用要求核对标题、文种、发文机关、主送或受文对象、发文字号、签发人、密级或紧急程度、附件、落款、成文日期、版记、印章或签署信息。正式签发所需且尚未确定的事实要素列为“待确认”，不得用 `[依据/背景]`、`〔年份〕X号`、`XXX单位` 等模板占位替代真实信息。用户已点名缺少文号、签发人、版记等具体要素，且要求简短核对时，优先只列用户点名缺项；其他正式要素用一句“其他正式要素按单位模板另行核对”概括，不展开成长清单。内部模板、企业模板或用户指定格式与严格国标不一致时，先保留用户模板，再把实际涉及的正式发文风险放在正文外提示。

交付 Word 前检查以下事项：

- 不得编造文号、密级、紧急程度、签发人、印章、正式签发日期和版记信息。
- 不得把 Markdown `**加粗**`、代码块或 `###` 标题标记原样带入正式 Word。
- 避免把缺项改写成正文泛占位，如 `指定渠道`、`截止时间前`、`联系人沟通`；缺项仍列在正文外。
- 用户提供单位模板、企业模板或内部审批样式时，优先保留来源模板，不强制套用严格 GB/T 9704。
- 红头、发文字号、版记、签发人、份号、密级等要素只有用户提供或明确要求时处理；无法确认时列入文后提示。

## 页面和基础版式

- 纸张：A4。
- 页边距常见参考：上 37 mm、下 35 mm、左 28 mm、右 26 mm。
- 版心：需要网格控制时，可参考每面 22 行、每行约 28 个汉字。
- 页码：有用户模板时按模板；无模板且用户要求 GB/T 9704 时，一般用 4 号半角宋体阿拉伯数字，数字左右各放一条一字线，一字线上距版心下边缘 7 mm，单页码居右空一字、双页码居左空一字。
- 正文段落：一般两端对齐、首行缩进 2 个汉字，行距、段前段后以模板为准。
- DOCX 主标题段落：居中排布，显式取消首行、左侧和右侧缩进，不继承正文的首行缩进；多行标题回行保持词意完整和排列均衡。

## 字体和层级

- 标题：常见为 2 号小标宋体或用户模板标题样式；多行标题居中排布，回行保持词意完整、长短适宜，通常排成梯形或菱形。
- 正文：常见为 3 号仿宋体。
- 一级标题：常见为 3 号黑体。
- 二级标题：常见为 3 号楷体。
- 三级标题：常见为 3 号仿宋体加粗。
- 一级、二级文字确实承担层级标题功能、统领后续一段或数段时，一般独占一行，末尾不加句号，正文另起。整理正式 Word 稿时，应把`（一）小标题。正文……`改为`（一）小标题\n正文……`；段首题、编号正文句或用户模板明确接排时仍按正文标点处理，不因出现 `（一）` 就机械拆段。
- 附件、版记、页码等细节按用户模板或正式排版要求处理。

## 标题和主送

- 标题通常体现“发文机关 + 事由 + 文种”，但内部材料、方案、报告附件可按用户模板简化。
- 标题不得夸大文种功能，如报告标题不能承载请批事项。
- 主送机关应与行文关系一致：上行文送上级机关，下行文送下级或有关单位，平行文送不相隶属单位。
- 多个主送机关的排序、简称和标点按用户模板或单位规范执行。
- 起草正文或改稿时，通常保持“标题 -> 主送机关或接收对象 -> 正文”的顺序，但最终以用户模板和材料属性为准。申请、信件式上报材料、内部采购申请、致辞、讲话稿等可能使用单位名称与标题分行、`尊敬的领导：` 等称呼或字段式费用明细，只有文种或用户要求明确时才做硬性位置判断。

## 版头和发文字号

正式公文可能涉及以下要素，材料不足时不要自行编造：

- 份号、密级和保密期限、紧急程度。
- 发文机关标志。
- 发文字号，常见形态如 `XX发〔2026〕X号`，年份使用六角括号 `〔〕`，不要用方括号 `[]` 或圆括号 `()` 替代。
- 签发人，上行文按单位要求列示。
- 红色分隔线、版头位置和字号按模板处理。

## 正文、附件和落款

- 在本轮授权范围内核对正文的文种功能，再处理排版。
- 请示、申请、报告、函等文种结尾语属于正文内容，应放在正文末段、落款和成文日期之前；不要在发文机关署名或日期后再补正文结尾。
- 附件说明一般在正文之后、落款之前列明，如 `附件：1.……`；附件名称和正文引用应一致。
- 落款单位、联系人和联系电话采用已有信息；日期按本次稿件用途填写，正式签发日期以用户或材料确认的信息为准。
- 印章和签署位置属于正式签发要素；没有模板和授权时，不生成可冒充真实签发的印章、编号、日期或签署信息。

## 版记和抄送

正式公文可能包含抄送机关、印发机关、印发日期等版记要素：

- 抄送对象应与办理需要相关，不随意扩大范围。
- 印发机关和印发日期按正式模板和用户单位要求填写。
- 公开发布、内部流转、会议材料和附件材料的版记要求不同，不要混用。

## 编号层级

常见中文层级为：

- `一、`
- `（一）`
- `1.`
- `（1）`

保留用户来源文件中的编号层级和样式。不要为了“更正式”把短文强行拆成多层编号。

## 上行文、下行文和平行文差异

- 上行文：重点核对发文字号、签发人、主送机关、请批事项、附件和联系人等。
- 下行文：重点核对发布对象、执行要求、时限、责任、反馈渠道和版记。
- 平行文：重点核对函件标题、主送单位、商请事项、回复期限、联系人和附件。

## DOCX 操作

- 保留样式、节、页眉页脚、页码、批注、修订、脚注和高亮，除非用户明确要求修改。
- 新生成版本默认不覆盖源文件。
- 版式、标题层级、页码、附件位置或关键数字高亮重要时，应渲染检查。
- 企业材料、项目材料和内部评审材料应优先保留企业模板，不强制套用严格 GB/T 版式。
