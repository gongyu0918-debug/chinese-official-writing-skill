# AI 算力场景附加规则

本页是场景附加页，不是文种页。先按报告、可研、方案、采购、申请或技术材料等主交付对象完成文种路由，只有材料明确涉及 AI 算力、GPU/服务器、模型服务、智算中心、云端/本地部署、Token、并发、SLA、安全或验收时才叠加本页。普通采购、费用申请、办公设备申请、普通方案或一般报告不因出现“AI”“安全”或“验收”单词自动加载。

本页的结构、指标和验收项目是起草或改写时的按需选项；只审既有摘要时，只有用户点名完整性核对才按 `genre-checklist-feasibility-review.md` 指出缺项，不把本页扩成新的审查范围。普通稿不读本页，算力稿也不因本页而替换主文种或并列展开三套骨架。

## 叠加定位

算力材料通常服务决策、采购、租赁、建设或审查，重点是把业务需求、资源需求、费用边界和运行风险说清楚，而不是解释 AI 概念、宣传产品或堆叠参数。按主交付对象取用以下内容：

| 主交付对象 | 重点补充 | 可保留的功能顺序 |
| --- | --- | --- |
| 可研/研究 | 需求来源、现状限制、路线比较、费用边界、条件和风险 | 背景与结论 → 业务需求 → 现状与增长 → 技术路线/建设或租赁模式 → 费用与比较 → 服务能力、SLA、并发和运维 → 安全、实施和验收 |
| 方案/建设方案 | 目标、服务范围、资源规模、部署方式、运维和保障 | 目的 → 服务范围 → 资源与部署 → 调度、监控、升级 → 安全、SLA、验收和风险 |
| 采购/租赁 | 采购目的、服务范围、规格、期限、交付、价格、合同和验收 | 采购目的 → 服务范围与资源 → 服务期和交付 → 运维、升级和故障响应 → 价格口径 → 验收、SLA、安全、数据权属和审计 |
| 技术需求 | 可检查的资源、接口、环境、运维和验收条款 | 数量/服务期/资源类型 → GPU 或等效性能 → CPU、内存、磁盘、网络、存储、带宽 → 训练/推理/微调/多租户 → 调度、配额、监控、日志、计费、告警 → 部署、驱动和依赖 → 运维、SLA、验收材料 |

同一稿件同时出现可研、采购和技术需求时，以用户指定的主交付对象组织，其余作为对应章节或附件。缺少主对象时回到 `genre-routing.md` 判定，不由本页自行决定文种。

## 需求与数据口径

- 先从业务场景写需求，再落到 Token、调用次数、用户数、峰值并发、存储、带宽、模型能力或 GPU/服务器资源。
- 有数据时区分当前实际用量、受限使用及原因、未来使用范围和增长假设；年度需求按已测数据与假设分开。
- 单位保持一致。以 Token 为主线时承接费用测算；TOPS/TFLOPS 说明服务器承载能力，不与 Token 单价混作同一成本口径。
- 实际数据、估算数据、建议值和待核字段分开；缺少厂商、金额、规模、阈值、期限、区域或服务对象时保留缺项。
- 不把普通采购、费用申请或办公设备申请写成算力论证；“先进算力”“强大平台”“领先能力”等评价必须紧跟可核验指标，否则删除或改为材料已有的具体能力。

## 成本与路径比较

按任务需要比较模型/API Token、云服务器、数据库、存储、带宽、防火墙、网关、负载均衡、日志、缓存、函数计算、GPU/服务器租赁、机房、电力、网络、维护、运维、安全、监控、支持、SLA、并发保障、业务连续性、本地化和统一调度价值。

云端、购置自建、GPU/服务器租赁和本地化服务各有适用前提：云端可能现金支出较轻但受增长、并发和数据控制影响；购置自建一次性投入和建设维护压力较大；租赁资源到位较快、合同可管理但受价格和服务条款约束；本地化更利于数据控制、审计、连续性和统一调度。结论必须写明需求规模、服务期限、成本口径和风险假设，不写成任何路径必然更便宜或必然可行。

成本章节重点写需求来源、服务期限、资源覆盖、风险控制和费用边界；除非用户要求测算表，不把正文写成“测算公式”“单价×数量”“计算如下”的计算草稿。

## 技术、SLA、安全与验收

技术条款使用可度量、可检查的“应支持/应提供”表达，按材料需要覆盖：资源规格或等效性能；模型推理、微调训练、批量任务和多用户并发；统一调度、配额、监控、日志审计、计费和告警；可用存储和网络带宽；系统安装、驱动适配、环境部署、版本升级和故障处置；7×24 运维响应、故障替换、维护窗口和恢复或替代资源；性能、可用性、并发、安全配置和运维文档验收。

SLA 不是孤立附件，可按任务写明可用性、故障响应和恢复时间、峰值并发和排队控制、资源隔离和优先级、监控日志和利用率分析、升级迁移和模型版本切换。没有阈值、时限或责任依据时保留待定状态，不代拟合同条款。

安全内容围绕材料给出的数据类型、权限、密钥、日志、访问范围、审计位置和受控环境展开，可涉及稿件、版权材料、审核记录、内部知识库、用户反馈、业务规则、训练/评测数据、日志和提示词。没有明确区域、等级、保密范围或服务商时不外推合规结论。

验收项目与需求逐项对应，可核对资源规格、性能或并发测试、模型服务可用性、日志审计、安全配置、部署材料和运维文档；拟议的核对安排仍写成拟议，不写成已经完成。
