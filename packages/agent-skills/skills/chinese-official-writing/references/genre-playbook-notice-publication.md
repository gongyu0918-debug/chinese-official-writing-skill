# 通知/通告/公告/公示/通报

## 共同骨架

- 适用：布置办理、公开周知、公示名单或事项、通报已知情况和明确要求。
- 骨架：事项 -> 对象范围或已知事实 -> 已给问题或要求 -> 已给时限/渠道/联系人；材料未给执行要求、整改要求和后续处理时，不为了像通报而补写。
- 风险：通知重执行，公告/通告重公开范围，公示重异议渠道，通报重事实和已给要求；不要互相套用。
- 补充读取：`genre-routing.md` 和 `handling-elements.md` 的对应行。

## 稀疏材料通报

- 通报只给“已完成梳理、发现问题、组织协调会”等事实时，可用短骨架“已完成事项 -> 发现问题 -> 已组织协调（只陈述次数或事实）”；协调会只写“已组织2次协调会”，不展开会议内容、处理边界、问题清单、对接要求、闭环机制或督办安排，也不写“对关键问题讨论、沟通、归集、说明、形成意见”；材料未给整改、处置、下一步安排时，不新增“已开展处置”“下一步安排”“整改方向”“治理闭环”“督导流程”等章节或小标题。用户第二轮指出补造事实或要求删未给内容时，按 `workflow.md` 的事实映射式二次修改删掉未支持推断。
