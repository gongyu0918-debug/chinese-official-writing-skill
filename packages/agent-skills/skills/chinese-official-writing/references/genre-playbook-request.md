# 请示/申请 Playbook

本文件用于请示、申请命中常规或完整骨架时直接进入对应文种规则。

## 使用方式

- 路由已确定为请示或申请后进入本文件；工作流、事实选择和文种冲突按已命中的共性页处理。
- 用户已有模板、称呼、字段顺序和落款方式优先；本文件只确定文种骨架和风险点。
- 事实、状态和缺项统一按 `writing-rules.md` 处理。

## 请示/申请

请示用于请求上级指示或批准，一文一事并落到请批事项；申请保留原因、依据与申请事项。主送采用用户给出的接收对象，机关名、部门名或职务称谓均按材料使用；落款采用已给的发文或申请主体，具体位置服从用户模板。

- 适用：向上级、领导班子或审批方请求批准经费、事项、资源、立项、采购方式。
- 骨架：请示通常按请示缘由、请示事项、请示要求组织。申请写清原因、依据或必要性，让读者理解因何产生本次需求，再承接具体申请事项、方案或金额、当前状态和请批语。短稿可合并句段，缘由到请求的关系仍要完整。
- 风险：请示一文一事；申请保留用户模板和称呼，文种根据用途判断。“妥否，请批示”可用于相应的申请。未给的主送和申请单位按 `writing-rules.md` 核对缺项，正式成稿清理无用途的占位。
- 形成理由：材料中的现状、用途、使用需要或制度依据能说明本次需求时，组织成自然的原因句，与申请事项连贯表达；常识支持的一般必要性也可写入。原因完全无法推知时，正文保留已知事项和请求，文后提示询问具体缘由。空白横线和“事由待补”等占位只用于用户要求的模板。
- 单项采购请示或申请可用一至两个自然段，段内写清缘由与使用需要、拟购品名规格和数量金额、请批事项。现有资源数量、使用负荷、排队共用、已确认损坏等事实可支持对应的使用需求；具体故障、损失、政策条款、采购程序或审批结论仍以材料为准。多品类、分项核算、比价验收、技术附件或明确长篇任务仍以本页为主文种；需要核对主体、金额、期限、附件或反馈时加读 `handling-elements.md`，需要解释必要性或比较方案时加读 `argument-chains.md`；字段表格保持原结构。
- 请假申请一般写明假别、事由或制度依据、起止时间和已给交接安排。年休假、婚假、产假等依规申请的假别，可在申请事项前使用“根据有关休假规定”等不特指条款的一般依据，不强行编造个人私事原因；事假、病假等完全未给具体事由时，不用“因个人事务”“因身体原因”等泛称代填。材料只给工作交接时，不据此补“工作不受影响”、通讯承诺或代办责任。
- 结合设备老旧、拟予更新等材料，可对日常使用需要作一般判断。通常用“为满足日常办公需要，现申请……”承接缘由和事项；“现有设备已不能满足日常办公需要”也可结合具体语境使用。
- 采购进展和后续安排沿用材料状态。材料只写供应商或采购日期尚未确定时，正文停在该状态；“批准后另行确定”“按规定办理”也属于后续安排，材料未给时不补入。篇幅调整保留完整理由、申请事项和请批动作。
- 需要论证或称谓复核时，结合 `argument-chains.md` 核对依据与请求之间的关系和 `formal-addressing.md`。
